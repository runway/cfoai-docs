Use a Trigger when you want Ari to do a job without being asked, on a schedule or once at a set time. For example, Ari can write a cash summary every Monday, check last month's spending after each close, or remind you tomorrow morning to revisit a reconciliation. A Trigger is a saved instruction with a schedule, or with one date and time. Each time it runs, Ari works through it in a new chat of its own, and you read the result when it suits you. For how unattended runs work, see [Skills, Triggers, and Guides](/concepts/automation).

<Tabs>
  <Tab title="Ask Ari">
    Tell Ari what to do, when, and where to send the result:

    > Every Monday at 8am Pacific, summarize the prior week's cash activity and flag expenses that differ from our recent pattern. Email me the summary.

    For a job that runs once, name the date and time:

    > Remind me tomorrow at 9am to revisit the bank reconciliation.

    Ari asks about anything it is missing, saves the Trigger with the time zone you named (or yours when Ari knows it, and otherwise UTC), and tells you its name and schedule. A new Trigger is on, and it first runs at the next scheduled time. A one-time Trigger turns itself off once its run is queued; see [Change, pause, or delete a Trigger](#change-pause-or-delete-a-trigger). You can also set one up by messaging Ari in Slack; see [Talk to Ari from Slack](/guides/use-ari-in-slack).
  </Tab>
  <Tab title="By hand">
    <Steps>
      <Step title="Open the Triggers page">
        Open the account menu, your name or picture at the bottom of the sidebar, and choose **Manage triggers**.
      </Step>
      <Step title="Start a new Trigger">
        Select **Write manually**. To work it out with Ari in a chat instead, select **Build with Ari**.
      </Step>
      <Step title="Name it and write the instructions">
        Enter a **Name**, such as Weekday cash brief. In **Instructions**, describe what Ari should check, update, or prepare each time. See [Write instructions that work unattended](#write-instructions-that-work-unattended).
      </Step>
      <Step title="Set the schedule">
        Under **Schedule**, choose how often it runs in **Repeat**, such as **Weekly**, then the days and the time. For a job that runs once, choose **Once**, then set **On date** and **At time**; the line under the schedule reads **Once on [date and time]**, and the date and time must be in the future. The note **Times in [time zone].** names the clock the times are read on: your browser's time zone for a new Trigger. cfo.ai saves the schedule with that time zone, so it keeps the same local time through daylight saving changes.
      </Step>
      <Step title="Save">
        Select **Create trigger**. The Trigger appears in the list, and its details show when it runs next under **Next scheduled**.
      </Step>

## Write instructions that work unattended

Nobody is in a Trigger's chat while it runs, so Ari cannot ask you anything. When something is unclear, it makes a reasonable assumption, keeps going, and says what it assumed in its result. Write instructions that need no follow-up:

- Name what to read: the Page, table, or Variable, and the Scenario if it is not Main. A run has no Page open.
- Name the period, such as "the last closed month" or "the prior week".
- Say what to return and how to judge it, such as "flag any expense line more than 10% over Forecast".
- Say where to send it: "email me" or "send it to my Slack direct messages". Without that, Ari posts the result in the chat you created the Trigger from, and the run's own chat keeps the full record.
- Set any MCP server tool the job needs to **Allow**. A tool on **Ask first** does not run in a Trigger; see [What a run cannot do on its own](/concepts/automation#what-a-run-cannot-do-on-its-own).

> Compare Actuals with Forecast for Operating Expense in the last closed month on the Monthly P&L Page. Flag any line more than 10% over Forecast, and send the summary to my Slack direct messages.

If you want a report on every run, say so. A run sends a warning only when something has changed since the last run, so the same warning does not arrive week after week; see [The record each run keeps](/concepts/automation#the-record-each-run-keeps).

## Choose where the result goes

Every run's result is saved in its own chat, listed in the Trigger's **History**. A result the instructions ask for also reaches you in cfo.ai, and a copy goes to email or Slack only when the instructions name that channel:

| The instructions say | What happens |
| --- | --- |
| Report to me, notify me, or nothing about where to send it | Ari posts the result as a message in the chat you created the Trigger from, or in your most recent chat in the workspace when that chat is gone. The message starts no reply, and Ari reads it when you next write in that chat. If you have no chat in the workspace, nothing is posted, and the run's record says so. |
| Email me | Ari emails your sign-in address. Headings, lists, tables, and links in the message show in the email. |
| Send it to my Slack direct messages | Ari sends you a Slack direct message, once Slack is connected. See [Talk to Ari from Slack](/guides/use-ari-in-slack). While no Slack workspace is connected, the run posts the same message in your cfo.ai chat instead, as in the first row, and records that Slack refused it. |
| Post it in this channel, or Post it in #finance | Only for a workspace administrator, and only for a private Slack channel Ari has already been added to. Each run posts its Slack message in that channel instead of your direct messages, and everyone in the channel reads the result, prepared with your access. Ask from inside the channel ("post it in this channel") or name the channel. To go back to direct messages, ask Ari to remove the channel from the Trigger. A run posts nothing, and reports why, when Ari has left the channel, the channel became public, or you are no longer an administrator. |
| Email someone else | Nothing is sent. The run leaves an email preview in its chat, and the email goes only when you open the chat and select **Send**. See [Email preview card](/reference/chat#email-preview-card). |

A Trigger cannot email anyone but you, and only an administrator's Trigger can post in a Slack channel. To share a result with others another way, have the Trigger update a Page and [share the Page](/guides/share-a-page). A Trigger can also export a Page as a spreadsheet. The file is saved in the run's chat, and the email or Slack message can carry a download link that works for a limited time. See [Limits](/reference/limits#skills-triggers-and-guides).

## Change, pause, or delete a Trigger

Ask Ari, for example "Pause my weekly cash Trigger", "Move it to Tuesdays at 9am", or "Delete the old variance Trigger". Or open the account menu, choose **Manage triggers**, and select the Trigger:

- To change its name, instructions, or schedule, select **Edit trigger** (the pencil), make the change, and select **Save changes**.
- To pause it, select **Edit trigger**, turn off the switch so it reads **Disabled**, and select **Save changes**. Turn the switch back on to resume. A paused Trigger reads **Paused** in the list.
- A one-time Trigger turns itself off when its run is queued, and reads **Schedule finished** in the list, with **Nothing upcoming** under **Next scheduled**. Its run still appears in **History**. To run it again, select **Edit trigger**, set a new date and time in the future, and select **Save changes**; changing the date or time turns the switch back on. Turning the switch on without a new date is refused.
- To run it once right away, select **Run now**. This works on a paused Trigger too and leaves the schedule as it is.
- To delete it, select **Delete trigger** (the trash can) and confirm. A run that already started still finishes.

You see and manage only your own Triggers. Your teammates' Triggers do not appear on your Triggers page, and you do not appear on theirs.

## Check whether a Trigger ran

Open the account menu and choose **Manage triggers**. Each Trigger in the list shows what happened last, such as **Finished**, **Did not complete**, or **Skipped: Ari was still busy**. Select a Trigger to see **Next scheduled** and its **History**: every run, newest first, with its status. A run that did not complete shows its own one-sentence reason. A run reads **Did not complete** both when it could not do the task and when it delivered a result with a part missing, such as a source it could not read; only a run that did the whole task reads **Finished**. Select a run to read its chat. For what each status means, see [The cfo.ai interface](/reference/interface#triggers-page).

You can also ask Ari:

> Did my Monday cash Trigger run last week, and did it finish?

Ari tells a run that only started apart from a run that finished its task, and it can tell you how many runs in a row have failed since the Trigger last finished its task.

A Trigger does one run at a time. When a run is still going at the next scheduled time, that scheduled run is skipped, and the Trigger's details read **The last scheduled attempt was skipped**.

## Reply to a run that needs you

A run never waits for an answer. When it has a question, such as which bank account to use, it works on an assumption and leaves the question in its chat. The run then reads **Needs response** in **History**. Open the run and answer there; Ari picks up from your reply. From your first reply, the chat is listed with your other chats. Your reply does not change the result the run recorded.

## If something goes wrong

<AccordionGroup>
  <Accordion title="The Trigger runs an hour early or late">
    A Trigger saved before time zones were added runs in UTC, so its local time moves by an hour when daylight saving time starts or ends; its details show **Time zone** as **UTC**. Open **Edit trigger**, set the time again, and select **Save changes**: the schedule is saved with your browser's time zone and keeps its local time from then on. You can also ask Ari to move the Trigger to your time zone.
  </Accordion>
  <Accordion title="No email or Slack message arrived">
    Check that the instructions name the channel. Then open the run from **History**: Ari's activity in the chat shows whether the email service or Slack accepted the message. For Slack, check that Slack is connected and that your Slack email matches your cfo.ai email; see [Talk to Ari from Slack](/guides/use-ari-in-slack).
  </Accordion>
  <Accordion title="The Trigger paused itself after three failed runs">
    When three runs in a row end without finishing the task, and none of them reached you with a message in cfo.ai, by email, or in Slack, cfo.ai pauses the Trigger so it does not fail night after night. The Trigger reads **Paused with an error** in the list, and its details read **This trigger is paused** with **This trigger was paused after 3 consecutive runs failed or ended without a completion report, with no notice delivered to you.** When billing stopped the newest run, the reason adds **The most recent run was stopped by billing.** and why, such as **The workspace had no AI usage remaining.** The same sentence is posted as a message in your most recent chat, starting **Trigger "[name]":**, with no email or Slack message. Open the newest run from **History** to see what went wrong, fix it, then select **Edit trigger**, turn the switch back on, and select **Save changes**; the count starts again from zero. A run that reaches you, even to report a failure, does not count toward the three.
  </Accordion>
  <Accordion title="A one-time Trigger paused without running">
    When a one-time Trigger could not start at its date and time, for example because the workspace had no active plan, cfo.ai keeps trying for 24 hours, then pauses it with the reason **One-time schedule paused after 24 hours without queueing a run. Resume it or set a new future date and enable it.** Select **Edit trigger**, set a new date and time, and select **Save changes**.
  </Accordion>
  <Accordion title="Run now says the Trigger already has a run">
    The message reads **This trigger already has a queued or active run. Open its latest conversation.** Open that run from **History**, or wait for it to finish.
  </Accordion>
  <Accordion title="The Trigger paused itself after a connection was removed">
    When someone removes a connection, cfo.ai pauses every Trigger in the workspace whose instructions refer to it the way Ari writes a connection: its name, `#`, and the start of its id, such as `Stripe#aa9`. A Trigger that escaped that pause, for example one saved against a connection that was already gone, pauses on its first run that is refused at the removed connection; the reason then names the reference as the instructions write it and the date the connection was removed. Either way the Trigger shows as paused on the Triggers page, with the reason under its last attempt; [The cfo.ai interface](/reference/interface#triggers-page) lists the status and the sentences. No email or Slack message is sent. Select **Edit trigger**, change the instructions to name a current connection, turn the switch back on, and select **Save changes**. The notice clears, and the next run records a new outcome. A Trigger that names the connection by a plain word, such as "Stripe", is not paused; its runs report that the connection is missing.
  </Accordion>
</AccordionGroup>
