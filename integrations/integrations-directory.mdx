cfo.ai connects to the systems where your financial and operational data already lives, so your Model stays current without manual entry.

## Standard and premium integrations

Your plan can classify connected sources as standard or premium:

- **Standard**: QuickBooks Online, Xero, Rippling, Google Sheets, and many more.
- **Premium**: NetSuite SuiteAnalytics and all database connections.

File upload is not a billable integration. Check your workspace's Usage or billing settings for the current limits and classification that apply to your plan.

## File upload

**CSV / Raw File Upload** is a manual option for bringing in a raw file directly. Use it when a live connection is not set up yet, or for a one-off or specialized report a system does not sync automatically. File upload is not a billable integration.

An uploaded file is tracked as its own connection, using its filename until you rename it, so ask Ari by that name if you need to check on it later. An uploaded file never refreshes on its own. To bring in newer data, upload the file again; the new upload replaces the data from the previous one.

After upload, ask Ari whether the file has finished loading. Ingestion runs in the background, and a Model that ends up with fewer rows than the source file is not necessarily a problem: a query that intentionally scopes the data down looks the same from the outside as one that is missing rows, so ask Ari to explain what the load produced before treating a smaller row count as an error.

This is for bringing a file's data into your Model as Actuals. To attach a file to an Ari chat message instead, for Ari to read a screenshot, PDF, or spreadsheet in the moment, see [Attach files to a chat message](/workspace-settings/file-attachments-in-chat).

## Accounting and ERP

- **QuickBooks Online** (Standard)
- **Xero** (Standard)
- **Rillet** — connects with a Rillet API key; a workspace holds one Rillet connection. Besides the ledger, it syncs customers, contracts, and invoices as their own tables, so Ari can query bookings and billing beside the accounting data. Its income statement and balance sheet land one row set per subsidiary, with **Entity** naming the subsidiary and **Currency** taken from each row, so a Model can report by subsidiary. Adding the subsidiaries up does not reproduce Rillet's consolidated view, because Rillet applies intercompany eliminations only there.
- **NetSuite SuiteAnalytics** (via Fivetran, Premium)

Use an accounting or ERP integration when you want Actuals to update automatically each time your books close. QuickBooks Online connections load the profit and loss statement and the balance sheet; Ari builds cash flow from those. Each report loads one row per line as QuickBooks prints it, and a subtotal row is marked as one, so Ari's queries total the detail rows only and do not count a subtotal twice.

A QuickBooks Online full-history load also fetches the balance sheet for the month before the history window begins, so the first month of Actuals can show how each balance changed. The Xero balance sheet files each account on the side of the statement where Xero's own report shows it: a credit card that Xero lists under current liabilities counts in **Liabilities**, not **Assets**, so the imported statement balances, while an account's type and the amount itself do not change. An installed Xero balance sheet query nobody has edited takes this text at its next sync. A Xero read that Xero refuses with a temporary error is retried a few times before the load reports a failure, and so is a QuickBooks Online read that fails because the provider was still refreshing the company's access token.

A workspace holds one QuickBooks Online company and one Xero organisation at a time. Connecting a second one reports that the integration's connection limit is reached. If you run more than one legal entity and want the group in a single Model now, export the second entity's ledger and bring it in through **CSV / Raw File Upload**, then give the Model an Entity Dimension so you can report on each entity and on the group. [Dimension mappings](/formulas/core-concepts/dimension-mappings) covers landing two entities' account structures in one reporting structure. Ask Ari what your own workspace allows before you plan around the limit.

Statements from QuickBooks Online, Xero, and Rillet carry **Entity** and **Currency** columns, and an accounting query's compatible Dimensions join the ones an earlier query created on its first sync, so two sources share one Entity rather than two. See [Share one Dimension across accounting sources](/formulas/core-concepts/dimension-mappings#share-one-dimension-across-accounting-sources).

cfo.ai checks that NetSuite shares the tables the income statement and balance sheet need when the connection first finishes setup, and again before every sync, whether the nightly refresh or one you ask Ari for. If a table is missing, the connection reads **Missing access in NetSuite SuiteAnalytics**, with a red triangle on its sidebar row, and its warning reads: **NetSuite isn't sharing some tables cfo.ai needs for your financial statements. Have your NetSuite admin create an access token for the Data Warehouse Integrator role, then reconnect NetSuite with that token. Changing only the role ID won't work. Missing tables: …**

A NetSuite access token belongs to one role, so entering a different role ID in the connection form changes nothing; the connection needs a token issued for the Data Warehouse Integrator role. Once that token is in place, the next sync asks NetSuite for its table list again, syncs the tables it finds, and clears the warning in the same run. While the warning stands, a sync that brings back no statement rows reports the missing access, with the next step **Grant access to the missing source tables to continue**, rather than an empty source. Ari sees the same warning when it inspects the connection. It can start a sync to re-check, but it does not rewrite the connection's saved queries to work around the gap.

A NetSuite sync is reported complete only once the provider's step that rebuilds the report tables from the synced data has finished, so the income statement and balance sheet queries read this sync's numbers rather than the previous run's. When that step is paused, blocked, fails, or has not finished after 15 minutes, the sync reads **Sync failed** and the next scheduled sync tries again; Ari reports the same cause and can retry it now. Ask Ari to add a NetSuite table the reports do not read, from the tables NetSuite shares; NetSuite takes additions only, because its reports read tables that saved queries do not name.

## HR

- **Rippling** (Standard)

Connect Rippling to bring headcount, compensation, and other people data into your Model alongside your financials. cfo.ai's catalog also lists a much longer roster of HR and payroll systems available to connect (via Merge), including BambooHR, Gusto, Workday, ADP Workforce Now, Paychex, Paycor, Justworks, TriNet, UKG Pro, Deel, Personio, Hibob, and dozens more. If your HR system is not Rippling, ask Ari to check whether it is in the catalog before assuming you need a file upload or manual entry instead. Signing in again to a company the workspace already holds through one of these systems is refused: the card reads **[Company] is already connected**, tells you to use that connection instead of adding another, and offers **Reconnect** when the existing connection needs it.

A payroll system connected via Merge, such as Gusto, loads benefits and pay groups separately from payroll, so a payroll row the warehouse refuses no longer discards the benefits that loaded with it; the sync reports the benefit rows it wrote and why payroll was not written. Gusto pay stubs that arrive without a parent payroll run are kept. The same sync also lands each employee's gross pay and net pay per payroll run, with the pay period's start and end dates and the check date, so Ari can build payroll cost per person and per month from a payroll system; a connection fills that history at its next sync, and a total the provider did not report stays empty rather than reading 0.

A new Rippling connection syncs the seven tables cfo.ai's daily employee roster reads: workers, users, worker details, departments, teams, team membership, and work locations. There is no table picker for Rippling at setup; once the connection is linked, ask Ari to add a table from Rippling's list, and a table you added can be removed again while no saved query reads it. Rippling connections made earlier keep the tables they already sync. A numeric roster column such as pay rate reads, in each period, each employee's latest value in that period; a period with no sync carries the previous value forward, and an explicit zero replaces it. Department and company totals add each employee's latest value once.

## CRM

- **HubSpot** (via Fivetran)
- **Salesforce** (via Fivetran)

Connect a CRM when Bookings, pipeline, or customer data needs to feed your Model directly, rather than being re-entered from a report export.

A HubSpot connection starts with a standard set of 20 tables: deals, deal pipelines and their stages, owners, contacts, companies, line items, products, and invoices; the links between deals, contacts, companies, line items, and invoices; and the property histories of line items, products, and invoices, so Ari can attribute a deal to its contact or company and reconcile invoices against deals. A table HubSpot does not expose is skipped. Every sync reapplies that set, so a table someone enabled in Fivetran outside it stops syncing, and a deal still loads when the account has no deal type field. To sync a table outside the set, ask Ari to add it once the connection is linked; the same goes for Salesforce. A table added that way loads its full history and can be removed again while no saved query reads it, and a connection selects at most 100 tables.

## Spreadsheets and files

- **Google Sheets** (Standard)
- **Google Drive**

Use a Google Sheets connection when a Variable is still maintained in a spreadsheet outside your other systems. You sign in with Google and pick one spreadsheet in Google's file picker; cfo.ai reads only the files you pick and keeps no copy of the files themselves; the data Ari imports from a file is stored in your Model like any other import. **Google Drive** works the same way for one Google Sheet, Excel workbook, or CSV file. Ari imports the file as it would an upload, and the connection re-reads it on the nightly refresh and when you ask Ari to refresh it. A Google Sheet is read as an Excel workbook of up to 50 MB; an Excel or CSV file stored in Drive is read up to 10 MB, and a larger one is not imported until it is made smaller. Every Google Sheets connection in a workspace shares one plan slot, while each Google Drive connection takes a slot of its own; your workspace's Usage settings show which class your plan gives each. See [Connect a Google Sheet or Drive file](/integrations/connect-and-sync-data#connect-a-google-sheet-or-drive-file).

## Databases

- **PostgreSQL** (via Fivetran, Premium)
- **Amazon RDS for PostgreSQL** (via Fivetran, Premium)
- **Amazon Aurora PostgreSQL** (via Fivetran, Premium)
- **Google Cloud SQL for PostgreSQL** (via Fivetran, Premium)

Use a database connection when your data lives in a system of record that does not have a dedicated integration above, but is reachable through one of these PostgreSQL-compatible sources.

A cloud data warehouse is not one of them. Snowflake, BigQuery, Redshift, and Databricks are not sources you can connect today. To model curated warehouse datasets now, land them in a PostgreSQL-compatible database cfo.ai can read, or export them and bring them in through **CSV / Raw File Upload**.

The connectors shown in your workspace's catalog can differ from this list depending on your plan and rollout. Ask Ari to check the catalog for a specific system.

## Connections for Ari

The integrations above bring data into your Model. Separately, **Settings → Connections** lets an authorized workspace administrator connect external tools and services for Ari to use directly. The **MCP** and **APIs** tabs show available connections and the services already connected for your workspace. Ari can also prepare one of these connections for you in chat; see [Ask Ari to connect an MCP server or API](/integrations/connect-and-sync-data#ask-ari-to-connect-an-mcp-server-or-api).

### MCP Connectors

Browsable by category:

- **Payments** — Stripe, PayPal, Square, Mercado Pago
- **Banking & Spend** — Mercury, Ramp, Brex, Expensify, Plaid
- **Accounting & Tax** — Avalara AvaTax, Avalara Returns, Numeric
- **HR & Payroll** — Gusto, Deel
- **Equity & Compliance** — Carta and Vanta
- **Market Data** — Alpha Vantage and Morningstar
- **CRM & Sales** — Intercom, Close, and Attio
- **Productivity & Docs** — Notion, Linear, Atlassian (Jira and Confluence), Airtable, monday.com
- **Data & Analytics** — Supabase and ThoughtSpot

Rippling also offers a remote MCP server at `mcpgateway.rippling.com`. Add it with **Add manually**; the **Add MCP server** dialog shows a **Rippling setup** note with what Rippling requires before its tools return data: copy the server URL from **IT → My IT → MCP connectors → Rippling MCP**, have a Rippling admin assign you access under **IT → MCP Gateway → Rippling MCP → Access assignments**, and hold an active Rippling AI trial or subscription. The same note appears beside the server's tool-loading error and on Ari's connect card.

If you do not see what you need, use the search bar to look for others, **Add with Ari** to have Ari research and connect the provider in a chat, or **Add manually**. **Add manually** opens the **Add MCP server** dialog, which takes a **Name** and the **MCP URL**; under **Advanced**, its **Authentication** choice is **OAuth**, **Bearer token**, or **API key header** with a **Header name** such as `X-API-Key`. Connections made from this catalog or the API list show the company's logo on the Variables, Dimensions, and tables they produce. A server or API you add by address shows its company's logo too when the address is a public company domain; a private or local address keeps a generic mark.

For how to connect cfo.ai's own MCP server to Claude Code, see the [MCP Server](/integrations/mcp-server) page.

Use the search bar, **Add with Ari**, or **Add manually** for anything not listed. **Add manually** opens the **Add API** dialog, which takes a **Display name**, an **API key**, and an **OpenAPI specification**, version 3.0 or 3.1, given as a **Specification URL** or with **Paste JSON**. A specification URL must be an https address and may carry a query string; cfo.ai gives the address 20 seconds to answer and accepts a document of up to 12 MiB. When the document cannot be used, the connection reports the stage that failed and a short reason, such as a required field that is missing, a reference that does not resolve, or an unsupported version field, and a workspace administrator can ask Ari for the ten most recent setup attempts. When the address gives no document, the reason says which way it failed: **The specification URL is not an https address.**, **The specification URL answered HTTP 404, not the document.**, where 404 stands for whatever status the address answered, or **The specification document is larger than the 12 MiB this connection accepts.** An address that does not answer at all reads **Could not load the OpenAPI specification. Check its URL or paste the document as JSON.**

## How integrations stay current

Connected integrations refresh once a day, automatically. By default every integration, whether it is QuickBooks Online, Xero, NetSuite, Google Sheets, or a database, refreshes in one shared nightly run that starts at 02:00 UTC and finishes within a few hours, so your Actuals are fresh by the start of the US workday.

A source that publishes its daily data after that run lands a day late on every refresh. Ask Ari to move that connection's refresh to a time of day instead:

> Refresh QuickBooks at 6:30 AM Pacific every day.

A refresh in which one table fails still finishes: the other tables load, the connection reads **Partly synced**, and the failed table is read again on the next refresh; see [When a sync fails](/integrations/connect-and-sync-data#when-a-sync-fails).

Ari saves the time and its time zone on the connection. From the next nightly run, the connection starts its own refresh at that time and reruns its saved queries when the refresh finishes, once per calendar day in that time zone, and the other connections keep the shared run. A change applies from the first nightly run after it, so a time set this morning takes effect tomorrow. Ask Ari to clear the time to return the connection to the shared run. A file upload has no scheduled refresh, so it cannot take a time. Ari reports each connection's refresh time when you ask about your connections. A connection's **last loaded** time counts successful loads only; a refresh that failed does not move it.

There is no manual refresh button today. If you need a number sooner than the next nightly run, ask Ari to refresh the connection:

> Refresh QuickBooks and tell me when the import has finished.

Ari starts the import in the background and can tell you when it completes. Before relying on a time-sensitive result, ask Ari when the source last finished syncing and whether it reported any problems.

When you first connect QuickBooks Online or Xero, cfo.ai loads Actuals from January 1 of the previous year through today. Ask Ari which accounting periods are available once the first load completes. For older books, ask Ari for a full-history import that starts at a year you name, 2015 or later; the months it imports stay through later routine refreshes.

The nightly refresh and asking Ari to refresh a connection work the same on every active plan, including during a trial. Plans differ in how many connections you can hold, not in what a connection does once it is connected. A workspace with no plan, or whose billing is locked, is not refreshed: the nightly run skips its connections, and a refresh you ask for answers **data syncing is paused for this workspace — choose a plan, or settle the outstanding payment, to resume syncing**. Refreshing resumes as soon as the workspace has an active plan again.

## API and MCP connections are live tools

The integrations above bring data into your Model on a schedule. API and MCP connections under **Settings → Connections** are different: they are tools Ari calls live when you ask a question. Nothing is stored or scheduled unless you ask Ari to save a sync setup. If Ari writes a number from one of these calls into your Model, it lands as a plain value that stays put until you ask Ari to pull it again.

The one stored, scheduled case is a sync setup Ari saves over one of a connection's tools or endpoints. The tool must be linked, allowed, and have a known input shape; it may be one that can also write, and then Ari saves a call whose every argument only retrieves the records you asked for and leaves the source unchanged, and each refresh repeats that saved call as it is. When Ari runs it, its rows land in the warehouse as a source table, the connection's saved queries rerun, and a saved query brings the rows into the Model; the connection's page lists each setup as **Enabled** or **Paused**. A sync from an MCP server reads the tool one page at a time: it gives the server 45 seconds to connect and 45 seconds to answer each call, holds an answer of up to 2 MiB per page, and stops when the whole sync reaches 10 minutes. When a page fails, the sync's record names the page and what stopped it, such as a tool whose definition changed since the setup was saved, an answer that is not one JSON result, or a server that rejected the connection's authorization, and Ari can read that record when you ask what happened.

Stripe is an example of a source you can use both ways. The **Integrations** tab lists **Stripe** and **Stripe Sandbox**, which sync Stripe data into your Model on a schedule like any other integration. Connected as an MCP connector or an API connection instead, Stripe becomes a tool: Ari can look up a balance or a payout when you ask, then write the figure into a Table Block as an editable value.

A scheduled Stripe sync lands Stripe's customers, subscriptions and their items, subscription schedules with their phases and phase items, invoices with their items, lines, line discounts, and payments, charges, refunds, disputes, payment intents, balance transactions, payouts, products, plans, prices, coupons, discounts, credit notes, payment methods, and setup intents and attempts as source tables. Products, plans, and prices are listed in both their active and archived states, and refunds, disputes, payment intents, and subscription schedules in every status. An object that another row names but Stripe's lists leave out, such as a deleted customer or a price created inline on a subscription, is fetched by its ID, and an object Stripe has deleted is kept as a row with **IS_DELETED** set, so an invoice's customer or a subscription item's price is there to join to. A coupon Stripe's list no longer returns but a discount still carries is kept the same way. Stripe lists payment methods one customer at a time, so for an account with many customers that table fills over several nightly syncs; for the customers not reached yet, the table holds only what earlier syncs and later changes to a payment method wrote, and Ari can say how far it has got.

A table that needs a permission the version of cfo.ai's Stripe app installed on your account does not include, at present coupons, payment intents, and disputes, is not a failure. The sync completes, the connection stays connected, and that table holds only the objects that Stripe's events and other objects carried. Every sync asks Stripe again, and the first sync after an owner of the Stripe account approves, in Stripe, an app version that includes the permission lists the table in full. Signing in again does not change the app's permissions and is not needed. Ari is told once when the state begins and once when it ends, and reports it whenever you ask about the connection in between.

API and MCP connections also do not use a plan integration slot. Only the integrations above, the ones that import data into your Model, count toward the standard and premium limits your plan sets, so you can add API and MCP connections without spending an integration you would rather give to your accounting or payroll system. Each connection takes its own slot, so connecting a second company or organization in a system you already use spends another integration. Every Google Sheets connection in a workspace shares one slot, as described above. An integration that is paused or needs attention still holds its slot until you remove the connection.
