Integrations bring financial and operating data into your cfo.ai Model. Connect a source when real accounting, people, customer, or spreadsheet history should inform your analysis.

## Choose the right source

Common starting points include:

- Accounting systems such as QuickBooks Online, Xero, or NetSuite.
- HR and payroll systems such as Rippling, Gusto, BambooHR, or Workday.
- CRM systems such as HubSpot or Salesforce.
- A Google Sheet, a file in Google Drive, or a PostgreSQL-compatible database.
- A CSV or another supported file-upload flow for a source that is not connected directly.

Available sources and plan entitlements can vary. Ask Ari to check the catalog for the system you use.

A file you upload as a data source must be a CSV with a `.csv` extension, up to 50 MB. An uploaded Excel workbook is not accepted as a data source: attach it to a chat message for Ari to read, ask Ari to [import it as a model](/getting-started/import-a-spreadsheet-model), or connect it through [Google Drive](#connect-a-google-sheet-or-drive-file), which imports a workbook the way Ari imports an upload.

## Connect a business system

<Steps>
  <Step title="Tell Ari what you want to connect">
    Name the source and what you want to use it for.

    > Connect QuickBooks Online so we can build a monthly profit and loss statement.

  </Step>
  <Step title="Approve the connection">
    Ari opens or links you to the connection flow. Complete the sign-in and approval in your browser. Ari cannot enter your password or approve access for you.
  </Step>
  <Step title="Choose the tables to sync, when asked">
    Some sources, such as Shopify, NetSuite, HubSpot, Salesforce, or your own database, show a table picker after you sign in. Every available table starts selected, so uncheck the ones you do not need, then choose **Finish setup & sync N tables**, which names the count it will import; after setup, ask Ari to add or remove tables, as [Choose which source tables sync](#choose-which-source-tables-sync) describes. At most 100 tables can be synced per connection, and a source with more than that, such as Shopify's full list, starts above the cap and asks you to uncheck tables before it lets you finish. Locked tables stay selected, and a source whose catalog lists features your account does not have, such as NetSuite, starts those tables unchecked. A larger selection makes the first sync longer. **Cancel setup** ends the setup: a new connection that never finished is removed, so nothing is left behind, and a connection that was already linked is kept.
  </Step>
  <Step title="Wait for the initial load">
    cfo.ai starts loading the connected data after the source links. The import can continue in the background while you work on something else.

    A source may still be running its own first sync when cfo.ai's load begins: an HR or payroll system such as Gusto, or a source that syncs through Fivetran, such as HubSpot, Salesforce, or a database, whose first sync copies the account's whole history and can take hours. cfo.ai then checks again every ten minutes until the provider's first sync finishes or fails, loads the data as soon as it completes, and gives up only when the provider reports a failed or paused sync. Ari can tell you that it is waiting on the provider.
  </Step>
  <Step title="Check what arrived">
    Ask Ari whether the connection has finished, when data was last loaded, and which information is ready for analysis.

    > Check whether QuickBooks finished syncing and tell me which accounting periods are available.

    If a past period was wrong at the source and you have corrected it there, ask Ari to re-import the connection's full history. The routine refresh covers recent periods only. A full-history import of QuickBooks Online or Xero starts at January 1 of the previous year unless you name its first year, 2015 or later; the months it imports stay through later routine refreshes, and a QuickBooks import also takes the balance sheet of the month before that year.

  </Step>
</Steps>

## Connect from the sidebar instead

You can also start without Ari. The **Connections** section of the sidebar lists each connection as a row, and reads **No connections yet** while there are none. Select its **+** button, **Add integration**, to open the connection manager, which has three tabs:

- **Integrations** lists the business systems cfo.ai can import from, with a **Connect** button on each card and an **Upload** button for CSV files.
- **MCP** lists MCP servers Ari can call, such as Linear or Notion, plus **Add manually** for one that is not listed and **Add with Ari**, which opens a chat where Ari helps you connect the provider. **Add manually** opens the **Add MCP server** dialog, which takes a **Name** and the **MCP URL**; its **Advanced** section has an **Authentication** choice of **OAuth**, **Bearer token**, or **API key header**, the last with a **Header name** such as `X-API-Key` and the key. When the URL's host is `mcpgateway.rippling.com`, the dialog adds a **Rippling setup** note listing what Rippling requires first: the server URL from **IT → My IT → MCP connectors → Rippling MCP**, access assigned by a Rippling admin under **IT → MCP Gateway → Rippling MCP → Access assignments**, and an active Rippling AI trial or subscription; the same note appears beside a saved server's tool-loading error and on Ari's connect card. A server that refuses Ari because it needs a sign-in says so: **This MCP server requires sign-in. Disconnect it and add it again with OAuth or a bearer token.** When a saved server's tools fail to load, the message names the server's answer: **The MCP server rejected authorization (it answered HTTP 401). Reconnect this server and try again.** or **Could not load tools from the MCP server (it answered HTTP 404). Try again shortly.** Ari sees each connected server's name and status at the start of every message, so it knows to read a bank balance from a connected Mercury server without being told.
- **API** lists other services' APIs Ari can reach, such as Stripe, plus **Add manually**, which opens the **Add API** dialog, and **Add with Ari**.

Each sidebar row shows the connection's status; hover it for its actions, or select it to open the connection's page. The section leads with what needs a look: an app with a connection in any state other than ready, apart from a routine nightly sync, sorts to the top, and inside the app that connection sorts first; the rest keep their order. An app with several connections starts expanded when one of them needs a look, and a click folds or unfolds it until you reload. When the section is folded with rows under it, its chevron shows without hovering. Starting a server's sign-in again, from Settings or from one of Ari's setup cards, replaces the unfinished attempt rather than adding a second one, so a workspace holds one pending connection per MCP server. See [Connect data by hand](/getting-started/build-by-hand#connect-data) for the click paths.

A connection you start here still reports to you in chat. While your workspace is new, before any connection has completed a first sync, cfo.ai ties the new connection to your most recent chat, so Ari announces there when the link completes and when the first sync finishes or fails. After that, the result of a background sync, such as data that is ready to model or a first sync that failed, is still delivered to the chat you used most recently.

## Ask Ari to connect an MCP server or API

A workspace administrator can also have Ari set up an MCP server or an API from the chat, for example "Connect PostHog's MCP server." **Add with Ari** on the **MCP** or **API** tab of the connection manager, or on the **MCP** or **APIs** tab under **Settings → Connections**, opens a chat that starts the same way, asking which provider to connect and what you want to do with it. Ari reads the provider's official documentation, then posts a card headed **Connect [service]** with the service's logo, its address, how it signs in, and a **Provider documentation** link. In this chat flow an MCP server signs in with OAuth or a **Bearer token**; a server that needs an API key header is added from the **Add MCP server** dialog instead. An API uses a **Bearer API key**, a named header, an **API key as Basic username**, or **No authentication**. The card carries no credentials, and Ari never asks for a key in the chat.

Select **Connect**. A service that uses OAuth opens its sign-in window; one that takes a token or key shows a secure field on the card, and what you type there goes to cfo.ai's connection service, not to Ari or into the conversation. The card reads **Connecting…**, then **Checking connection…** while cfo.ai confirms that the server's tools answer or that the API's endpoints loaded, then **Connected** for a server or **API saved** for an API. On a failure it offers **Retry**, and a retry keeps a connection that was already saved; **Cancel** stops the setup. A member who cannot manage connections sees **A workspace admin must connect this service.**

When the provider refuses cfo.ai's sign-in address, the message **The provider must approve cfo.ai's sign-in URL to connect.** appears on the card, and in the **Add MCP server** dialog in Settings. Trying again cannot fix that; the provider has to allow cfo.ai's callback address first. A provider that rejects the registration for another reason is named as the one that refused, and a temporary failure still asks you to try connecting again. Once a server is connected, Ari gives it 45 seconds to answer when a chat turn or the Settings page lists its tools; a server that stays silent is reported as unavailable for that turn, and the other servers' tools still work.

Once the card completes, Ari continues in the same chat: it checks the connection's tools or endpoints and, for an API, verifies the key with a documented read before relying on it. When Ari calls a connected API, it reads a JSON response of up to 160 KiB whole; a larger response is not returned, and Ari is told its size and the limit, with the response's page metadata when it has any, so Ari can ask the service for less at a time. **API saved** means the definition parsed, not that the key works. An OAuth provider that needs a preregistered app, and an API that signs in with a username and password or with a key in the query string, cannot be set up this way; Ari says so instead of collecting the secret.

## Finish a connection you started earlier

If the source's sign-in window closes before you finish authorizing, for example because a pop-up was blocked or you are not the company's administrator, the connection card says **QuickBooks Online was not connected** (with the name of the source you chose) and explains that the window closed before authorization finished. Select **Try again** to reopen the sign-in on the same pending connection, or **Close**. Trying again does not create a second connection.

Connecting the same source again later continues the unfinished connection instead of starting a new one, whichever door you use: **Connect** on the source's card, **Finish setup** on the connection, a connect link, or asking Ari. This applies while no connection to that source is linked yet and the earlier connection's setup never finished: its status reads **Setup not finished**, or it failed because its link expired. The status says only what cfo.ai knows for certain: the setup may have failed, been abandoned, or still be open in a teammate's tab.

If a Fivetran-backed source's table picker loses track of the setup, for example because you finished it in another tab, the page reads **Fivetran setup was interrupted** and offers **Go to cfo.ai**. The connection was saved, so choose **Finish setup** on it to continue. A connection that lost access and reads **cfo.ai lost access** is not picked up this way; use **Reconnect** on it. Continuing a connection someone else started needs edit access to that connection. When you continue a connection from a chat, that chat is the one Ari reports to when the link completes and the first sync finishes.

## Connect a Google Sheet or Drive file

**Google Sheets** and **Google Drive** are listed under **Data upload** on the **Integrations** tab. Select **Connect** on the card: a Google sign-in opens, then Google's own file picker, where you choose one file. The Google Sheets picker shows spreadsheets; the Google Drive picker also shows Excel workbooks and CSV files. The card reports **Opening Google authentication…**, **Choosing in Google…**, **Completing connection…**, and then **Connected**. Closing Google's picker without choosing a file closes the flow with no error; the connection stays unfinished, shows **Setup not finished**, and offers **Finish setup**. Google grants cfo.ai access to the files you pick and nothing else in your Drive, and you can revoke it from your Google account.

What happens next depends on where you connected:

- **From a chat.** Ari attaches the file to that chat and imports it there, so Ari can ask you about the sheet while it works. The connection row reads **Attached to the chat that connected it. Ari imports it there.** Once that chat has imported the sheet, the row links the Page Ari built and reads **The chat that connected it handles later changes.**
- **From the connection manager.** Ari imports the file in the background without opening a chat. The row reads **Waiting for the first sync to read this file…**, then **Ari is importing this file…**, then **Imported to \[Page]**, with a link to the Page Ari built, and **Ari updates the model when the file changes.** If Ari stopped partway, the row reads **Ari stopped before finishing this import. The next sync tries again.** A file connected from a chat instead reads **Ari stopped before finishing this import. Continue in the chat that connected it.**, and a sync does not resume it. When you replace an uploaded file, Ari reports the upload as not ready until the new file's import finishes, instead of reading the previous file's rows; Ari reads an upload's rows in the Scenario the chat is in, the same Scenario its readiness report describes.

A Google Sheet is read with every tab, its formulas, cached values, and number formats, and Ari rebuilds it the way it rebuilds an uploaded workbook. Each sync compares the spreadsheet's content with the last import: its tabs, with their names, order, and whether each is hidden, every cell's value and formula, and its defined names. A sync that finds the same content starts no update and spends no AI usage, and the connection's row and its page add **The last sync found no change.** A change to number formats, colors, column widths, comments, or charts alone starts no update either; a changed value or formula starts an update of the Model. A Google Sheet is read as an Excel workbook of up to 50 MB, and an Excel or CSV file stored in Drive up to 10 MB. A larger file shows **This file is too large to import. Make it smaller and the next sync imports it.**, and in a chat Ari names the limit that applied, such as the 50 MB cfo.ai attaches as an Excel workbook. One connection reads one file, and the same file cannot be connected twice in a workspace. A Google Sheets or Google Drive connection made earlier through Fivetran keeps syncing as it did.

## Upload a file

If you attach a CSV in Ari chat, choose whether it should become a data source or stay attached only to the conversation.

- **Use as a data source** when the file's rows should become available in the Model.
- **Use in chat only** when Ari should read or summarize the file without importing it.

An uploaded data source is identified by its filename until you rename it. If the same filename already backs a connection, cfo.ai asks for confirmation before replacing it. Each file can be up to 50 MB. When you ask what went wrong with a load, Ari can copy the file as you uploaded it into the chat, including the lines the loader refused.

cfo.ai reads each column's type from its values. Dates are decided for a whole column at once: cfo.ai reads every value in the column and picks the one day and month order that reads them all, so a column holding `13/04/2026` is read day-first throughout, and a column whose values all read either way is read month-first. A column that needs both orders is not a date column. Dates may carry a clock, such as `2026-09-25 00:56`, and then load as timestamps rather than text. Plain digit strings such as `2024` or `20240229` stay numbers; only a column whose header is exactly `yyyyMMdd` is read as a date in that compact form, such as `20260131`. Some point-of-sale exports use this header.

A column named `Date` does not place the file's rows on the calendar by itself. Tell Ari which column dates the rows, such as an invoice date or a period column, and Ari saves it as the source's preferred time column; `first` and `last` over the source's rows then order by that column.

An imported source with no date column at all cannot be laid out by period. A Table Block that shows one of its Variables by month stops calculating and reports that the source **has no date column to read it by**, naming the source. Add a date column at the source and sync again, or tell Ari which existing column dates the rows. A read that does not depend on Date, such as `last` over the source's rows in a table with no Date axis, still answers. See [A table cannot date an imported source](/formulas/formula-reference/formula-errors-and-troubleshooting#a-table-cannot-date-an-imported-source).

If the file is an existing financial model rather than a source-data export, ask Ari to [import and rebuild the spreadsheet model](/getting-started/import-a-spreadsheet-model) instead of treating the workbook as an ordinary data connection.

## Follow a sync from the chat

When you ask Ari to sync a connection, the chat shows the sync the way the sidebar shows its connection. A line above the message box, under Ari's **Thinking…** status line, reads **Syncing** with the connection's name and offers **Stop**, and a card in the transcript lists the run's two steps, **Sync source data** and **Run saved queries**, with **Step 1 of 2** while it runs. A run that fails reads **Couldn't finish** and keeps the connection's own status, reason, and action, such as **Retry**. A run you stopped reads **Stopped**, with **This sync was stopped before it finished.**, because nothing broke. A file whose shape could not be read offers **Update file** instead of **Retry**.

A sync Ari starts reruns the connection's saved queries as written and writes no new ones; a source table with no saved query stays in the warehouse until you ask Ari for a query over it. When the run completes or fails, a system message arrives in that chat after the running turn ends, and Ari reports it, for example that the sync of QuickBooks Online completed and ran two saved queries. A run started somewhere else reports to the chat that started it.

## Understand sync status

A connected source is ready only after its background load completes. A linked account, started import, or uploaded file does not by itself mean the resulting data is already available.

A connection's details show a **Source tables** section, **When each table from this source last synced.**, once two or more of its tables have synced. Each row names the **Table**, when it was **Last synced**, and the date its **Data through** reaches. A connection whose sync reports a single table shows no section.

After the first load, connected integrations refresh once a day, automatically, in a shared nightly run that starts at 02:00 UTC; there is no manual refresh button, so ask Ari to refresh a connection if you need newer data sooner, or ask Ari to move one connection's daily refresh to a time of day in your time zone. File uploads never refresh on their own. See [how integrations stay current](/integrations/integrations-directory#how-integrations-stay-current).

If the Model contains fewer rows than the source file, ask Ari which source records were included. A saved query may intentionally filter the source to match your request. When a connection's saved queries return no rows although the source holds data, for example because a query joins through an empty report table, Ari can hand the connection to a background worker that repairs the queries. When you ask when a connection last loaded, Ari answers from the last successful load; a failed or canceled refresh does not count.

### Choose which source tables sync

A database or application connected through Fivetran offers many tables, and the connection syncs only the ones selected for it. You make the first choice in the connection's setup picker; tables the provider locks are synced as well and do not count against the limit. After setup, ask Ari to add or remove tables, for example "Also sync the subscriptions table from Postgres." A connection selects at most 100 tables. Tables you do not name keep their state. A newly selected table loads its full history, and on a connection that has already synced, Ari asks the provider to load that table's history again, as far back as the connection's other tables reach. The table reaches the warehouse when that import lands and reaches the Model only once a saved query reads it, so ask Ari for a query over a table you add.

Ari refuses to remove a table a saved query reads, because the query would keep showing the rows that last landed; delete the query first. It also refuses to remove the last selected table, because deleting the connection is how syncing stops, and a change on a connection whose setup is not finished, because that first selection belongs to the setup picker. A connection whose tables cfo.ai's catalog locks in place, such as HubSpot, Salesforce, or Rippling through Fivetran, has no selection to change. When you ask what a connection syncs, Ari can say whether cfo.ai or you chose its tables and list them in the source's own names; a table the catalog gained later syncs only for connections made after.

### Saved queries

Saved queries belong to Main. Ari creates, edits, and runs them in Main whatever Scenario you are viewing, and every ordinary Scenario reads Main's latest SQL and result; a Snapshot keeps the SQL and result it was pinned with. You cannot test a query change in one Scenario alone.

Saving a query, from **Settings → Connections** or through Ari, first plans it: the warehouse runs the statement once to count its rows and read its columns, with a limit of 40 seconds for one plan. A query whose plan runs longer is refused and nothing is saved. Ari's refusal says so and notes that the same SQL meets the limit again unless the warehouse runs it faster, so shorten the statement or narrow its reads before trying again.

A query that cfo.ai installed from one of its own templates, such as the Xero balance sheet, and that nobody has edited moves to the template's current text at the connection's next sync, so a template fix reaches it without a new connection. A query you or Ari edited keeps its text. An upgrade that would drop or change the type of a column the query already loaded is skipped, and the query keeps its saved text.

Ask Ari to remove a saved query you no longer need. Ari first previews what the removal retires, the Variables and Dimensions the query owns and the formulas and tables that read them, and deletes only when you confirm that list; the connection and its other queries stay. A query whose load is still running cannot be removed until it finishes.

When Ari reports that a source finished loading, it names the periods the load covered, such as **January 2025–September 2026**, and says that completion establishes nothing about data outside that range. A table the source finished with some records unavailable is called out as a partial result rather than complete Actuals.

Each column a query returns loads into the Model as a Variable or a Dimension, with a saved starting formula you can open from its row, edit, or delete like any other rule: a Variable starts with `sum` over the source column and a Dimension with `last`, the row with the latest date. Because the rule is an ordinary saved formula, it reads source rows in every period, including months after **Last close**. A column that loaded before starting formulas existed keeps the generated read instead, which returns its source rows in Actuals and 0, or an empty value, in Forecast; see [A cell no rule covers](/formulas/core-concepts/how-cfoai-chooses-a-formula#a-cell-no-rule-covers). cfo.ai guesses the role when the column first loads: a numeric column becomes a summed Variable unless its name marks it as an identifier: a name that ends in the word "id", including a camel-case ending such as `dealId`, or in "account number" or "account code", such as `Customer ID`, `deal_id`, `P&L Account Number`, or `SalesDefaultAccountCode`. Such a column loads as a text Dimension, so a leading zero in `00400` and every digit of a long ID stay as written, while `Account Balance` and `Number of Accounts` still sum. A column a database or warehouse query returns as text (`TEXT`, `VARCHAR`, `STRING`, or `CHAR`) loads as a text Dimension whatever its name and even when every value looks like a number, so a cast in the saved SQL, such as `to_varchar(stage_order)`, chooses the role before the first load; text whose values are all dates still loads as dates. Columns returned as numbers, and untyped CSV columns, still follow the name rule. An identifier that loaded as a number before these rules keeps its stored type, and an edit to the saved query that leaves such a column alone still saves: cfo.ai refuses a type change only for a column the edit itself changed, and the refusal states the stored type, when it was first set, and what the saved SQL and the edited SQL each return. If a code loaded as a summed Variable, ask Ari to load it as a Dimension instead. Ari switches the role in place, so formulas, tables, and filters that already point at the column keep working, and every later load keeps the new role. A switched column keeps its stored type, so a number column that becomes a Dimension has number items; to keep leading zeros, return the column as text under a new name. A column that loads into a Dimension other queries also feed, such as four QuickBooks connections' **Customer** columns feeding one Customer Dimension, cannot have its role switched for one query: Ari names the shared Dimension and the other queries instead.

A Variable or Dimension carries its source's logo on table row labels, column labels, column group headers, and formula reference chips when every reference in its formulas reads imported columns of one integration. Two connections of the same integration count as one, so a Dimension that joins two Xero ledgers shows the Xero logo, and a formula that reads the Variable itself, such as a total rolled up from its own segments, keeps the logo its other references earn. A formula that mixes integrations, reads another Variable, or reads through a segment literal or `this.` shows no logo. In table and formula search, a Variable or combined Dimension lists each contributing query with its integration's badge, or none while any of them is still unknown.

## Reconnect a source that lost access

When an accounting system such as QuickBooks Online or Xero revokes cfo.ai's access, for example after a password change or an expired authorization, the connection reads **cfo.ai lost access** after the next nightly refresh fails, with the line **Reconnect to start syncing again.** and a **Reconnect** action. Select it and sign in again to the company or organization the connection already holds.

A connection that is healthy or still syncing does not offer **Reconnect**. Signing in again cannot help it, so cfo.ai offers the action only when the source revoked access or when a failed sync needs a new sign-in. A connection whose setup never finished offers **Finish setup** instead, when the source's setup can be picked up where it stopped, as a Merge-based accounting or HR source, a Fivetran source, Rillet, or Plaid can. A source whose setup cannot be resumed, such as Stripe (Direct), offers only **Cancel setup** on its hover card, with the line **Setup wasn't finished. Cancel it and connect Stripe (Direct) again.**; on the connection's page the line says **Remove it** and the button is **Remove connection**. Cancel setup removes the connection without asking, because it holds no data yet. People who cannot manage connections see **Syncing won't begin until setup is finished.** and no button.

### Retry a failed import

When a linked connection's import failed but its sign-in still works, the connection offers **Retry** instead of **Reconnect**: on the connection's page and on its sidebar row's hover card. The directory card of a source that has connections reads **Added**, counts them, and offers **Add another** instead of listing each connection; the connection's own page holds its actions. Retry restarts the import on the same connection without signing in again and without using another plan slot, and the status moves from **Needs attention** through **Connecting** to **Synced**, the label a connection that loads data shows once its data is in; a connection that syncs nothing, such as an MCP server or API, reads **Connected** instead. A connection never offers both actions: **Retry** appears when cfo.ai knows the sign-in still works and only the import needs to run again, and **Reconnect** when the failure needs a new sign-in. Neither appears while an import or sync is still running, when the failure needs cfo.ai support, when the source is disabled, or for members who cannot manage connections.

Asking Ari to connect a source never re-authenticates an existing connection; reconnecting is a separate action that names the connection. If you ask Ari to connect NetSuite while a NetSuite connection already needs re-authentication and you do not say which company you mean, Ari asks whether you want another company connected or that connection reconnected. Name the company to add a second connection, or name the connection to reconnect it. When your plan's connection limit is reached, Ari's refusal names the connection that needs re-authentication so you can reconnect it instead of adding another.

If the provider's screen says you are already connected, its main button may read **Finish**; choose **Relink integration** there instead. **Finish** keeps the current authorization, and cfo.ai reports that the source **was not reconnected**, names the organization to sign in to, and offers **Try again**. Choosing **Relink integration** on a connection that is still linked succeeds: cfo.ai stores the new sign-in on the same connection and starts a sync, and the connection stays linked to the same company. A sign-in to a different company than the connection holds is refused, as is one to a company another connection in the workspace already holds. For Xero, if the consent screen lists your organization as already connected, disconnect the cfo.ai app under **Connected apps** in Xero, then try again; the card names the app as Xero lists it.

## When a sync fails

A source that syncs through Fivetran, such as NetSuite, HubSpot, Salesforce, a database, or a Google Sheets connection made earlier through Fivetran, stays connected when a sync fails on the provider's side. The connection reads **cfo.ai lost access** only when the provider asks for a new authorization. cfo.ai retries the sync on the next nightly run, and you can ask Ari to retry it now.

A stopped sync names its cause, in the sidebar row, the row's hover card, the connection's page, and the directory, and offers the one action that fixes it. The sidebar row marks a problem you must act on with a red triangle; a problem that resolves on its own, or that only cfo.ai can fix, gets a steady orange dot instead.

| What the connection says | What it means | What to do |
| --- | --- | --- |
| **Missing access in [source]**, such as **Missing access in NetSuite SuiteAnalytics** | The source is not sharing some tables the reports need. Red triangle. | Open the connection for the steps, then **Reconnect** with the new access. |
| **Sync failed**, with **[Source]'s sync hit an error. cfo.ai will try again on the next scheduled sync.** | The provider's own run failed, often for a moment. Orange dot. | Nothing, or **Retry** to run it now. |
| **Paused until next sync**, with **[Source]'s daily limit was reached. Progress is saved, and syncing picks up on the next scheduled run.** | The source's daily API allowance ran out. Orange dot. | Nothing; signing in again would not change the limit, so no **Reconnect** is offered. |
| **Sync stopped**, with **Contact cfo.ai support if it isn't fixed soon.** | cfo.ai's data warehouse refused the data. Orange dot. | Contact cfo.ai support. |
| **Sync failed**, with the source's own reason or **The last sync couldn't finish.** | cfo.ai could not classify the failure. Red triangle. | **Retry**, then **Investigate with Ari**, which opens a chat that asks Ari to find the cause. |

When several causes apply at once, cfo.ai's own failure is the one shown, because no other fix helps until it is repaired. Other statuses say what to do the same way: **Connection failed** with **Retry to set it up again.**, **Setup not finished** with **Syncing won't begin until setup is finished.** and a **Cancel setup** action on the hover card that removes the unfinished connection, **No queries yet** with **Data synced. No queries saved yet.** and **Set up queries with Ari** for people who can edit the connection, and **No data found** with **Investigate with Ari**.

When a nightly sync of a connection you made from the connection manager fails right after a successful one, cfo.ai starts one background Ari task for the person who connected the source. The task acts for that person, with that person's permissions: Ari checks the connection, repairs what its tools can repair, such as an API source's saved sync setup after the source changed its response layout, and can hand the connection to a background ingestion worker that rewrites a saved query the new layout broke. The source counts as restored only when its saved queries return values again for the records they returned before; a sync that completes while a query column that held values now holds none is still a stopped source. Ari then sends that person one message, by email or Slack direct message, that says when the source last synced successfully, what Ari changed, and the one step that is theirs when there is one, such as signing in at the provider. A source that keeps failing starts no further task.

A sync from a connected source finishes even when one of its tables fails. The other tables load, the saved queries over them refresh, and the failed table is read again on the next sync, so one bad table no longer stops the whole source. The connection then reads **Partly synced** in place of **Synced**, with a steady orange dot on its sidebar row and a line such as **Stripe's last sync couldn't refresh balance transactions. Everything else is up to date, and cfo.ai will try again on the next sync.** The line names up to three tables and counts the rest. No action is offered, because the next sync retries the missing tables; Ari's connection readiness names the same tables. A Stripe connection redoes only the tables that failed, while its other tables keep syncing from Stripe's change events. A failure that affects the whole connection, such as a refused sign-in or a provider rate limit, still fails the sync as before.

A NetSuite connection also checks, before every sync, that NetSuite still shares the tables the financial statements need, and reads **Missing access in NetSuite SuiteAnalytics** when one is hidden. See [NetSuite table access](/integrations/integrations-directory#accounting-and-erp).

## Connections for external tools

An integration imports business data into cfo.ai. A connected external MCP server or API gives Ari access to another service's tools. The cfo.ai MCP server does the opposite: it lets an outside AI client use cfo.ai's tools.

These are separate connection types with different setup and access controls.

An MCP server that signed in with OAuth reads **Needs attention** with **Reconnect this source to continue.** when its saved sign-in has no usable token, in **Settings → Connections** and when Ari reads the connection; it no longer reads **Ready for Ari**. Before a turn first lists a server's tools, cfo.ai renews a sign-in it knows has expired. When your MCP connection settings cannot be read as a turn starts, Ari's connected MCP tools do not run in that turn and Ari says so; the next turn reads the settings again.
