When you ask Ari to build or reshape a Table Block (see [Build and format a Table Block](/dashboards/build-and-format-tables)), Ari sends the table's `rows` and `columns` as a typed list: each entry names one Variable, one Dimension, the Date axis at a grain, a blank row, or a fork into side-by-side branches, and a Variable entry can carry its own breakdown of Dimension levels. The same shapes have a compact written form called a **breakdown**, which Ari reads in its modeling reference and which the product uses internally. You don't need to write either form yourself, but knowing the shapes helps you describe what you want precisely.

## The basic forms

- **One Dimension**: `[Department]` splits a row's values across every Department.
- **A name with spaces**: ``[`Spend Type`]`` — backticks quote a Dimension name that is not a single word.
- **Nested segmentation**: `[Department, Level]` splits by Department, then splits each Department further by Level.
- **Side-by-side split**: `[Department, {Level, Owner}]` splits by Department, then forks into two parallel breakdowns — one by Level, one by Owner — under each Department. Each path from the top of a breakdown to its end can fork once.
- **A branch condition**: `[Department, {Level[Department = "Engineering"], Owner}]` routes the Level breakdown under Engineering specifically, while Owner applies more broadly. A branch condition names one item of an earlier Dimension on the same path; a condition over several items is not accepted yet.
- **Filtering to specific items**: `[Region in {East, West}]` keeps only the named items instead of showing every item in the Dimension. Only a list of items to keep works here; ranges, exclusions, and `where` conditions are not accepted yet.
- **A date grain**: `[Date.Month]` buckets a date Dimension at a chosen grain — Day, Week, Month, Quarter, Half, or Year. A table has one Date axis.

## Variables vs. Dimensions as rows

Each row in a table's view is either:

- A **Variable**, which measures something (Revenue, Headcount, Gross Margin), or
- A **Dimension used as a mapping**, where each cell shows that Dimension's item for its row and column instead of a number — useful for a database-style list of entities and their attributes.

A Variable row can carry its own breakdown, splitting just that one row differently from the rest of the table. A mapping row takes no breakdown.

## Orientation

A view with a measured Variable keeps values on rows and its Dimensions, including time, on columns. A mapping-only view already reads down the rows: source keys on rows and their mapped attributes across the columns. There is no separate transpose action; to flip a table, ask Ari to reshape it by moving the Variables between rows and columns. Moving an axis changes the presentation, not the grain of any cell.

## When a table comes back empty

An empty result on a table with dates often means the table's **window**, the date range and grain it is set to show, does not cover the dates that hold values: writing dated values does not move the window, and a wrong window is fixed on the table itself. Two other causes are common: a member whose cells are all empty is hidden when the table hides empty members, and a member outside a formula's condition reads empty. Ask Ari to check the table's window before reworking its breakdown.
