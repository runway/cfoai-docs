---
title: "Aggregation functions"
description: "Use sum, product, average, count, min, max, median, first, last, stdev, and var to combine selected Model values."
---

Aggregation functions combine several selected values into one result.

## sum and product

`sum` adds selected numeric values. `product` multiplies them. `sum` always returns a number: empty values contribute nothing, and a sum with no values at all, such as a total over an empty group, returns 0 rather than an empty value.

```text
sum(Revenue[Department in any])
product(`Growth Factor`[Date.Month in any])
```

Both functions accept one to 10 expressions.

## average

Returns the arithmetic mean, or null when no values exist.

```text
average(Revenue[Department in any])
```

`average` is the preferred spelling. Existing formulas using `avg` remain supported.

## min and max

Return the smallest or largest value, or null when no values exist.

```text
min(Revenue[Department in any])
max(Revenue[Department in any])
```

Over a Variable that holds dates, a single-argument `min` or `max` returns the earliest or latest date, so ``max(`Observed On`[Employee in any])`` gives the newest observation. When a group mixes numbers and dates, the numbers decide. With several arguments, `min` and `max` compare numbers only.

## count

Counts non-empty values of any type. It behaves like Excel `COUNTA`, not Excel `COUNT`.

```text
count(Orders[Department in any])
```

## first and last

Return the first or last value in the selected series order, or null when the series is empty. Over an imported record's rows, `first` and `last` order the rows by the source's preferred time column. `last` returns the value of the row with the latest date there, and rows on one date keep their source order.

A rule that references the imported source column itself, rather than the Variable loaded from it, with no aggregation function around the reference, reads it as `last`: the row with the latest date by the preferred time column, or the last row in source order when the source has no date column. That is the same row an imported Dimension's generated default picks. A Variable loaded from the source keeps its own aggregation, so an amount column that loaded as a summed Variable still sums when a formula names the Variable. Wrap a column reference in `first(...)`, `sum(...)`, or another aggregation to choose a different one.

```text
first(Revenue[Date.Month in any])
last(Revenue[Date.Month in any])
```

Both functions also take several arguments, when every argument is a direct source column or a direct reference to a Variable or Dimension, with no arithmetic around it. The result comes from the one input whose row is latest for `last` or earliest for `first`: a source column is dated by its source's preferred time column, and a Variable or Dimension by the dates of its own cells. Each input keeps its own filters and skips empty values, so a combined `` last(`Vendor A`, `Vendor B`) `` filtered to one Entity shows that Entity's latest vendor. A dated input always beats an undated one. When two inputs tie on the date, `last` takes the later argument and `first` the earlier one. This is how cfo.ai reads a Dimension combined from several accounting sources; see [Share one Dimension across accounting sources](/formulas/core-concepts/dimension-mappings#share-one-dimension-across-accounting-sources).

## median

Returns the middle numeric value when the selection has an odd number of values. When the count is even, it returns the average of the two middle values. It returns null when no values exist.

```text
median(`Annual Salary`[Employee in any])
```

`median` accepts one expression.

## stdev and var

`stdev` returns sample standard deviation. `var` returns sample variance. Both use the sample calculation with one degree of freedom and return null when fewer than two values are present.

```text
stdev(Revenue[Region in any])
var(Revenue[Region in any])
```

Both functions accept one to 10 expressions. Existing formulas using `stddev` or `variance` remain supported, but `stdev` and `var` are preferred.

## Combine multiple expressions

`sum`, `product`, `average`, `count`, `min`, `max`, `stdev`, and `var` can combine up to 10 expressions, and `first` and `last` combine any number of direct source columns or direct Variable or Dimension references, as described above:

```text
sum(Revenue[Region in any], `Other Income`[Region in any])
```

`average` pools the underlying values rather than averaging the average of each expression.
