Skills and Triggers let Ari repeat work, so you explain a job once instead of every month, and the work happens on time even when you are not there. A **Skill** tells Ari how to do a job. A **Trigger** tells Ari when to do it. A **Guide** shows a person around the work, one step at a time.

Take a month-end review. A Skill holds your steps: compare Actuals with Forecast for the closed month, flag any line more than 10% off, and write the summary in your usual format. A Trigger runs the review on the fifth of each month and emails you the summary. A Guide walks your board through the variance Page before the meeting.

## How Ari picks a Skill

A Skill has a name, a description, and instructions. On every request, Ari sees the name and description of each Skill it has: the built-in Skills, the workspace's shared Skills, and your own Skills that apply in this workspace. When a request matches a description, Ari reads that Skill's instructions and follows them. Nobody has to name the Skill. That is why a description works best when it is written as "Use when…": it is what Ari matches against.

Skills come in three kinds:

- Built-in Skills come with cfo.ai, which keeps them up to date. Nobody can edit them. Most are always on; seven optional ones, **Entity consolidation**, **Model audit**, **Flash report**, **Investor review**, **Model migration tie-out**, **Source tie-out**, and **Workbook template fill**, stay off until someone in the workspace turns them on. A Trigger of yours that names an optional built-in in its instructions also gives that Skill to its runs and to your own chats in that workspace, while the Trigger is on or one of its runs is in progress, with the switch still off; see [Turn on a built-in Skill](/guides/turn-on-built-in-skills#a-trigger-that-names-a-built-in-skill).
- Your own Skills belong to you, the person who saved them. Ari follows them whenever it works for you, in every workspace where you are a member, so a fractional CFO who saves a close review once has it in every client's workspace. Other people in a workspace have their own Skills, and yours do not change their chats unless you ask Ari to give them a copy. A Skill of yours cannot take a built-in Skill's name, and when cfo.ai later ships an optional built-in under a name you already use, the built-in wins only in a workspace that turns it on; see [Update or remove a Skill](/guides/save-a-skill#update-or-remove-a-skill).

- Workspace Skills belong to one workspace: an administrator made one of their own Skills available to everyone there, and every member's Ari follows it. Any administrator can edit or delete it. When you have a personal Skill with the same name, Ari follows yours in that workspace; see [Make a Skill available to everyone in a workspace](/guides/save-a-skill#make-a-skill-available-to-everyone-in-a-workspace).

A Skill of your own can also be limited to one workspace, for a procedure built on one company's own accounts, systems, people, or figures. Ari follows a limited Skill only in that workspace. When you ask Ari to save a Skill that names one company's own setup, it limits the Skill to that company's workspace and tells you so.

A new or changed Skill reaches a new chat at once, and a chat already open within a message or two. A Skill holds a process. A fact that everyone at a company should share, such as how the company defines bookings, belongs in workspace memory instead, which applies to every administrator's chats in the workspace; see [What Ari remembers](/concepts/ari-memory).

## How a Trigger runs with nobody watching

A Trigger is a saved request with a schedule that runs on the Trigger's own time zone, or with one date and time for a job that runs once, such as a reminder; see [Schedule a report or a reminder with a Trigger](/guides/schedule-a-trigger). At each scheduled time, cfo.ai starts a new chat for the run and Ari works through the saved instructions, with the access of the person who set up the Trigger. The saved instructions are the authorization for the run.

A run starts with no Page open and works in Main, unless the instructions name another Scenario. It works on exactly what the instructions name. If a connection the instructions name was removed, the run reports that instead of using another connection. If a Page or a table they name was removed, or was renamed and the instructions name it in plain words, the run does not read something that looks similar in its place. When one replacement clearly serves the same request, the run can change the Trigger's instructions to name it, which is a fix you can undo; see [When a run fixes a problem or needs your decision](#when-a-run-fixes-a-problem-or-needs-your-decision). When no replacement is clear, the run delivers the parts the missing Page or table does not affect and reports what is missing.

A reference written the way Ari writes one follows a rename. Ari writes a table, a Page, a Variable, or a saved query as its name, `#`, and the start of its id, such as `Bills#72f`. Each time the instructions are saved, by Ari or on the Triggers page, cfo.ai records which object each such reference names. A run then reads the reference as that object under its current name. So if you rename the Bills table to Payables, the Trigger keeps reading that table, and a new Variable named Bills does not take its place. If the recorded object was deleted, or the Trigger's owner can no longer read it, the run is told that the reference names nothing it can read, and nothing else is put in its place. When a reference could mean more than one object at the time you save, cfo.ai records none for it, and each run is told the reference was left as written. A Trigger saved before cfo.ai kept these records gets them the next time its instructions are saved.

When a connection is removed, cfo.ai also pauses every Trigger whose instructions refer to it the way Ari writes a connection, so the Trigger does not fail run after run; a Trigger that names a removed connection the way Ari writes it, but escaped that pause, pauses on its first run that is refused there. The Triggers page keeps the reason. [Schedule a report or a reminder with a Trigger](/guides/schedule-a-trigger#if-something-goes-wrong) has the exact rule and how to resume the Trigger.

Nobody reads the chat while a run works, so nobody can answer it. When Ari would ask you a question, it makes a reasonable assumption, keeps going, and states the assumption in its result. Its questions, plans, and buttons stay in the chat for you to read later. Answering one later starts a new turn in that chat; it does not change what the run already did. That turn is an ordinary chat turn, so Ari can ask you to approve a call in it.

## What a run cannot do on its own

A run never waits for a person, so anything that needs a person's approval stops short:

- A Scenario merge or deletion that the run prepares waits in its chat until someone presses the confirmation button.
- A run does not delete imported data your Model still uses. A Variable or Dimension that a saved query loads stays while a formula, table, chart, Canvas block, setting, or hand-added item reads it, or while it holds a formula of yours, even when the instructions say to delete it, its table, or its Page. The run reports what it kept. To remove it, ask Ari in a chat and confirm the list it shows; see [Saved queries](/reference/imported-data#saved-queries).
- An email to anyone but you waits as a preview in the chat until someone presses **Send**.
- A run reports to you in cfo.ai, as a message in the chat you created the Trigger from, or in your most recent chat in the workspace when that chat is gone; with no chat of yours in the workspace, nothing is posted and the run's record says so. It can email you or message you in Slack only when its instructions name that channel, apart from a decision the Trigger waits on, which cfo.ai sends you in a Slack direct message; see [When a run fixes a problem or needs your decision](#when-a-run-fixes-a-problem-or-needs-your-decision). It can message nobody else. The one exception is a Trigger a workspace administrator points at a Slack channel Ari is in, private or public: its runs post the result there, and everyone who can read the channel reads what the administrator could read. The run sends nothing on its own; the message is part of the saved task, so the instructions must still say what to send.
- A tool of an MCP server, or an endpoint of a connected API, set to **Ask first** does not run. No approval card appears in the run's chat, and Ari is told that the call did not run and that no approval request was created. Set the tool or endpoint to **Allow** before a Trigger needs it; see [Choose what Ari may do](/guides/give-ari-another-service#choose-what-ari-may-do).

A Trigger does one run at a time. When a run is still going at the next scheduled time, that time is skipped. A paused Trigger does not catch up: when you turn a recurring Trigger back on, it waits for its next scheduled time. Runs use AI usage like any chat with Ari; see [Plans, AI usage, and connection slots](/concepts/plans-and-usage).

## When a run fixes a problem or needs your decision

Why did a Trigger change its own instructions, or message you in Slack when its instructions never mention Slack? A run that meets the same problem every time does one of two things, and which one depends on whether the fix can be undone.

A run can make a fix that can be undone, in the same run. Two kinds of fix count: a change to the Trigger's own saved instructions, and an edit to your Model that version history can undo. Take a Trigger whose instructions ask for a column that its source stopped sending, so every run delivers with a gap. A run can change the instructions so that later runs deliver the whole result. Ari then tells you once what it changed and how to undo it. cfo.ai keeps the instructions a Trigger had before its latest change, whoever made that change, so the undo is to ask Ari to put the earlier instructions back. It keeps one earlier version. An edit to your Model is undone from version history, like any other change.

A choice only you can make stays yours: a change the instructions forbid, or one that cannot be undone. The run keeps doing the work it is allowed to do and records the choice as the decision the Trigger waits on. cfo.ai sends you that decision once, in a Slack direct message. When Slack has no way to reach you, for example because the workspace has no Slack connection or Slack has no account under your cfo.ai email, the message is posted in your cfo.ai chat instead. The Slack message goes to you alone, never to a Slack channel the Trigger posts in, and cfo.ai sends it even when the instructions name no Slack delivery. When the message cannot be delivered either way, for example because Slack cannot reach you and you have no chat in the workspace, the Trigger does not start waiting, and the next run that needs the decision sends it.

A later run that reports the same decision in the same words sends nothing more. A later run that reads **Delivered with gaps** or **Did not complete** starts its reason with the date the Trigger began waiting, so the Trigger's history shows how long the decision has been open. A run that reports a different decision, or the same one in new words, sends that one, and it replaces the first; a Trigger waits on one decision at a time. Each run judges the problem again, so a later run can settle it with a fix that can be undone instead of repeating the decision. When a run does not need the decision anymore, it leaves it out of its report, and the Trigger stops waiting. To answer a decision or undo a fix, see [Schedule a Trigger](/guides/schedule-a-trigger#answer-a-decision-a-trigger-waits-on).

## The record each run keeps

Each run's chat is its record, listed in the Trigger's history. A run ends by reporting its outcome: the saved task was done, it was not done, with the run's own sentence for why, or the run ended without reporting either. A result delivered with a part missing, such as a source the run could not read, is **Delivered with gaps**: it counts as a delivery, and the run's own sentence says what was missing, but the next run still catches up from the last run that delivered everything, so the missed work stays in scope. A Trigger that refreshes a connection succeeds only when the import that run started finishes. When three runs in a row deliver nothing and none of them reached you with a message, cfo.ai pauses the Trigger and tells you in your most recent chat; see [Schedule a Trigger](/guides/schedule-a-trigger#if-something-goes-wrong). When three runs in a row deliver with gaps and none of them reached you, cfo.ai keeps the Trigger running and tells you once, in your most recent chat and nowhere else; with no chat of yours in the workspace, the notice waits until you have one. The same section describes that notice.

Each run's report stays in the run's record, not in Ari's memory. Memory holds only what a person states in a message or in a document they give Ari to remember, and no person's message starts a run, so a run cannot save a memory. A figure that later runs must compare against, such as last week's ending cash, belongs on a Page or in a table that the instructions name. When you reply in a run's chat, Ari can save what you state there, as in any chat. You can still ask Ari about earlier runs in any chat, such as "What did my cash Trigger find last month?": Ari reads the summary of the run you ask about from the Trigger's history. The next run reads the last run's record: what it found, how long that has held, what it already told you, and the decision the Trigger waits on, if any. A report the instructions ask for every time goes out every time. A warning goes out when something changes, so the same warning does not repeat on every run.

## Guides show people around

A Guide is a saved walkthrough that spotlights parts of the workspace, such as a Page, a block, or one cell, with a short note at each stop. A Guide can be a step-by-step tour, a walkthrough of an analysis, or a single explanation. Ari builds Guides from your description, and they are saved in the workspace for everyone. People start a saved Guide by asking Ari for it, or with the **Start tour** or **Start walkthrough** button Ari posts in the chat. A button in a Canvas block, or **Take the tour** on an invitation, can also start one. Saved Guides are not listed in the Help center. See [Walk someone through a Page with a Guide](/guides/create-a-guide).

## Choosing between them

| You want | Use |
| --- | --- |
| Ari to follow your steps whenever a certain job comes up | A Skill |
| A job done on a schedule, without asking | A Trigger |
| A job done once at a set time, such as a reminder | A Trigger that runs once |
| Your steps followed on a schedule | A Skill for the steps, and a Trigger that asks for the job |
| A teammate or your board shown around a Page | A Guide |
| Ari to remember a fact or a preference | Memory; see [What Ari remembers](/concepts/ari-memory) |
