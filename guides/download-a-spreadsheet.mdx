To export a Page to Excel, select **Share** in the Page header, open the **Export** tab, and choose **With formulas**, or ask Ari to export it. You get an Excel workbook (`.xlsx`) with one sheet for each table on the Page, and its numbers are live Excel formulas, not pasted values. When you want the numbers without the formulas, or a large Model takes too long to export, [export values only](#export-values-only). A Page whose figures are drawn by Canvas blocks exports too: each dataset a Canvas block draws becomes a sheet of values. Text on the Page is written to a **Cover** sheet, and a chart block becomes an Excel chart when the export can draw its kind; see [What you get](#what-you-get). To put several Pages in one workbook, such as your three financial statements, ask Ari.

## Are the formulas live?

Yes, in a **With formulas** export, which is also what Ari exports unless you ask for values only. Each number a formula calculates in cfo.ai is an Excel formula in the workbook. The numbers those formulas read from outside the Page, such as typed assumptions and imported Actuals on other tables, sit on a **Model inputs** sheet. Change an input in Excel and every cell that depends on it recalculates. A formula that chooses among several inputs with `first` or `last`, such as `` first(`Preferred start`, `Fallback start`) ``, stays live too: Excel chooses again when you change an input.

The workbook is a copy. Changes you make in Excel do not flow back into cfo.ai.

Formulas and the **Model inputs** sheet need your own access to everything the Page shows. Someone who reads the Page's data only because the Page shows it, such as a person who opens the Page through a share link, is not offered **With formulas**. They get the numbers the Page shows them as plain values, with no **Model inputs** sheet; see [What a share-link reader can download](#what-a-share-link-reader-can-download).

A few formulas cannot be written as Excel formulas, such as one longer than Excel allows. Those cells keep their calculated value instead of a formula, and an **Export notes** sheet lists each one. Each such cell holds the value cfo.ai calculated when the export ran, so the value is not wrong; it stays fixed when you change an input in Excel. A formula that names items of a numeric Dimension as text, such as deal IDs, finds their cells by number, and a formula that names an item the workbook has no cell for keeps its calculated value and is listed in **Export notes** rather than being written without that item. A cell that reads text or dates, such as a cost center or an end date, from several periods or Dimension items also keeps its calculated value and is listed, because an Excel formula cannot preserve text or dates read from several cells; a text or date read that matches one cell stays a reference to that cell. The download notice counts them and offers **Ask Ari to fix**, which asks Ari to repair the file you downloaded: Ari writes a working formula into each of those cells and keeps everything else in the file as it is.

## Export values only

To export a Page's numbers without its formulas, select **Share**, then **Export**, and choose **Values only**, or ask Ari to export the Page as values only. Use it when you want fixed numbers to send, or when a **With formulas** export of a large Model fails or takes too long.

A values-only workbook has the same sheets for the Page's text, tables, chart blocks, and Canvas data, with these differences:

- Each cell a Model formula calculates holds the calculated value, not an Excel formula, so the numbers do not update when you change an input in Excel.
- Subtotal and comparison columns stay Excel formulas, because they read only cells the sheet shows, and recalculate from those values.
- There is no **Model inputs** sheet.
- An **Export notes** sheet says that the workbook holds values; [The cfo.ai interface](/reference/interface#download-spreadsheet) has its wording.

A values-only export does not calculate the inputs that formulas read from outside the Page, which a **With formulas** export needs for the **Model inputs** sheet, so it does less work on a large Model. It still calculates the Page's own tables.

When a **With formulas** export fails, its **Could not download spreadsheet** notice offers **Download values only**, which starts a values-only export of the same Page. cfo.ai does not make that switch for you.

## What a share-link reader can download

A reader who opened a Page through a share link can download it as a values-only workbook, and only while the Page still shows them what the file holds. In a desktop browser, the reader selects **Download spreadsheet**, the download icon in the Page header, and then **Values only**, the one format offered.

The workbook holds what the Page shows that reader: each table as it was saved, with its saved filters, and each Canvas dataset as the Page loads it, or only the periods a Canvas block showed the reader when the block reports them; see [What you get](#what-you-get). It is the same as a [values-only export](#export-values-only), and its **Export notes** sheet says that it holds values. The export runs in the background like any other, and the reader's own exports are listed under **Recent exports**.

If you change the Page after the reader's file was made, such as by narrowing a table's filter, that file can no longer be downloaded. Its row under **Recent exports** reads **Out of date** with the reason, and the reader downloads again for a file of the Page as it is now. When the Page changes while the file is being made, cfo.ai makes the file once more by itself. What puts a file out of date, and each message, is in [A share-link reader's file](/reference/interface#a-share-link-readers-file).

## When an export leaves Pages or formulas out

An export calculates the selected Pages one at a time, each Page's tables and then the inputs those tables read. It has no fixed time limit and keeps running while it makes progress. An export that reaches its allowance of calculated cells or calculation requests, listed in [Limits and file types](/reference/limits#tables-pages-sharing-and-exports), stops calculating and writes the Pages it has. The workbook then holds every Page whose tables finished, and its **Export notes** sheet names the Pages left out. On a Page that is in the workbook, a cell that reads an input the export did not reach keeps its calculated value and is listed in **Export notes**. When the first Page with a table did not finish, there is nothing to write, and the export fails at the allowance; a new export of the same Pages reaches the same allowance while the Model is unchanged, so export fewer Pages or narrow the tables. An export of one Page, such as one from the Page's **Export** tab, never leaves a Page out: it finishes or fails. Ari's export reports the Pages left out too, and the table that was still calculating when the allowance ran out.

An input the calculation engine stops at its time or memory limit is handled the same way: the export asks for a large group of items once more in halves, and when the engine still stops it, the cells that read it keep their calculated values and are listed in **Export notes**. When the Page's tables and their inputs together pass the workbook's size limit, the export writes the workbook once more without the **Model inputs** sheet: the tables keep the formulas that refer to each other, and a cell that reads an input keeps its calculated value and is listed.

A table whose formulas cannot be worked out within the time limit for one table calculation is written as values instead of failing the export. **Export notes** names each such table at the top, and the table's own sheet carries a subtitle that says its numbers are fixed; subtotal and comparison columns on it still recalculate from those numbers, the other tables keep their formulas, and Ari is told which tables were written as values. The messages are listed in [The cfo.ai interface](/reference/interface#download-spreadsheet).

An input too large to read is left out, and the cells that read it keep their calculated values; **Export notes** says the workbook may hold only some cells of that Variable. A total over such an input, such as a sum across every region, also keeps its calculated value, so no formula in the workbook adds up only part of the data. A Page's own table that large fails the export. A workbook that has no room left to name the Pages it leaves out fails instead of looking complete. The sizes are in [Limits and file types](/reference/limits#tables-pages-sharing-and-exports).

## What you get

- One worksheet for each table on the Page, in the Scenario you exported. A table's Scenario comparison columns come along, and rows and columns hidden on the table are left out.
- A table set to always show one Scenario or Snapshot exports that Scenario's or Snapshot's numbers, whichever Scenario you exported, and its worksheet names it under the sheet title. Wherever the workbook writes formulas, the table's formulas are the chosen Scenario's or Snapshot's, and the inputs they read on the **Model inputs** sheet are its inputs too. When you cannot open the chosen Scenario or Snapshot, the workbook leaves the table out, as the Page shows you no values for it. See [A table that always shows one Scenario](/reference/table-blocks#a-table-that-always-shows-one-scenario).
- Each date column is headed by its period, whatever **Date format** the table uses: a month by its year and month, such as `2027-01`; a day by its date and a week by the day it starts, such as `2027-01-04`; a quarter or half-year by its first month; and a full-year column by its year, such as `2027`. The same headings appear on the **Model inputs** sheet.
- One worksheet for each dataset a Canvas block on the Page draws, after the table sheets. It holds the whole dataset, including rows the block reads but does not draw, as plain values with no formulas; no formula reads these sheets, and they add nothing to the **Model inputs** sheet. One case holds less: a block with a period picker that Ari built to report the periods it shows. Its sheet then holds only the columns of the periods the block showed when you chose the format, plus any column that has no period; every row is still written. A block reports its periods only when its code does, so ask Ari to make the block's download follow its period picker. A block that reports none exports every period its dataset was saved with, and so does an export you ask Ari for. The sheet is named for the block's title, with the dataset's name added as **[title] · [dataset]** when the block draws more than one dataset. When that name is longer than the 31 characters Excel allows, the title is shortened, or left out when the dataset's name leaves it no room, and the dataset's name is kept. A dataset name that is itself longer than 31 characters is cut at its end to fit. The sheet's rows and columns follow the dataset's layout. When Ari builds a dataset with its periods ahead of its Variables, the sheet lists every Variable for the first period, then every Variable for the next, such as Actual and Budget for January and then for February. Otherwise each Variable's periods stay together. Ask Ari for that order when you want each month's figures side by side. A dataset saved for another Scenario names that Scenario under the sheet title, and its Variable column headings use the names that Scenario gives the Variables. You get the datasets the Page shows you: a dataset in a Scenario you cannot open is left out, and so is one whose saved query the Model refuses to calculate.
- A **Cover** sheet, the first sheet, when the Page has text. It holds the Page's name as the title. The next line holds the Scenario's name, with your brand's name before it when the workspace has a brand. The Page's text follows in Page order, including its Text blocks. Headings, bulleted, numbered, and check lists, and tables typed into the text keep their shape. A mention of another Page shows that Page's current name, and a mention of a number shows the label it had when it was written; a mention of a Page or number you cannot open shows **[page]** or **[number]**. In a workbook of several Pages, each Page's text follows a heading with that Page's name. A Page with no text has no **Cover** sheet.
- One worksheet for each chart block on the Page, a chart from an earlier version of cfo.ai, after the table sheets. It holds the chart's data as values, with an Excel chart drawn from those cells. Line, bar, area, stacked, combo, pie, and doughnut charts are drawn, with the legend, axis titles, hidden axes, and gridlines the Page shows. A waterfall or Nightingale chart, a chart that compares Scenarios, a stacked chart that stacks each of several Variables on its own, a chart with no data, and a chart past Excel's limit of 255 series are left out with their data. **Export notes** names each chart left out and the reason, and Ari's export reports up to 100 of them; the wording is in [The cfo.ai interface](/reference/interface#download-spreadsheet). A Page whose only chart blocks are left out still exports, so you can read why.
- A Canvas block's drawing is not exported: a chart Ari built in a Canvas block becomes its sheets of values, not an Excel chart.
- A row that has its own name on the table, set with **Rename on this table**, takes that name on the table's worksheet. Formulas and the **Model inputs** sheet keep the Variable's name.
- A table with **Subtotals below details** keeps that layout: each expanded group becomes a heading row with its name and no values, then its detail rows, then a row labeled **Total [name]** that holds the group's formulas; a name that already starts with "Total" keeps its name. See [Put subtotals below their details](/guides/format-a-table#put-subtotals-below-their-details).
- A total that adds three or more cells next to each other in one row or column is written as a range, such as `=SUM(B5:B7)`. When blank rows sit between the details and their total in the same column, the range runs through those blank rows, so a row you insert above them in Excel is added to the total.
- A formula that reads a single-cell input on another sheet reads it by name, such as `Tax_Rate`, instead of by a cell address, so you can tell what the formula reads without opening the other sheet. A cell gets an Excel name when its Variable has no Dimensions, shows in exactly one cell of the workbook's table sheets, on a table with no breakdowns, and holds a number or a date that is typed in or comes from a formula that reads no other Variable and no imported data. The name is the Variable's name with each run of characters other than unaccented letters and digits turned into an underscore, so `Tax Rate` becomes `Tax_Rate`. A name that starts with a digit, or that Excel would read as a cell address or as TRUE or FALSE, gets `Input_` in front, so `Q1` becomes `Input_Q1`. A second Variable that would get the same name gets `_2` at its end. The workbook defines a name only when a formula on another sheet uses it. Inputs on the **Model inputs** sheet are not named, and a values-only workbook has no names.
- Each worksheet is laid out to read and print. A column with no width set on the table widens to fit its content, up to a width of 48 characters, or 64 for the first column; a width you set on the table is kept. Text is left-aligned. A row that totals the rows grouped under it has a thin line above it and a double line below it. Each sheet prints in landscape, with its print area set and its frozen heading rows repeated on every printed page.
- A date cell stays a real Excel date, shown in the day form of the **Date format** chosen on the table: **Abbreviated** as `Sep-30-26`, **ISO standard** as `2026-09-30`, **Full month** as `September 30, 2026`, **Compressed year** as `Sep 30 ’26`, **Year-first slash** as `2026/09/30`, **Month-first slash** as `09/30/2026`, **Period-separated** as `2026.09.30`, **Day-first formal** as `30-Sep-2026`, and **Descriptive** as `30-Sep-26`. A table that never had a **Date format** chosen shows **Abbreviated** on the Page but exports its date cells as `2026-09-30`. The formats are listed in [Date formats](/reference/table-blocks#date-formats).
- Each number keeps its format: currency, percentage, or a multiple such as `3.5x`, with up to five decimal places. A table shown in thousands, millions, or billions keeps that **Scale** in the workbook, with the suffix `K`, `M`, or `B`; percentages and multiples are never scaled. A negative number shows as the Page shows it: with a minus sign, or in parentheses where the table or the workspace chose **Negatives** → **Parentheses** (see [Format and arrange a table](/guides/format-a-table#show-negative-numbers-in-parentheses)). Excel picks the parentheses by the exact value, so a negative that rounds to zero exports as `(0.00)` where the Page shows `0.00`.
- Colors that the Page gives numbers by rule are not exported: the red and green of **Color by sign** and the blue of typed values. Numbers keep their format and sign.
- A table with an [item filter](/reference/table-blocks#item-filter) exports the values it shows under that filter.
- A blank input stays blank rather than becoming 0, and an input that holds text, such as a customer name, stays text. A function of a blank, such as `round`, `abs`, or `year` of an empty cell, is written so that Excel also shows blank after it recalculates, instead of 0 or 1900, and an average or median skips those blanks as cfo.ai does. A test of whether two numbers or dates are equal (`=`) or different (`<>`) also gives cfo.ai's answer when one side is blank: a blank equals only another blank.
- In a workspace with a brand, the filled row at the top of each worksheet that holds the table's title in white takes the brand's text color as its fill, and the first three Dimension colors take the brand's chart colors when it has them. See [Brand your workspace](/guides/brand-your-workspace).

## Fill your own Excel template

To get your Model's numbers in your own Excel layout, such as an investor report template, attach the workbook to a chat and ask Ari to fill it. A Page export cannot start from your workbook; it writes one sheet for each table. With the optional **Workbook template fill** Skill turned on, Ari fills a copy that keeps your workbook's design and formulas, saves which cell gets which figure, and can fill it again every month; see [Turn on a built-in Skill](/guides/turn-on-built-in-skills).

## Other formats

- For Google Sheets, upload the workbook to Google Drive and open it with Google Sheets.
- For a CSV file, ask Ari for a CSV of a table, and it gives you the file in the chat. There is no CSV button.
- For a PDF, see [Get a PDF report or slide deck](/guides/get-a-pdf-or-slides).

## If something goes wrong

A failed export shows **Could not download spreadsheet** with the Page's name and the reason. When a **With formulas** export ran and then failed, the message also offers **Download values only**; see [Export values only](#export-values-only). An export that was cancelled, or refused before it started, does not offer it. When the reason says an edit did not save, or that another change is still being saved, no export started: check the edit, wait a minute, and download again. When the reason names a table and Excel's worksheet limits, the table's saved layout is too large for one worksheet; narrow the table, or hide rows or columns, before exporting again. Every progress label and message is listed in [The cfo.ai interface](/reference/interface#download-spreadsheet). For export time and size limits, see [Limits and file types](/reference/limits#tables-pages-sharing-and-exports).
