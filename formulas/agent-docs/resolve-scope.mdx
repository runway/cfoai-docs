---
title: "Resolve formula scope as an agent"
description: "Derive formula scope from visible table targets or write current supported default, Dimension, segment, and Date conditions."
---

Formula scope determines which Model values a saved rule controls. A visible Table Block target is the preferred authority because the server can derive the actual cell address and formula range.

## Start from the visible target

Inspect the relevant saved table and copy the returned row or column reference into `edit_table_blocks`. Use a row or column for a rule that applies along that axis, or a cell for one exact visible result.

The server derives scope from the target. The caller does not invent Dimension IDs, array positions, or formula-range IDs.

## Model-wide default

The broad default condition is:

```text
[]
```

Use it when the same rule should apply across the Model and no narrower business condition is intended.

## A rule for a Dimension

A rule for every Department item uses:

```text
[Department in any]
```

The unprefixed condition continues to apply when additional Dimensions are present.

## A rule for one segment

Use the readable Dimension and item names returned by inspection:

```text
[Department = "Sales"]
```

```text
[Department = "Sales", Region = "West"]
```

Wrap names with spaces in backticks and use a returned short disambiguator only when needed.

## Time-aware scope

A formula range needs the Model's Date grain. In a monthly Model:

```text
[Department = "Sales", Date.Month in any]
```

For a rule saved on the Variable with no table named, use an `edit_table_blocks` `update` with a `variables` entry and put the rule under `default_formulas.actuals` or `default_formulas.forecast` when it belongs to that formula range.

## Exact versus broader scope

A condition without `$` can continue to match a richer cell address. A condition beginning with `$` matches the exact set of Dimensions it names:

```text
[Department = "Sales"]
$[Department = "Sales"]
```

In a saved table, the exact form is what a cell-level write produces: a `cell_updates` entry on one cell saves an exact-address rule, while a `row_updates` entry saves the row's own relative rule. In an expression, the same `$` marks an absolute reference.

The leading `$` is part of the condition grammar. In an expression, an absolute Variable reference instead places `$` after its name: `Revenue$[Department = "Sales"]`.

Use exact scope only when the user intends that narrower behavior. A rule that omits Date cannot fill dated cells if it matches only its exact Dimension set.
