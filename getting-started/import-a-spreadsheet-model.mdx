If your financial model lives in a spreadsheet, Ari can rebuild it as a native cfo.ai Model with its data, assumptions, formulas, Scenarios, and reports. Ari rebuilds the logic in cfo.ai's structure, so the layout will not match the spreadsheet cell for cell.

Import in passes: rebuild the core model, check that it ties, then add reports and Scenarios. Smaller passes give Ari less to get right at once, and you can check the numbers before you build on them.

## Import in passes

<Steps>
  <Step title="Rebuild the core model">
    Attach the Excel workbook, spreadsheet export, CSV, or PDF to a chat, and be specific about what to build first:

    > Import this workbook into cfo.ai. Make one Page for each tab that holds inputs, data, or calculations. Skip summary, dashboard, and instruction tabs such as "How it works" for now. Build everything in Main, with no other Scenarios yet.

    If your accounting or payroll system is already connected, add:

    > Use our connected [QuickBooks / Rippling] data for actuals instead of rebuilding the actuals tabs.

  </Step>
  <Step title="Check that it ties">
    Turn on the **Model migration tie-out** Skill: open **Settings → Skills**, find it under **Built-in skills**, and turn on its switch. Then ask Ari, with the workbook attached:

    > Does this tie to my workbook? Build the tie-out page.

    Ari builds a Page with a bridge from the workbook's number to cfo.ai's, the differences grouped so you can drill into each, and buttons that hand each decision back to Ari. A rebuilt model can be more correct than the spreadsheet, so a difference is not always a mistake. Building the page does not change the Model; changes happen only when you decide a difference.

    Without the Skill, ask Ari directly:

    > Reconcile the rebuilt revenue, payroll, and cash totals to the attached workbook for every quarter. Explain any difference you cannot resolve.

  </Step>
  <Step title="Add reports and dashboards">
    Once the core ties, rebuild the summary and dashboard tabs you skipped. They usually come out better as cfo.ai Pages than as copies:

    > Rebuild the [Summary / Dashboard] tabs as Pages. Use charts and Canvas blocks where they show the numbers better than a table.

  </Step>
  <Step title="Add Scenarios">
    Add the workbook's alternative cases last, once Main is right:

    > Add the Scenarios from the workbook: [Base, Upside, Downside]. Keep Main as [Base].

    See [Understand Scenarios](/scenarios/understand-scenarios).

  </Step>
</Steps>

To have Ari explain a workbook without building anything, say so:

> Review this workbook and explain how the forecast works. Do not change the Model.

## What Ari looks for

Ari reads the source to understand:

- Which sheets hold inputs, source data, calculations, financial statements, or reports.
- How the sheets depend on each other.
- Which repeated rows, columns, or sheet groups are business Dimensions.
- The time horizon, reporting grain, and Actuals cutoff.
- The assumptions and formulas behind the visible results.
- Alternative cases that should become Scenarios.
- Missing inputs, broken references, or numbers that do not reconcile.

From a workbook with formulas, Ari reads both the formulas and the values. A PDF or values-only export gives less to go on, so Ari labels any logic it had to infer as an assumption.

## What the rebuilt Model contains

- Repeated department, customer, employee, product, or entity sections become shared Dimensions.
- Revenue, payroll, assumptions, balances, and other results become Variables.
- Spreadsheet calculations become cfo.ai formulas.
- Closed history and future planning are separated by Last close and formula ranges.
- Statement and report sheets become Pages with saved Table Blocks.
- Alternative plans become Scenarios when the source and your request support it.

## What to check

- The Actuals cutoff and the first Forecast period.
- The business categories used to segment the Model.
- Imported source totals versus calculated subtotals.
- Scenario names and assumptions.
- Existing workspace content that should stay unchanged.
