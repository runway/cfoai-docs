A connection's status says whether its data is current and whether you must act. An integration or an upload shows one status; an MCP server or an API shows two, **Connection** and **Data sync**, as [Connected](#connected) describes. You see it on the connection's row in the sidebar's **Connections** section, on the card that opens when you point at the row, on the connection's page, and on the source's card in the connection manager. Ari reads the same status when you ask about a connection. To fix a problem step by step, see [Fix a connection that needs attention](/guides/fix-a-connection).

## Sidebar marks

The mark at the right end of a connection's row in the sidebar says whether anything needs you.

| Mark | Meaning |
| --- | --- |
| No mark | The data is in and current (**Synced**), or an MCP server or API is ready (**Connected**). |
| Blinking orange dot | A sync is running (**Syncing**). |
| Steady orange dot | Something is incomplete but usually needs nothing from you: the sync resumes by itself, cfo.ai must fix it, or someone else must act. The one exception is a **Partly synced** connection whose source refused access to a table, which offers **Reconnect**. |
| Red triangle | A problem you must act on. The card names it and offers the fix. |
| Gray dot | Setup was not finished, someone stopped the latest sync, or the source was added but not connected. |

With no connections, the section reads **No connections yet**. The **Connections** section shows one row per app. An app you connected more than once, such as one QuickBooks company per entity, gets a parent row with its connections nested under it, and the parent shows the mark of its most urgent connection. A connection with no name of its own, such as an unfinished setup, is named for its source, and several such connections of one source are numbered in the order they were created: **Stripe**, **Stripe (2)**. Ari uses the same names in its chat notes. Under a parent row, a nested MCP server or API that has only its app's name reads **MCP server** or **API**, with the same number. A group of APIs is named as the connection's own name spells the app, such as **Alpha Vantage**, or, when the connection is named differently or all in lowercase, by the app's name with a capital first letter.

## Statuses

### Synced

The data reached your Model, and the last sync finished. Mark: none. Action: none. The card also shows **Last synced** and **Used in**.

### Connected

An MCP server or an API is ready for Ari to call. Mark: none. Its page and its sidebar card show two statuses: **Connection**, which reads **Connected** while Ari can call its tools or endpoints, and **Data sync**, which reads the state of the sync setups Ari saved for it, such as **Synced**, **Syncing**, **No queries yet**, **No data found**, or **Needs attention**. A working server can therefore read **Connection: Connected** beside **Data sync: Needs attention** when an import failed. A server with no sync setup has no **Last synced** time. When the data sync is failed or blocked, the **Data sync** section offers **Fix with Ari**, which starts a chat about that sync; someone who cannot edit the connection reads **Someone with edit access can fix this sync with Ari.** instead.

### Syncing

A sync is running, or a first sync is queued. Mark: blinking orange dot. The connection's page reads **A sync is running now.** No **Reconnect** or **Retry** is offered while it runs. A connection also reads **Syncing** while one of its saved queries is being saved, whether Ari is saving it or someone is editing its SQL or moving it in the app. Ari waits for that save before it reads the query's columns. A save that ran too long saves nothing, and Ari is told so. While cfo.ai waits on the provider, the line says how long it has waited:

- **Waiting [time] so far for [source]’s first sync to finish.** It may add what the provider last reported, then **If it hasn’t finished by [date and time], this sync stops at its next check after that.** cfo.ai checks every 10 minutes and waits up to 20 hours. For a source that syncs through Fivetran, the provider's report reads **Fivetran reports its first historical sync of the account still running**, or, when the source's API has stopped answering Fivetran for now, **Fivetran rescheduled its first historical sync of the account because the source's API allows no more calls for now; its next attempt is due at [time]**. cfo.ai keeps waiting through a rescheduled first sync and asks Fivetran to run it again once that time has passed.
- **Waiting [time] so far for [source]’s transaction history. At the first check after [date and time], a first sync loads recent transactions if Plaid has them ready; otherwise it stops. Later syncs add older history. Rebuilding all history still requires complete history.** A bank connected through Plaid reads this line in place of the one above while Plaid prepares the account's transactions. The date and time is 20 hours after the wait began. Plaid's last report may follow: **Plaid is still preparing transaction history**, **Plaid has recent transactions ready and is still preparing older history**, **Plaid is still preparing the initial transaction pull**, or **Plaid's transaction update status is unavailable**. A full-history refresh loads nothing until Plaid has the complete history, because it replaces the stored transactions.
- **Waiting [time] so far for cfo.ai’s request allowance at [source] to reset. The allowance for this organization is used up or nearly used up, and the sync resumes on its own when it resets.** It ends the same way. Xero, for example, limits how many requests an app can make each day.
- **Waiting [time] so far for [source] to finish a sync it is still running. cfo.ai loads that sync once it finishes. If [source] still reports it running at the first check after [date and time], this sync stops.** A source that syncs through Fivetran was still running its own sync 45 minutes after cfo.ai asked for one. cfo.ai starts no new sync and checks again about every 10 minutes for up to 20 hours. The data from the last loaded sync stays usable meanwhile.

### Partly synced

The last sync finished without some of the source's tables. The data that arrived is usable, and the missed tables count as stopped until a sync refreshes them; see [When a source stops updating](/concepts/connected-data#when-a-source-stops-updating). Mark: steady orange dot. The line names up to three tables and counts the rest, and it says whose side the cause is on once cfo.ai has read why each table failed:

- Until cfo.ai has read the cause, for a moment after the page opens or for as long as cfo.ai cannot read the connection's sync outcome: **[Source]’s last sync couldn’t refresh [tables]. Everything else is up to date, and cfo.ai will try again on the next sync.** Action: **Reconnect**, as for any connection that needs attention, until the cause replaces this line.
- The source refused this connection's sign-in or permissions for every missed table, such as a QuickBooks account that cannot read **accounts**: **[Source] refused this connection access to [tables], so the last sync didn’t refresh that data. A reconnect with an account that can read it lets the next sync refresh it. Everything else is up to date.** Action: **Reconnect**.
- The source refused some tables and the rest failed for another reason: the refusal sentence, then **A problem on cfo.ai’s or [Source]’s side kept [tables] from refreshing, and cfo.ai will try again on the next sync. Everything else is up to date.** Action: **Reconnect**, which repairs only the refused tables.
- No table was refused: **A problem on cfo.ai’s or [Source]’s side kept the last sync from refreshing [tables]. Reconnecting won’t change it. cfo.ai will try again on the next sync, and everything else is up to date.** Action: none; the next sync retries the missing tables.

A refusal is the source answering a sync request with a sign-in or permission error, such as HTTP 401 or 403, or QuickBooks Online's **Permission Denied**. A rate limit, a timeout, or a failure in cfo.ai's own reader is not a refusal.

### Setup not finished

Someone started connecting the source and did not finish. The setup may have failed, been abandoned, or still be open in someone's tab. Mark: gray dot. Line: **Syncing won’t begin until setup is finished.** Actions: **Finish setup** continues the same connection, and **Cancel setup** removes it without asking, because it holds no data yet. **Send link**, beside **Finish setup** on the connection's page and its hover card, makes a link that continues the same setup for someone else who holds the source's sign-in; its tooltip reads **For someone else with the [source] sign-in**. See [Send a link so someone else can connect a source](/guides/send-a-connect-link).

A source whose setup cannot be resumed, such as Stripe (Direct), offers only **Cancel setup** on the card, with **Setup wasn’t finished. Cancel it and connect [source] again.** On the connection's page, the line says **Remove it** and the button is **Remove connection**. People who cannot manage connections see the line and no button.

### Connection failed

Setup failed before the source linked. Mark: red triangle. Line: the failure's reason, or **Retry to set it up again.** Action: **Retry**.

### cfo.ai lost access

The source revoked cfo.ai's access, for example after a password change or an expired authorization. Mark: red triangle. Line: **Reconnect to start syncing again.** Action: **Reconnect**, then sign in to the same company the connection already holds. **Send link** beside it makes a link for someone else to do that sign-in; see [Send a link so someone else can connect a source](/guides/send-a-connect-link).

The data the connection synced before it lost access stays in your Model. Ari can still read it and answer from it, and it tells you when that data was last synced; new rows arrive only after you select **Reconnect**.

A source that syncs through Fivetran, such as BigQuery, Maxio, Ramp, or Gmail, also shows this status when Fivetran has paused its connector, which Fivetran does on its own after the connector stays broken for a long time. A paused connector runs no sync, so **Retry** is not offered. **Reconnect** opens Fivetran's Connect Card for the same connection, and finishing it resumes the connector. The connection's failure line keeps Fivetran's own report of what the owner must fix, such as **The user cannot access BigQuery tables/project (BigQueryConnectorTask_ACCESS_DENIED)**.

When you return from Fivetran's Connect Card, cfo.ai asks Fivetran to run its setup tests before it counts the connection as reconnected. The page reads **Fivetran connected** and **Fivetran is connected. Returning to cfo.ai...** when they pass. When they still ask for a re-authorization, it reads **Finish setting up [source]** with **Fivetran still needs a few details before cfo.ai can read [source]. Go back to Fivetran to finish setting it up.** and a **Finish setup** button that opens the Connect Card again; the connection keeps **cfo.ai lost access** until the tests pass. A sync you start within 15 minutes of a reconnect runs the tests once more before it asks for another reconnect.

An HR or payroll connection that syncs through Merge, such as Justworks, BambooHR, or Hibob, shows **Reconnect required** when Merge has stopped syncing its account and asks for it to be linked again. The data from the last successful sync stays, and the nightly refresh leaves the connection alone until you select **Reconnect**.

### Missing access in [source]

The source is not sharing some tables the reports need, such as **Missing access in NetSuite SuiteAnalytics**. Mark: red triangle. Line on the card: **[Source] isn’t sharing some tables the reports need. Open the connection for the steps to fix it.** A connection whose saved query fails because it reads one of those hidden tables also shows this status, not **Sync failed**, because another sync cannot help until the access is fixed. The connection's page shows an **Access missing** badge and the steps. For NetSuite they read: **NetSuite isn't sharing some tables cfo.ai needs for your financial statements. Have your NetSuite admin create an access token for the Data Warehouse Integrator role, then reconnect NetSuite with that token. Changing only the role ID won't work. Missing tables: …** Action: fix the access in the source, then **Reconnect**.

### Sync failed

There are two kinds:

- The provider's own sync failed, often for a moment. Mark: steady orange dot. Line: **[Source]’s sync hit an error. cfo.ai will try again on the next scheduled sync.** When the provider gave a reason, its report sits between the two sentences, for example **BigQuery’s sync hit an error. Fivetran reports: Problem with view (BigQueryConnectorTask_VIEW_ERROR): [the view Fivetran could not read]. cfo.ai will try again on the next scheduled sync.** Fivetran's report gives each failing task as its message, its code in parentheses, and its details, which name what failed, such as the view or table; several tasks are separated by semicolons. Ari reads the same report. Action: none, or **Retry** to run it now. When the report names something to fix at the source, fix that first. When Fivetran reports the connector broken by a generic sync failure and nothing else, and its setup tests pass, the nightly refresh starts one ordinary sync on up to two later nights; a success clears the count, and a connector that needs a new sign-in or is paused is not retried this way. When every problem Fivetran reports carries the code `incident_in_snowflake`, the failure is in cfo.ai's own data warehouse, not at your source: the next scheduled sync, or **Retry**, has Fivetran run its setup tests again and syncs when they pass, however many nights it takes, and cfo.ai engineering is notified when that still fails. Ari says the same when you ask about the connection.
- cfo.ai could not tell why the sync failed. Mark: red triangle. Line: the source's own reason, or **The last sync couldn’t finish.** Actions: **Retry** and **Investigate with Ari**. When the reason names a table the source hides, the connection shows [Missing access in [source]](#missing-access-in-source) instead.

### First sync not ready

The provider had not finished its own first sync of your account 20 hours after cfo.ai began waiting. A bank connected through Plaid gets this status only when Plaid has no recent transactions ready by then; when it has, the first sync loads them, and later syncs add the older history. Mark: steady orange dot. Line: **[Source]’s data still wasn’t ready when cfo.ai stopped waiting for its first sync, so this sync ended without data. The next scheduled sync tries again.** Action: none, or **Retry** to start a new wait.

A later sync that the source still reports running when the 20 hours run out does not get this status. The connection reads **Sync failed** with a red triangle, and the line is the reason sentence **the provider's latest report still showed its sync running 20 hours after the wait for that sync began at [time]**, followed by what the source last reported. The next scheduled sync tries again, or select **Retry**.

### Paused until next sync

The source's daily request allowance ran out. Mark: steady orange dot. Line: **[Source]’s daily limit was reached. Progress is saved, and syncing picks up on the next scheduled run.** Action: none. Signing in again would not change the limit, so **Reconnect** is not offered.

### Sync stopped

cfo.ai's data warehouse refused the data. Mark: steady orange dot. Line: **Contact cfo.ai support if it isn’t fixed soon.** Action: none; only cfo.ai can fix it.

When several causes apply at once, this one is shown, because nothing else helps until it is fixed.

### Stopped

Someone stopped the latest sync. Nothing broke. Mark: gray dot. Line: **This sync was stopped before it finished.** Action: **Retry**.

### No queries yet

The source's data synced, but no saved query brings it into your Model yet. Mark: red triangle, or a steady orange dot when someone else must set up the queries. Line: **Data synced. No queries saved yet.**, or **Data synced. Someone with access can set up queries with Ari.** Action: **Set up queries with Ari**, for people who can edit the connection.

### No data found

The sync finished, but neither the source nor its queries returned any rows. Mark: red triangle. Line: **The last sync finished but found no data.** Action: **Investigate with Ari**.

### Upload incomplete

A file upload connection has no file attached yet. Upload the file again.

### Needs attention

The general status for a connection that stopped short of your Model. MCP servers and APIs show it with a next step, such as **Reconnect this source to continue.** for a server whose saved sign-in no longer works.

### Not connected

A source was added, for example from a list Ari asked you to connect, but nothing was connected yet. Mark: gray dot.

## Statuses for MCP servers and APIs

In **Settings → Connections** and on the **MCP** and **API** tabs, a server or API reads one of these, followed by its next step when it has one.

| Status | Meaning |
| --- | --- |
| **Ready for Ari** | Ari can call its tools or endpoints. |
| **Synced** | A sync setup Ari saved has brought its data in. |
| **No queries yet** | A sync setup brought its data in, and no saved query reads it yet. On the connection's page, the line reads **Data synced. No queries saved yet.** with **Set up queries with Ari** for people who can edit the connection, or **Data synced. Someone with access can set up queries with Ari.** The page reads the status again each time it opens and when Ari saves a query. |
| **Connecting** | Setup is still in progress. |
| **Waiting for you** | Someone must finish setup, such as signing in. An MCP server in this state offers **Finish setup**; see [Sign-in incomplete](#statuses-for-mcp-servers-and-apis). |
| **Needs attention** | Something broke; the next step says what to do. |
| **Unavailable** | The status could not be read. |

An MCP server's row also shows the state of its saved sign-in. The state describes the saved credential, not whether the provider answered or how fresh its data is.

| Sign-in state | Meaning |
| --- | --- |
| **Sign-in saved** | The saved sign-in is current. |
| **Sign-in saved · expiry unknown** | The saved sign-in works, and the provider did not say when it expires. |
| **Access expired · renewal on next use** | The access token has expired, and cfo.ai renews it the next time it uses the server. Nothing to do. |
| **Reconnect required** | The connection holds no usable sign-in: the provider refused to renew it, or the access token expired and the provider gave cfo.ai nothing to renew it with. When a provider refuses a renewal, cfo.ai removes the saved sign-in. The server's status reads **Needs attention** with **Reconnect this source to continue.**, and until someone signs in again cfo.ai does not contact the server, so Ari cannot use its tools. Select **Reconnect**, which opens the provider's sign-in again and keeps the connection and its sync setups. |
| **Sign-in incomplete** | The server was added but its sign-in never finished. Its row in **Settings → Connections**, its details, and its sidebar card offer **Finish setup** to people who can add connections. It starts a new sign-in and replaces the unfinished attempt; the connection keeps its name and address for another try when the sign-in fails. The sign-in finishes even when the cfo.ai tab that started it reloads before the provider sends you back: cfo.ai keeps the attempt for ten minutes, and the page the provider returns you to completes it. Switching workspaces cancels an unfinished attempt. |
| **Provider access not checked** | The server does not sign in with OAuth, so there is no credential state to show. |

| Next step | When |
| --- | --- |
| **Reconnect this source to continue.** | The saved sign-in has no usable token. |
| **Fix with Ari** | In the **Data sync** section when the sync is failed or blocked. Starts a chat that names the connection and asks Ari to inspect the latest run and its saved sync setup, repair or retry it, and check the result. Shown with **Ari is unavailable.** and the reason while the workspace's AI usage is blocked. |
| **Finish authorization to continue.** | Sign-in was started and not finished. Select **Finish setup**. |
| **Retry authorization to continue.** | Sign-in failed. Select **Finish setup**. |
| **Allow at least one API endpoint to continue.** | No endpoint of the API is allowed yet. |
| **Grant access to the missing source tables to continue.** | A synced source, such as NetSuite, hides tables the reports need. See [Missing access in [source]](#missing-access-in-source). |
| **Refresh the API definition to continue.** | The API's specification needs to be loaded again. |
| **Verify the available tools to continue.** | The server's tool list needs checking. |
| **Retry the import to continue.** | A data import failed. |
| **Import data to continue.** | Nothing has been imported yet. A server or API whose data synced without a saved query reads **No queries yet** instead. |
| **Review the imported data to continue.** | The import finished, and what it produced needs a look. |
| **Review the source data to continue.** | The source's data needs a look before it can be imported. |
| **Attach a file to continue.** | A file upload has no file. |
| **No action is needed while setup finishes.** | Setup is running. |

### Statuses of a source Ari fetches

A source connection is for a system that has no integration: Ari fetches its data with a saved script, using a saved login or key when the system needs one; see [Bring in data from a source that has no integration](/guides/connect-other-sources#bring-in-data-from-a-source-that-has-no-integration). It is listed with your APIs and its **Type** reads **API**, but it is an exception to the two statuses other APIs show: its status follows its latest fetch, as this table lists.

| In **Settings → Connections** | On the connection's page | Meaning |
| --- | --- | --- |
| **Ready for Ari. Import data to continue.** | **Connected**, with **Ari can call this API directly.** | The connection is saved, and no fetch is running or has failed. The line is the one every API's page shows; Ari does not call a source connection live, and only fetches from it on its schedule or when you ask. It reads this before the first fetch and after a fetch that loaded its data, so it asks nothing of you once your data is in. |
| **Connecting. No action is needed while setup finishes.** | **Setup not finished**, with **No action is needed while setup finishes.** | A fetch is running, or a table it delivered is still loading. |
| **Finish setup to continue** | **Setup not finished**, with **Finish setup to continue** | The fetch stopped for something only a person can give. When the source sent you a sign-in code, a field labeled **Code [source] sent you** appears under the line; see below. With no field, the fetch stopped with a question, such as a login the source rejected. A fetch you asked for puts that question in the chat that asked; for a scheduled fetch, ask Ari to fetch from the source again. |
| **Needs attention. Import data to continue.** | **Needs attention**, with **Import data to continue.** | The latest fetch ended without data: it failed, it finished without loading a table, or nobody entered the code in time. Ask Ari to fetch from the source again. A source with a saved script is also fetched again on its next scheduled day. |

When the source texts or emails you a sign-in code, the fetch waits 15 minutes for it. People who manage connections see the field **Code [source] sent you** with **Continue fetch** on the connection's row, on its page, and on Ari's connect card for 30 minutes after the card saved the connection. An empty field reads **Enter the code first**. When cfo.ai takes the code, a **Code sent** notice appears and the fetch goes on. cfo.ai also sends one email for each wait, to the person who asked for the fetch or, for a scheduled fetch, to the person who made the connection. Its subject is **[Source] sent you a code**, and it reads **Ari is fetching data from [source] for your workspace, and the fetch is waiting for you.**, then **The source sent a code to you by text or email. Enter it on the [source] connection within 15 minutes, and the fetch continues.**, a link labeled **Open the connection** that opens your API connections, and **If the time runs out, ask Ari to fetch from this source again.** The email quotes nothing from the source's pages.

A source connection has no **Edit configuration**, so its saved login or key cannot be changed. When the password or key changes, ask Ari to connect the source again and remove the old connection. Removing a source connection keeps the tables it loaded, and they stop updating.

## Connection actions

| Action | What it does | Offered when |
| --- | --- | --- |
| **Finish setup** | Continues the unfinished setup on the same connection. No second connection is created. | Setup was not finished and the source can resume it. |
| **Cancel setup** | Removes an unfinished connection at once. It frees the plan slot the connection held. | Setup was not finished. |
| **Send link** | Makes a connect link that continues this connection's setup or sign-in for someone else who holds the source's login; its tooltip reads **For someone else with the [source] sign-in**. The hover card calls it **Send them a link**. See [Send a link so someone else can connect a source](/guides/send-a-connect-link). | Beside **Finish setup** or **Reconnect**, for people who manage connections. |
| **Reconnect** | Opens the source's sign-in again for the same connection. | The source revoked access, Fivetran paused the source's connector, a failed sync needs a new sign-in, a connection reads **Missing access in [source]** and the access has been fixed at the source, or a **Partly synced** connection's source refused access to a missed table or cfo.ai has not read why the table was missed. |
| **Retry** | Runs the import again with the same sign-in, or starts setup again after **Connection failed**. It does not use another plan slot. | A sync failed and only the import needs to run again, a sync was stopped, or setup failed. |
| **Sync now** | Starts a sync of the connection at once, with the same sign-in. The button reads **Syncing…** and is off while the sync runs, and **Couldn't start sync** when the sync could not start. The notice under that title gives the reason; **This sync can’t start because cfo.ai’s background sync processing isn’t running.** means no worker was available to run it, which cfo.ai must fix, so refreshing the page does not help. Try again later or contact support. | On a linked integration's page, for people who manage connections, when neither **Retry** nor **Reconnect** is offered. Not on an upload, an MCP server, or an API. |
| **Update file** | Replaces an uploaded CSV with a new file. | On a file upload. It is the only action when the file could not be read. |
| **Set up queries with Ari** | Opens a new chat with a request for Ari to review what synced, propose saved queries, and set them up. You review the request before you send it. | **No queries yet** |
| **Investigate with Ari** | Opens a new chat and asks Ari to find out why the sync failed or found nothing, and start it again if that helps. | **No data found**, or a **Sync failed** with no known cause |
| **Remove connection** | Asks **Do you want to remove this connection? This stops future imports and cannot be undone.** Data already in your Model stays, and stops updating. A Trigger whose instructions refer to the connection the way Ari writes it, such as `Stripe#aa9`, is paused with the reason on the Triggers page; see [Schedule a report or a reminder with a Trigger](/guides/schedule-a-trigger#if-something-goes-wrong). | On the connection's page, for people who can manage connections |
| **Remove file** | Asks **Do you want to remove this file? This cannot be undone.** A Trigger whose instructions refer to the file's connection the way Ari writes it is paused the same way as for **Remove connection**. | On a file upload's row and page |
| **Manage**, **Disconnect** | **Manage** opens the server's or API's connection page, the same page its sidebar row opens, where its tools or endpoints and their permissions live. **Disconnect**, in the row's **…** menu, does the same as **Remove connection** on that page. Disconnecting a server warns **Ari will no longer be able to use this server's tools until you reconnect.** | MCP servers and APIs, in **Settings → Connections** and on the **MCP** and **API** tabs. **Manage** appears on every row, including a server whose setup is not finished. |

A connection never offers both **Retry** and **Reconnect**. No action appears while a sync is running, when only cfo.ai support can fix the failure, when cfo.ai has turned the source off, or for people who cannot manage connections. To rename a connection, open its page and select its name.

## The connection's page

Select a connection's row to open its page. Its sections, top to bottom:

| Section | What it shows |
| --- | --- |
| **Status** | The status, the line under it, any setup warning, and the actions. **Last synced** reads the date and time of the last finished sync, to the second, in your browser's time zone, such as **Oct 23, 2026, 6:02:14 PM PDT**, or **Not yet**; the sidebar card still shows how long ago, such as **Just now**. Beside the status, people who manage connections see **Sync now** on a linked integration; see [Connection actions](#connection-actions). **Used in** lists the Pages that use the connection's data. **Added** gives the date it was connected, and **File** names an uploaded file. For an MCP server or API, the facts are **Type**, **Address**, **Sign-in**, and **Added**, with **Last synced** and **Used in** once it syncs. |
| **Source tables** | **When each table from this source last synced.** Each row gives the **Table**, its **Last synced** date and time to the second in your time zone, and the date its **Data through** reaches. It appears once two or more tables have synced. |
| **Import** | **What Ari imported from this connection.** It appears for Google Sheets and Google Drive connections. |
| **Available actions** | **Choose what Ari can do without asking first.** It appears for an MCP server that finished sign-in, for people who can manage connections. It opens with **Connection health**: **Sign-in saved**, **Sign-in saved · expiry unknown**, **Access expired · renewal on next use**, **Reconnect required**, **Sign-in incomplete**, **Provider access not checked**, or **Provider access could not be verified** when the tool list could not be read. Under it, **Available actions checked: [date and time]** or **A saved sign-in does not confirm current provider access.**, and **Reconnect** for a server that signs in with OAuth. The server's tools are grouped as **View information** and **Change or delete**, and **Reset permissions** sets the first group to **Allow** and the second to **Ask first**, classifying each tool with AI. A server with no tools reads **No actions are available from this service.** When the list fails, the error shows with **Try again**. |
| **Endpoints** | **Choose which endpoints Ari may call without asking first.** It appears for an API, grouped as **Read endpoints** and **Write/delete endpoints**, with **Auto-classify**. A path the specification leaves out joins the list once a call to it waited for approval, so you can set its permission; it leaves the list when a new specification is saved without it. |
| **Fetch script** | **Ari saves the script that repeats this fetch. The next fetch runs the newest revision.** It appears instead of **Endpoints** on the page of a source Ari fetches, for people who can manage connections. Each time Ari changes the script, it saves a revision, listed newest first as **Revision [N]** with **Saved [date and time]** and Ari's note. The newest reads **Current**; each earlier one has **Restore**, which saves that revision again as the newest, so the next fetch runs it, and confirms **Revision [N] restored as revision [M]**. Before the first fetch it reads **No script saved yet. Ask Ari to fetch from this source to save the first one.** The section lists revisions only; it does not show the script's code. |
| **Syncs** | **What Ari copies from this connection into your data.** It appears on an MCP server's or API's page for people who can manage workspace settings, before the first sync as well. |
| **Queries** | **Ari writes these queries to bring this data into your model. They are read-only.** Each saved query shows its last run, such as **Ran 2 hours ago · Completed**, **Queued**, **Running**, or **Never run**, with **Show SQL** and **Copy SQL**. With no queries, it reads **No saved queries yet.** On an MCP server's or API's page it appears with **Syncs**, or once the connection has synced. |

At the bottom, people who can manage connections see **Remove connection**, or **Remove file** for an upload.

Each table that a source Ari fetches loads is a connection of its own, named for the source and the table and labeled **Custom integration** on its page. Its **Status** section opens with **Ari manages this integration using code saved for your workspace. Each sync replaces its full table. Ari repairs the code when a sync fails.**

### A removed connection's page

A link to a connection that was removed, such as a table cell's **View source**, opens a page headed **Connection removed**, with **No longer in this workspace** under it. Its **Status** section shows a **Removed** badge and reads **This connection was removed, so its data no longer updates. The values it already imported stay in your model until you replace them.** **Imported** names the saved queries that still read the connection, and **Used in** lists the Pages. **Replace with Ari** opens a new chat with an unsent request that names the connection and what it imported, so Ari can tell you which Variables and Pages use that data and help you replace it with a current source or a new file. **Add a connection** opens the connection manager, for people who can add connections.

## Messages in a chat

When Ari syncs a connection, a line above the message box reads **Syncing** with the connection's name. Selecting it opens a card with the run's two steps, **Sync source data** and **Run saved queries**, its progress, such as **Step 1 of 2**, and **View connection** and **Stop**. A failed run reads **Couldn't finish** and keeps the connection's own status and action. A run you stopped reads **Stopped**.

When a scheduled sync finds that a source you connected stopped updating and a repair needs you, cfo.ai opens a chat titled **[Connection name] stopped updating** in your chat list.

When a newer version of a connected file arrives while an earlier import of it is still running or waiting, the chat that handles the import reads **Superseded tasks withdrawn: [tasks]. Their earlier questions no longer need answers. The current task is "[task]".** The new version went to that import, and older duplicate imports were withdrawn. **Its question remains open: [question]** follows when the import is still waiting for your answer.

When a workspace has no active plan, a refresh you ask for answers **data syncing is paused for this workspace — choose a plan, or settle the outstanding payment, to resume syncing**, and the nightly refresh skips the workspace until it has a plan again.
