A Scenario answers a "what if" question, such as "What if we hire two engineers in Q1?", without changing Main, the plan your team relies on. A Snapshot pins a plan at one moment, such as the budget your board approved, so later syncs and later edits to that plan do not reach it. Version history records every change, yours or Ari's, so you can undo any of it, and nothing you try is permanent by accident.

## Main is the plan

Every Model has one **Main Scenario**, Main for short. Main holds the numbers your team treats as the current plan, and it is what Pages show unless you pick another Scenario.

## A Scenario holds only what is different

A Scenario branches from Main. It stores only what differs from Main, such as values, formulas, Variables, Pages, and blocks, and reads everything else from there. A Page you add in a Scenario stays in that Scenario until you merge it.

Take a hiring Scenario in which two engineers start in January. When QuickBooks syncs new Actuals overnight, Main updates, and so does the hiring Scenario, because it reads those Actuals from Main. The two extra salaries stay in the Scenario alone. You never have to copy new data into your Scenarios by hand.

Two consequences follow:

- A value that the Scenario inherits from Main changes when Main changes. If you set a cell in a Scenario to the value it already inherits, nothing is saved, and the cell keeps following Main. To make a number hold still while Main moves, give the Scenario a different value.
- Connected data is shared. A Scenario changes Model formulas, values, and presentation; it never makes a private copy of an integration. Saved queries that read your connections also belong to Main, so every ordinary Scenario sees the same imported rows.

## A copy starts where another Scenario is

A new Scenario normally starts from Main. When you want to try a second version of a plan you already built, start from that plan instead: duplicate the Scenario, or ask Ari for "a new Scenario from the Hiring plan". The copy is a regular Scenario with the same base as the original, Main for every Scenario created from Main, and it begins with everything the original changed: its values, formulas, Variables, Pages, and tables, with the sharing settings the original set on its Pages. From then on the two are independent. An edit to one stays in that one, and both keep receiving Main's updates where neither overrides them.

A copy is not a Snapshot. A Snapshot is pinned to one moment and stops following its source; a copy keeps following Main and is listed beside the original, not under it. You can also duplicate a Snapshot: the copy is a regular Scenario on Main that starts with the Snapshot's pinned numbers and any edits made in the Snapshot since, so you can work from the plan the board approved while the Snapshot itself stays as it was. The copy is not pinned. It keeps only what differed from Main when you made it and follows Main for the rest. A formula that matched Main changes when Main changes it, and a formula the copy saved keeps its own value. A table added to Main appears in the copy. A table deleted from Main leaves the copy too, along with any values the copy held in that table. Only the Snapshot keeps the plan as it was, so keep the Snapshot for as long as you need that record.

## Merging brings a Scenario into Main

When you decide to adopt a Scenario, you merge it. Merging applies every change the Scenario holds to Main, then deletes the merged Scenario. The merge shows in Main's version history, and undoing it takes the changes back out and brings the merged Scenario back. A Snapshot taken from the Scenario does not block the merge.

## A Snapshot pins a moment

A **Snapshot** pins Main or a Scenario at one point in its history. After that point, nothing from the source reaches it:

- Integration syncs. When QuickBooks syncs, Main updates and the Snapshot keeps the numbers it had.
- Edits. A formula or value someone changes in the source later stays out of the Snapshot.
- Table setup. Later changes to a table's settings or column widths in the source do not carry over.

Use a Snapshot to keep the budget you submitted, the plan your board approved, or a reporting baseline you will compare against later.

A Snapshot is not read-only. You and Ari can still type values over its numbers, and those edits save, so treat a Snapshot as a copy your team agrees not to touch. A Snapshot cannot be merged into Main, cannot be restored to an earlier point, and cannot itself be snapshotted, and its version history offers no **Undo**. To pin an earlier moment of a Scenario, take the Snapshot from that point in its version history.

## Version history records every change

Every write to a Scenario is recorded, whether you made it or Ari did. Version history gives you two ways to go back:

- **Undo** reverses one change, or one related batch of changes, and puts back only the fields that change wrote. Later changes to other fields stay, even on the same Page or Variable. When a later change edited one of those same fields, such as the same Page's name, the undo is refused and names that later change, so nothing is silently replaced.
- **Restore** returns the whole Scenario to an earlier point and rolls back every change made after it. The restore is itself a recorded change, so you can undo it too. Ari calls this a revert.

Undo can also return a Scenario to Main. When you undo the only edit a Scenario made to something it read from Main, such as a formula, a Canvas block, or a table's settings, the Scenario reads that item from Main again. It shows Main's current version, including edits made in Main since the Scenario's edit, and it follows later Main edits. Say a hiring Scenario changes a formula it read from Main, and someone then edits that formula in Main. Undoing the Scenario's change shows Main's edited formula.

A change a Scenario inherited from Main cannot be undone from inside the Scenario. Undo it in Main.

## Scenario, Snapshot, or version history: which one to use

| You want to | Use |
| --- | --- |
| Try a change and maybe adopt it | A Scenario, then merge it |
| Compare a plan with the current one | A Scenario, shown side by side with Main on a table |
| Try a second version of a plan you already built | A duplicate of that Scenario |
| Keep a plan exactly as it was on a date | A Snapshot |
| Take back a change you or Ari just made | Undo in version history |
| Go back to how Main or a Scenario looked last week | Restore it in version history |

## Where Scenarios show up

- A Page is open in one Scenario at a time. The sidebar's Scenario picker shows that Scenario, unless you have picked another one there to browse its Pages; the Page changes Scenario when you open it from that list.
- A Table block can show other Scenarios beside its own, and a Canvas block can read up to three Scenarios at once.
- A share link shows the one Scenario you choose for it. See [Sharing and access](/concepts/sharing-and-access).
- Ari makes changes in the chat's Scenario, the one that was on screen when you started the chat, unless you name another one. Opening a different Scenario afterwards does not move the chat. See [Each chat works in one Scenario](#each-chat-works-in-one-scenario). Ari also knows that Main is the plan of record. A new company model, baseline, Page, or report goes in Main unless you name a Scenario, so it stays available in every Scenario; a request to change the chat Scenario's plan, such as planned hires, spending, or funding, stays in that Scenario with its Pages and tables. Ari names the destination when it differs from the Scenario on screen, and before it adds new amounts to Main while you view another Scenario, it explains their effect on the live Scenarios that inherit them. A correction goes where the original was made; a Scenario that keeps its own version of the number is named, and Ari offers to correct it too.

So if a Page or a change seems to be missing, check the Scenario picker: it may be in another Scenario. Ari's reply names the Scenario it edited when that is not the one on screen.

## Each chat works in one Scenario

A chat keeps working in the Scenario that was on screen when you started it. That answers a question people ask after they open another Scenario: "I switched to Main. Why did Ari still edit Hiring freeze?" Suppose you start a chat while a Page is open in Hiring freeze, then open the Page in Main to check a number. "Raise the engineering budget" still edits Hiring freeze. Because the Scenario on screen is now a different one, Ari names the Scenario it will edit when it starts and again when it finishes. When the chat and the screen use the same Scenario, Ari leaves the names out.

What follows from this:

- A question about what is on screen, such as "why is this cell negative?", is answered for the Scenario on screen. Ari then offers the same answer for the chat's Scenario.
- A question that does not point at the screen is answered for the chat's Scenario, and Ari asks whether you meant the one on screen.
- A request that names a Scenario, such as "In Main, add two engineers," edits that Scenario. The chat keeps its own.
- A request to edit what is on screen while the screen shows another Scenario makes Ari ask first which Scenario you mean: the chat's Scenario, the one on screen from now on, or the one on screen this once.
- To move a chat to another Scenario, ask Ari, for example "Switch this chat to Main." The switch applies from your next message, and you need edit access to that Scenario.
- Nothing on screen names a chat's Scenario. Ask Ari which Scenario the chat works in.
- If the chat's Scenario is deleted, or you lose access to it, Ari tells you and needs you to name a Scenario before it changes anything.
- An older chat, started before chats kept a Scenario of their own, works in the Scenario on screen when you send each message, and cannot be switched.
