A **Trigger** is a saved instruction Ari runs by itself on a schedule, like a weekly variance summary sent to you every Monday morning, without you needing to ask each time.

## Create a Trigger

Ask Ari to schedule one, giving it:

- **A name** you'll recognize later.
- **A prompt** — phrased as a normal request, since it runs unattended and has to stand on its own without the rest of your conversation for context.
- **A schedule**, including your timezone when you specify a local time. Ari converts it to the schedule format it stores internally.
- **A delivery destination**: your Slack direct messages or your verified email address. Ari asks you to choose before it creates or updates a Trigger.

A Trigger starts enabled as soon as you create it.

<Note>
  Trigger schedules use a fixed UTC time. A Trigger set for a particular local
  time may shift by an hour when daylight saving time changes.
</Note>

## What a delivered email looks like

An email from a Trigger is formatted, not plain text. Headings, bold text, bullet and numbered lists, tables, and links in Ari's message render in the email, so a weekly variance summary can arrive as a short table with a link back to the Page. Raw HTML and images are not rendered. A Slack direct message uses Slack's own formatting and shows no link previews; its links still open when you select them.

A Trigger can also export a Page as a spreadsheet. The workbook is saved as a file in the run's chat, and the run's message can carry a download link to it that works for 24 hours for anyone who holds the link, so a forwarded email shares the file. The link stops working sooner if the file or its chat is deleted.

## Pause, resume, or change a Trigger

Ask Ari to list your Triggers, or, as a workspace administrator, choose **Manage triggers** from the account menu at the bottom of the sidebar to open a chat about them, then:

- **Pause** one without deleting it, and **resume** it later.
- **Update** its name, prompt, or schedule.
- **Delete** it once you no longer need it.

You can only see and manage your own Triggers, not another workspace member's.

## Check whether a Trigger ran

Ask Ari to show a Trigger's last run. Two timestamps matter, and they answer different questions:

- **Last dispatch** records that the scheduler attempted or started a run, with its status and any error. It does not mean the work finished.
- **Last run** is what the newest run reported: **finished** when it reported the saved task done, **did not complete** with the run's own sentence for why, or **ended without a report** when it ended without saying either.
- **Last succeeded** is the only proof that a run completed. It moves only when a run reports the task done.

If a run is still going when the next one is due, the overlapping run is skipped, so a missing dispatch is not necessarily a failure; Ari can tell you when the run that holds the schedule started. A run that ended without a report releases the schedule, so the next scheduled time starts a new run. When a Trigger's job is to refresh a data connection, its run succeeds only if the import it started completes; an earlier import on the same connection does not count.

## What makes a good Trigger prompt

Because a Trigger fires with no conversation around it, write the prompt as if you were asking Ari cold: name the Table Block, Page, or Variable involved, and be specific about what you want back, like "Summarize the variance between Actuals and Forecast for Operating Expense over the last closed month, flag anything over 10%, and send the summary to my Slack direct messages."

Ari can deliver results only to your own Slack direct messages or verified email. It cannot post a scheduled update to a shared Slack channel or message another person. When Ari reports that a notification was sent, it means the email provider or Slack accepted the message; the activity card reads **Notification request accepted**, or **Notification outcome unconfirmed** when the provider gave no answer, and inbox placement is not confirmed. Each run ends with a report of what it did, and the next run of the same Trigger receives that report: what the last run found, how long that outcome has held, and whether you were told, so Ari tells you only what is new instead of repeating last week's message. Each run also saves a summary to Ari's memory, which the next run can search. A run never waits for you: when Ari would ask you a question, it states a reasonable assumption and continues, and the questions are saved in the run's chat, where an answer you give later starts a new turn. It also cannot complete work that requires your approval during the run, such as merging or deleting a Scenario.

When a run's work has something for you, such as a question it could not answer or work it could not finish, the run's conversation becomes a chat in your workspace. From your first reply there, Ari answers as it does in any chat and can ask you questions.
