---

Connect a Google Sheet when numbers you still keep in a spreadsheet should feed your Model, such as a hiring tracker or a pricing table. Ari imports the spreadsheet's visible tabs, rebuilds them in your Model, and re-reads it every night, so a change you make in the sheet reaches cfo.ai without a new upload. Use Google Drive to connect an Excel workbook or a CSV file the same way, and to give Ari documents such as contracts, PDFs, and Google Docs to read.

## Before you start

- A Google account that can open the file.
- A started trial or an active plan with a free connection slot. Every Google Sheets connection in a workspace shares one slot, and so does every Google Drive connection. See [Standard and premium integrations](/reference/integrations#standard-and-premium-integrations).

cfo.ai can open only the files you pick in Google's file picker, nothing else in your Drive. You can remove its access from your Google account at any time.

## Connect the file

<Tabs>
  <Tab title="Ask Ari">
    In a chat, ask Ari to connect the sheet and say what it holds:

    > Connect our hiring tracker from Google Sheets and use it for the headcount plan.

    Ari opens the connection manager with Google Sheets. Select **Connect**, sign in with Google, and pick the file. The file attaches to this chat. Ari reads it here and imports what you asked for, so it can ask you about the sheet while it works.
  </Tab>
  <Tab title="By hand">
    <Steps>
      <Step title="Open the connection manager">
        In the sidebar, point at **Connections** and select **+** (**Add integration**).
      </Step>
      <Step title="Choose Google Sheets or Google Drive">
        On the **Integrations** tab, select **Connect** on **Google Sheets** for a spreadsheet, or on **Google Drive** for an Excel workbook (`.xlsx`), a CSV file, or several files at once. Both are listed under **Data upload** when you filter the directory by type.
      </Step>
      <Step title="Sign in and pick the file">
        Sign in with Google. Google's file picker opens; choose the file. In Google Drive you can choose several files of any type. Each Google Sheet, Excel workbook, or CSV file you choose becomes its own connection, and Ari imports each one. Ari reads the other files, such as PDFs and Docs, when you ask about them. The card reads **Opening Google authentication…**, **Choosing in Google…**, **Completing connection…**, and then **Connected**.
      </Step>
      <Step title="Watch the import">
        If none of the files you chose is a spreadsheet, nothing is imported, and the row says so; see [Google Drive](/reference/integrations#google-drive). Otherwise each spreadsheet has its own row, and Ari imports it in the background. No chat tells this import what you need, so it covers every visible tab. Each row reads **Waiting for the first sync to read this file…**, then **Ari is importing this file…**. When the import is done, it reads **Imported to** and the Page Ari built, with **Ari updates the model when the file changes.**
      </Step>
    </Steps>
  </Tab>
</Tabs>

If you close Google's picker without choosing a file, the connection stays unfinished and reads **Setup not finished**. Select **Finish setup** on it to pick the file.

## Import one tab instead of the whole spreadsheet

To import only part of a spreadsheet, such as one tab, ask Ari in a chat to connect it, and say which part you need:

> Connect our planning sheet from Google Sheets. I only need the Hiring plan tab for now.

Ari starts the connection setup in that chat. The file attaches to the chat, and Ari reads it there and imports what you asked for. A spreadsheet you connect from the connection manager has no chat and no request to narrow it, so Ari imports every visible tab in the background.

A later change to the file updates what the first import recorded on its import summary Page; see [Keep the file in sync](#keep-the-file-in-sync). When the Model holds no import summary Page for the earlier version, see [When the Model no longer holds the import](#when-the-model-no-longer-holds-the-import).

## What Ari builds from the file

Ari reads the spreadsheet's visible tabs with their formulas, values, and number formats, and the hidden cells they read; a hidden tab is otherwise left out unless you name it. It rebuilds the file in your Model the way it [imports a spreadsheet model](/guides/import-a-spreadsheet-model): tabs that hold assumptions, calculations, or reports become Pages, repeated sections become Dimensions, and formulas become cfo.ai formulas. A tab or file of plain records, such as a list of transactions, becomes no Page; it is imported as data.

## Keep the file in sync

cfo.ai re-reads the file every night, and when you ask Ari to refresh it. When a value, a formula, a tab, or a defined name changed, Ari updates the parts of your Model that came from the changed sections. Edits you made in cfo.ai to sections that did not change stay. A modeling choice you made with Ari after the import, such as booking revenue from invoices instead of the sheet's formula, also stays when its section changes. Ari keeps it when it recorded the choice in its memory or on the import summary Page, the Page that the connection's **Import** section links to; see [The connection's page](/reference/connection-statuses#the-connections-page). The update's report, in the chat that handles the import, names each difference it kept for that reason. When the search for those saved choices fails or takes too long, the update still starts, and Ari is told that the saved choices were not included, so it can look them up itself. A sync that finds the same content starts no update and uses no AI usage, and the row adds **The last sync found no change.** A change to formatting alone, such as colors, column widths, or comments, starts no update either.

In an update, a choice about structure, such as which tabs or columns to import, stays as Ari recorded it. An import that starts again because no import summary Page names the earlier version does not keep it; see [When the Model no longer holds the import](#when-the-model-no-longer-holds-the-import).

A choice that depends on what cells hold, such as leaving cells that show an error blank, is kept as the rule you stated. Each update applies the rule to the new version of the file: a cell that no longer shows an error takes its value from the file, and a cell that now shows one is left blank. A list of cells on the import summary Page records what an earlier import or update did, and the update checks each listed cell against your rule again. Ari keeps a difference from the file only when its memory or the import summary Page records the rule you stated, so state the rule when you want cells to differ. After an update, the import summary Page holds your rules under one heading and the cells each rule covers in the current file under another.

Where the update happens follows where you connected the file. A file connected from a chat updates in that chat. A file connected from the connection manager updates in the background. Ari opens a chat with you when the update needs you. It also opens one when the update finished before it had read a note from one of the steps that did the work, so the note reaches you instead of nobody. Such a chat may need nothing from you.

When the file changes again while an earlier update of it is still running or waiting for your answer, the new version goes to that update instead of starting another, and older updates of the same file that were still waiting are withdrawn. The chat says so, starting **Superseded tasks withdrawn**, and repeats a question that is still open; see [Messages in a chat](/reference/connection-statuses#messages-in-a-chat).

A tab or section that Ari imported as data, such as a long list of transactions, is reloaded from the new version into the same data source. Connecting the file was your decision that each new version updates your Model, so the update does not stop to ask you before replacing those rows. Elsewhere, replacing a data source's rows still waits for your confirmation.

### When the Model no longer holds the import

An update starts from the import summary Page of the version imported before. When the file changes and no import summary Page names that version, for example because you deleted what the import built, cfo.ai does one of two things:

- If a background import or update of that version finished, cfo.ai imports nothing, so a change to the sheet does not rebuild a Model you deleted. It saves the changed version as a file in the chat that handles the import, and Ari tells you once in that chat that the file changed and that nothing was imported. For a file connected from the connection manager, that chat appears in your chat list. The connection shows that the import waits for you in a chat; [Messages about uploaded files](/reference/connection-statuses#messages-about-uploaded-files) has the status. Later changes to the file start nothing and send no other message. To bring the file back, ask Ari to import it. Ari imports the version saved in the chat. Once that import has saved its summary Page, the next sync that finds the file changed updates your Model to the file's current content, and later changes update it as before.
- If the import of that version failed, or Ari imported that version in the chat you connected the file from, the new version is imported as a whole, the way a file connected from the connection manager is imported. This import runs in the background and cannot read the chat, and it starts without the choices Ari recorded for the earlier import, so it does not keep a choice to import only some tabs: it covers every visible tab.

## Limits

- One spreadsheet imported per connection. Choosing several spreadsheets in Google Drive makes one connection for each, and all of them share Google Drive's one slot. If some of the files connect and others do not, select **Retry** in the dialog to finish the same pick; see [Messages while connecting](/reference/connection-statuses#messages-while-connecting). The duplicate rule, the connect-link rule, and the other files a Google Drive connection holds are in [Google Drive](/reference/integrations#google-drive).
- A Google Sheet can be up to 50 MB when exported as an Excel workbook. An Excel or CSV file in Drive can be up to 500 MB, the same as a file you attach to a chat. A CSV file over 50 MB is attached as a chat file only, not a data source; see [Limits](/reference/limits).
- A larger file shows **This file is too large to import. Make it smaller and the next sync imports it.**

## If something goes wrong

- **Ari stopped before finishing this import. The next sync tries again.** The next nightly sync resumes it, or ask Ari to refresh the connection now.
- **Ari stopped before finishing this import. Continue in the chat about this import.** The import waits for you, and a sync does not move it on. For a file you connected from a chat, open that chat and ask Ari to continue. For a file you connected from the connection manager, open the chat Ari started with the import's question and answer it there. If the chat says the file changed and nothing was imported, see [When the Model no longer holds the import](#when-the-model-no-longer-holds-the-import).
- If either import stopped to ask you a question, the question waits in a chat, and answering it continues the import. For a file connected from the connection manager, the next sync answers for you only when the question is about how to read the file, such as which tab holds the forecast; any other question waits for your answer, and newer versions of the file are not imported until you give it. When a newer version of the file arrives while the question waits, the newer version takes over the import that was waiting, and only that import's question stays open; the chat repeats it. Older waiting imports of the same file are withdrawn, and their questions no longer need answers. [Messages about uploaded files](/reference/connection-statuses#messages-about-uploaded-files) says which chat for each message.

For other problems, see [Fix a connection that needs attention](/guides/fix-a-connection).
