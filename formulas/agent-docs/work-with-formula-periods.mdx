---
title: "Work with FormulaRanges as an agent"
---

FormulaRanges such as Actuals and Forecast are the current canonical name for what used to be called formula periods or formula breaks.

## Read FormulaRanges first

Call `list_formula_ranges` for the selected scenario before writing a FormulaRange-scoped formula. Use the returned ID rather than guessing it.

The system Actuals and Forecast FormulaRanges already exist. Do not create a new one for a normal Actuals or Forecast request.

## Date scope is required

A `formula_range_id` is valid only when the formula condition includes a Date term.

Accepted examples:

```text
Date.Month: ANY
```

```text
Department: "Sales", Date.Month: ANY
```

```text
anySegment, Date.Month: ANY
```

Rejected examples:

```text
anySegment
```

```text
Department: "Sales"
```

A FormulaRange has nothing to apply to when Date is absent. Resolve scope from a time-based table block or add the correct Date term before writing.

## Granularity

Use the table's Date granularity when available. Otherwise use the model default of Month. Keep the condition and expression references at the same grain.

## Combining scope

A FormulaRange can be combined with segmentation and segment conditions. The formula applies only where both the FormulaRange and segment scope match.
