---
title: "Read and explain formulas as an agent"
description: "Inspect saved Variable formulas and visible Table Block values, then explain their expression, scope, range, and Scenario."
---

Use `inspect_table_blocks` with its `variable` block when a user asks how a Variable is calculated or why its behavior changes by segment or period.

## Read the saved rules

For example:

```json
{
  "scenario": "Main",
  "variable": { "target": "Gross Margin" }
}
```

The result lists every formula definition saved on the Variable, with its condition and its Actuals or Forecast range. Add `conditions` only when the question requires one exact saved scope, such as `["[Department = \"Sales\"]"]`. Omit the filter when the user wants the complete set of rules. A Variable with many rules pages; copy `next.after` into `after` with the same target.

Use the `dimension` block the same way to read a Dimension's saved definitions, and `items` to list its members.

## Connect rules to visible values

Use the `read` block for the table that actually shows the result. Each row and column already carries its formula per range, and a cell that breaks the row's rule says so in the cell. Request `formula_origins: "all"` when the explanation depends on which saved rule the engine ranked first for a row, or `"zeros"` to explain only the rows that show a zero, blank, or error.

```json
{
  "scenario": "Main",
  "read": {
    "target": "Operating Plan",
    "rows": ["Gross Margin"],
    "formula_origins": "all"
  }
}
```

Use the same requested Scenario for both the saved-formula read and the table read. The saved rule explains the intended calculation. The visible table confirms which rule actually applies to the selected period, segment, and Scenario. A row computed by a rule saved outside the table names that rule's owner and condition in `inherited_from`.

## Explain one cell's inputs

For a single cell, select one row and one column and add `include_inputs: true`. The result shows one level of the formula's inputs and where each value came from: lookup coordinates, aggregate units, the selected rule, and source dates. Read an input by its own reference to go deeper.

## Historical reads

Use `as_of_point` when the user asks for the Model as it existed at a previous saved change. Omit it for the current state.

## Explain the business meaning

Lead with what the formula does, then explain the inputs, the Scenario, the relevant Dimensions, and whether Actuals or Forecast changes the result. Include assumptions only when they matter to the user's question.
