sidebarTitle: "Connect a Google Sheet"
description: "Connect a Google Sheet, or an Excel or CSV file in Google Drive, so Ari imports it into your Model, and choose whether the Model updates when the file changes. Google Drive can also hold PDFs, Docs, and other files for Ari to read."
---

Connect a Google Sheet when numbers you still keep in a spreadsheet should feed your Model, such as a hiring tracker or a pricing table. Ari imports the spreadsheet's visible tabs and rebuilds them in your Model, and cfo.ai re-reads the file every night. A file you connect from the connection manager updates your Model when it changes. A file you connect from a chat does so after you ask Ari to keep the Model updated. Use Google Drive to connect an Excel workbook or a CSV file the same way, and to give Ari documents such as contracts, PDFs, and Google Docs to read.

## Before you start

- A Google account that can open the file.
- A started trial or an active plan with a free connection slot. Every Google Sheets connection in a workspace shares one slot, and so does every Google Drive connection. See [Standard and premium integrations](/reference/integrations#standard-and-premium-integrations).

cfo.ai can open only the files you pick in Google's file picker, nothing else in your Drive. You can remove its access from your Google account at any time.

## Connect the file

<Tabs>
  <Tab title="Ask Ari">
    In a chat, ask Ari to connect the sheet and say what it holds:

    > Connect our hiring tracker from Google Sheets and use it for the headcount plan.

    Ari opens the connection manager with Google Sheets. Select **Connect**, sign in with Google, and pick the file. The file attaches to this chat. Ari reads it here and imports what you asked for, so it can ask you about the sheet while it works. A later change to the file does not change your Model until you ask for that; see [Turn automatic updates on or off](#turn-automatic-updates-on-or-off).

    To have every visible tab imported in the background instead, say so:

    > Connect our planning workbook from Google Sheets and import the whole workbook in the background.

    Ari opens the same connection setup, and the file you pick attaches to no chat. It is imported the way a file connected by hand is; see the **By hand** tab. This works in a chat in the cfo.ai web app; [Google Sheets](/reference/integrations#google-sheets) has the rules.
  </Tab>
  <Tab title="By hand">
    <Steps>
      <Step title="Open the connection manager">
        In the sidebar, point at **Connections** and select **+** (**Add integration**).
      </Step>
      <Step title="Choose Google Sheets or Google Drive">
        On the **Integrations** tab, select **Connect** on **Google Sheets** for a spreadsheet, or on **Google Drive** for an Excel workbook (`.xlsx`), a CSV file, or several files at once. Both are listed under **Data upload** when you filter the directory by type.
      </Step>
      <Step title="Sign in and pick the file">
        Sign in with Google. Google's file picker opens; choose the file. In Google Drive you can choose several files of any type. Each Google Sheet, Excel workbook, or CSV file you choose becomes its own connection, and Ari imports each one. Ari reads the other files, such as PDFs and Docs, when you ask about them. The card reads **Opening Google authentication…**, **Choosing in Google…**, **Completing connection…**, and then **Connected**.
      </Step>
      <Step title="Watch the import">
        If none of the files you chose is a spreadsheet, nothing is imported, and the row says so; see [Google Drive](/reference/integrations#google-drive). Otherwise each spreadsheet has its own row, and Ari imports it in the background. No chat tells this import what you need, so it covers every visible tab unless a rule you stated about the file leaves some out; see [Import one tab instead of the whole spreadsheet](#import-one-tab-instead-of-the-whole-spreadsheet). Each row reads **Waiting for the first sync to read this file…**, then **Ari is importing this file…**. When the import is done, it reads **Imported to** and the Page Ari built, with **Ari updates the model when the file changes.**
      </Step>
    </Steps>
  </Tab>
</Tabs>

If you close Google's picker without choosing a file, the connection stays unfinished and reads **Setup not finished**. Select **Finish setup** on it to pick the file.

## Import one tab instead of the whole spreadsheet

To import only part of a spreadsheet, such as one tab, ask Ari in a chat to connect it, and say which part you need:

> Connect our planning sheet from Google Sheets. I only need the Hiring plan tab for now.

Ari starts the connection setup in that chat. The file attaches to the chat, and Ari reads it there and imports what you asked for. A spreadsheet you connect from the connection manager has no chat and no request to narrow it, so Ari imports every visible tab in the background. A background import cannot read a chat. Its instructions tell Ari to follow a rule someone stated about the file, when that rule is saved in Ari's memory or recorded on the file's import summary Page. So to narrow a background import, first ask Ari to remember the rule, such as "For the planning workbook, use only the Hiring plan and Budget tabs." Ari is told to list each tab the rule leaves out on the import summary Page. For a rule from the private memory of the person who connected the file, the Page says only that the tab was excluded at the owner's request.

Once automatic updates are on, a later change to the file updates what the first import recorded on its import summary Page; see [Keep the file in sync](#keep-the-file-in-sync). When the Model holds no import summary Page for the earlier version, see [When the Model no longer holds the import](#when-the-model-no-longer-holds-the-import).

## What Ari builds from the file

Ari reads the spreadsheet's visible tabs with their formulas, values, and number formats, and the hidden cells they read; a hidden tab is otherwise left out unless you name it. It rebuilds the file in your Model the way it [imports a spreadsheet model](/guides/import-a-spreadsheet-model): tabs that hold assumptions, calculations, or reports become Pages, repeated sections become Dimensions, and formulas become cfo.ai formulas. A tab or file of plain records, such as a list of transactions, becomes no Page; it is imported as data.

Ari builds a workbook one tab at a time. As it finishes each tab, it adds that tab's checks against the file to a **Workbook tie-out** table on the import summary Page. [Workbook imports](/reference/imported-data#workbook-imports) describes the table and the steps a background import runs.

## Keep the file in sync

cfo.ai re-reads the file every night, and when you ask Ari to refresh it. When a value, a formula, a tab, or a defined name changed, and automatic updates are on for the connection, Ari updates the parts of your Model that came from the changed sections. [Turn automatic updates on or off](#turn-automatic-updates-on-or-off) says which connections have them on. Before an update starts, cfo.ai lists each number or formula that you, a teammate, or Ari in another chat changed after the import, in Actuals and in Forecast, and tells Ari to keep them, even where their section of the file changed. Cells the import wrote that nobody has changed since take the file's new values. Read the update's report, which lists the edits that the person who connected the file can see in version history, to confirm that an edit you care about was kept, and state a rule for any cell that must never change. A modeling choice you made with Ari after the import, such as booking revenue from invoices instead of the sheet's formula, also stays when its section changes. Ari keeps it when it recorded the choice in its memory or on the import summary Page, the Page that the connection's **Import** section links to; see [The connection's page](/reference/connection-statuses#the-connections-page). The update's report, in the chat that handles the import, names each difference it kept for that reason. The report also lists the cells the update checked; [Workbook imports](/reference/imported-data#workbook-imports) says what each entry holds. When the search for those saved choices fails or takes too long, the update still starts, and Ari is told that the saved choices were not included, so it can look them up itself. A sync that finds the same content starts no update and uses no AI usage, and the row adds **The last sync found no change.** A change to formatting alone, such as colors, column widths, or comments, starts no update either.

In an update, a choice about structure, such as which tabs or columns to import, stays as Ari recorded it. An import that starts again because no import summary Page names the earlier version does not keep it; see [When the Model no longer holds the import](#when-the-model-no-longer-holds-the-import).

A choice that depends on what cells hold, such as leaving cells that show an error blank, is kept as the rule you stated. Each update applies the rule to the new version of the file: a cell that no longer shows an error takes its value from the file, and a cell that now shows one is left blank. A list of cells on the import summary Page records what an earlier import or update did, and the update checks each listed cell against your rule again and gives the result in its report. Ari keeps a difference from the file in three cases: its memory or the import summary Page records a rule you stated; the import summary Page records the difference with its cause, such as a formula error in the workbook that the import corrected; or someone changed the number or formula after the import. Ari changes any other difference to match the file. State a rule when you want cells that nobody has edited to differ, or when the rule should apply to later versions of the file. After an update, the import summary Page holds the rules you stated and each kept difference with its cause. The update's report lists each kept difference with its rule or cause, and each number or formula changed after the import with its current value and the file's value.

An edit counts while the cell holds something other than what the import left. A value you put back to the imported one, a value you added and then removed, a default cfo.ai fills in for a breakdown, and a value an automatic data sync wrote do not count, and the update may change them. The report lists only the edits that the person who connected the file can see in version history.

Where the update happens follows where you connected the file. A file connected from a chat updates in that chat, once you have asked Ari to keep the Model updated. A file connected from the connection manager updates in the background. Ari opens a chat with you when the update needs you. It also opens one when the update finished before it had read a note from one of the steps that did the work, so the note reaches you instead of nobody. Such a chat may need nothing from you.

When the file changes again while an earlier update of it is still running or waiting for your answer, the new version goes to that update instead of starting another, and older updates of the same file that were still waiting are withdrawn. The chat says so, starting **Superseded tasks withdrawn**, and repeats a question that is still open; see [Messages in a chat](/reference/connection-statuses#messages-in-a-chat).

A tab or section that Ari imported as data, such as a long list of transactions, is reloaded from the new version into the same data source. Connecting the file from the connection manager, or asking Ari to keep the Model updated from a file you connected in a chat, was your decision that each new version updates your Model, so the update replaces those rows without asking you.

### Turn automatic updates on or off

Whether a changed file updates your Model depends on where you connected it.

- A file you connected from the connection manager is imported at its first sync, and each changed version updates your Model. Connecting it there is your request. A file Ari connected for a background import counts the same way.
- A file you connected from a chat does not. Ari imports what you ask for in that chat, and a later change to the file changes nothing in your Model until you ask.

To turn updates on, ask Ari after the file is connected:

> Keep the Model updated when the hiring tracker sheet changes.

Nothing starts when you ask. From then on, a sync that finds the file changed starts an update. Ari is told to keep a number or formula someone changed after the import; see [Keep the file in sync](#keep-the-file-in-sync).

If nobody has imported the file yet, asking for updates is also your request to import it. The next sync imports the whole file in the background, whether or not the file changed. That sync is the nightly one, or one Ari starts when you ask it to refresh the file now. The import covers every visible tab, the way a file connected from the connection manager is imported, unless a rule you stated about the file leaves some out; see [Import one tab instead of the whole spreadsheet](#import-one-tab-instead-of-the-whole-spreadsheet). It runs in the chat where you connected the file. Until the import starts, the connection's row says that it waits for the first sync; [Messages about uploaded files](/reference/connection-statuses#messages-about-uploaded-files) lists each line the row can read.

A file counts as imported once a background import or update has taken a version of it, or once Ari's import in the chat has saved its import summary Page. For a workbook, that Page must hold the **Workbook tie-out** table; a Page that only mentions the file is not an import. So when Ari is importing a workbook in the chat, ask for updates after that import has finished. Otherwise a sync can start a second import beside it.

To turn updates off, tell Ari not to import the file:

> Do not import the planning workbook. I only want you to read it.

Ari records the file as read, not imported, and cancels an import or update of it that has not finished. Whatever that import had already built stays in your Model. Ari's reply can name the Pages, blocks, Variables, and Dimensions the import created that you can open, up to 50 of them; ask Ari to remove them if you do not want them. Numbers and formulas the import wrote into tables that already existed are not in that list. This works for a file connected from a chat and for one connected from the connection manager.

Only the person who connected the file can turn updates on or off, in a message they write in a chat of their own. Ari does not record the choice from another member's message, from a Trigger run, or from an AI client connected over MCP.

A request you made earlier counts too. If you asked Ari to keep the Model updated from the file in an earlier message, in a chat of your own in the workspace, Ari can record that request later, for example when a sync finds the file changed and leaves its note in the connection's chat. You do not have to ask again. Ari can do this only in a chat of your own, in a turn that holds no other person's message. Your newest decision wins: an earlier request never replaces a later one, so a file you told Ari not to import stays that way until you ask again.

When updates are off and the file changes, cfo.ai saves the changed version as a file in the chat that handles the import, and Ari tells you once in that chat that the file changed and that nothing was updated. For a file you connected from the connection manager, that chat can be the chat where you told Ari to stop the import; otherwise it is a new chat in your chat list. Each later sync that finds the file changed again saves the new version in that chat and sends no other message, so Ari reads the file's current content when you ask about it there. Nothing in your Model changes. The connection reads **Waiting for your decision**, and its row reads **No import is running. Continue in the chat about this import.** No question is waiting. The saved versions and the note go only to you, the person who connected the file, and only while you can still open the connection. After you ask Ari to turn updates on, the next sync updates your Model from the version last imported to the file's current content, as long as your Model still holds that version's import summary Page.

### When the Model no longer holds the import

An update starts from the import summary Page of the version imported before. When no import summary Page names that version, for example because you deleted what the import built, or because you connected the file from a chat and nobody imported it, cfo.ai does one of three things:

- If you connected the file from a chat, automatic updates are on, and no background import or update has ever taken a version of the file, the next sync imports the file as a whole in the background, whether or not the file changed. This is the import that asking for updates starts; see [Turn automatic updates on or off](#turn-automatic-updates-on-or-off). It covers a file nobody imported. It also covers a file Ari imported in that chat whose import you deleted before any background update ran; to keep a sync from importing that file again, tell Ari not to import it.
- If a background import or update of that version finished, cfo.ai imports nothing when the file changes. With automatic updates off, the same holds for a file you connected from a chat that no background import ever took: a file nobody imported, and a file Ari imported in that chat whose import you then deleted. A change to the sheet does not rebuild a Model that a background import built and you deleted, and it does not start an import that nobody asked for. It saves the changed version as a file in the chat that handles the import, and Ari tells you once in that chat that the file changed and that nothing was imported. For a file connected from the connection manager, that chat appears in your chat list. The connection shows that the import waits for you in a chat; [Messages about uploaded files](/reference/connection-statuses#messages-about-uploaded-files) has the status. Later changes to the file start no import and send no other message; each sync that finds the file changed again saves the new version in that chat, so the chat holds the file's current content. To bring the file back, ask Ari to import it. Ari imports a version saved in the chat, and cfo.ai points Ari to the newest one. For a file from a chat that no background import ever took, you can instead ask Ari to keep the Model updated from it, and the next sync imports the whole file. Once that import has saved its summary Page, the next sync that finds the file changed updates your Model to the file's current content when automatic updates are on for the connection. With updates off, it saves the changed version in the chat with one note instead; see [Turn automatic updates on or off](#turn-automatic-updates-on-or-off).
- If a background import of that version failed and automatic updates are on, the new version is imported as a whole, the way a file connected from the connection manager is imported. An import that is still running or waiting for your answer takes the new version instead, as [Keep the file in sync](#keep-the-file-in-sync) describes. This import runs in the background and cannot read the chat, and it starts without the choices Ari recorded for the earlier import, so it does not keep a choice to import only some tabs that Ari recorded nowhere else: it covers every visible tab unless a rule you stated, saved in Ari's memory or recorded on the import summary Page, leaves some out.

## Limits

- One spreadsheet imported per connection. Choosing several spreadsheets in Google Drive makes one connection for each, and all of them share Google Drive's one slot. If some of the files connect and others do not, select **Retry** in the dialog to finish the same pick; see [Messages while connecting](/reference/connection-statuses#messages-while-connecting). The duplicate rule, the connect-link rule, and the other files a Google Drive connection holds are in [Google Drive](/reference/integrations#google-drive).
- A Google Sheet can be up to 50 MB when exported as an Excel workbook. An Excel or CSV file in Drive can be up to 500 MB, the same as a file you attach to a chat. A CSV file over 50 MB is attached as a chat file only, not a data source; see [Limits](/reference/limits).
- A larger file shows **This file is too large to import. Make it smaller and the next sync imports it.**

## If something goes wrong

- **Ari stopped before finishing this import. The next sync tries again.** The next nightly sync resumes it, or ask Ari to refresh the connection now. The first import of a Google Sheet with two or more visible tabs resumes at the step that stopped, so tabs whose steps finished are not built again; see [When a workbook import stops](/reference/imported-data#when-a-workbook-import-stops).
- **No import is running. Continue in the chat about this import.** The connection reads **Waiting for your decision**: the import waits for you, nothing failed, and a sync does not move it on. For a file you connected from a chat, open that chat and ask Ari to continue. For a file you connected from the connection manager, open the chat Ari started with the import's question and answer it there. You can also ask Ari in another chat of yours to answer the import or to follow it; the import's later questions and its report then arrive in that chat. If the chat says the file changed and nothing was imported, see [When the Model no longer holds the import](#when-the-model-no-longer-holds-the-import). If the file changed while automatic updates were off, see [Turn automatic updates on or off](#turn-automatic-updates-on-or-off). **Investigate with Ari** on the connection asks Ari what the import waits on; see [Waiting for your decision](/reference/connection-statuses#waiting-for-your-decision).
- **Ari stopped before finishing this import. Continue in the chat about this import.** The import stopped without a question, and no sync runs it again. If someone cancelled the import, a newer version of the file starts a new import while automatic updates are on. Otherwise, open the chat about the import and ask Ari to continue.
- **A limit on cfo.ai’s side stopped Ari before it finished this import.** The import's calculations ran past a limit on cfo.ai's side, and the connection reads **cfo.ai is fixing this**. Nothing in your file caused it, and a sync does not move the import on. Once cfo.ai has lifted the limit, reply in the chat about the import to continue it. If it lasts, email [success@cfo.ai](mailto:success@cfo.ai). See [cfo.ai is fixing this](/reference/connection-statuses#cfoai-is-fixing-this).
- If either import stopped to ask you a question, the question waits in a chat, and answering it continues the import. For a file connected from the connection manager, the next sync answers for you only when the question is about how to read the file, such as which tab holds the forecast; any other question waits for your answer, and newer versions of the file are not imported until you give it. When a newer version of the file arrives while the question waits, the newer version takes over the import that was waiting, and only that import's question stays open; the chat repeats it. A first import that builds a Google Sheet tab by tab does not take a newer version: the newer version waits until that import finishes, and a sync after that starts the update. Older waiting imports of the same file are withdrawn, and their questions no longer need answers. [Messages about uploaded files](/reference/connection-statuses#messages-about-uploaded-files) says which chat for each message.

For other problems, see [Fix a connection that needs attention](/guides/fix-a-connection).
