Integrations bring financial and operating data into your cfo.ai Model. Connect a source when real accounting, people, customer, or spreadsheet history should inform your analysis.

## Choose the right source

Common starting points include:

- Accounting systems such as QuickBooks Online, Xero, or NetSuite.
- HR and payroll systems such as Rippling, Gusto, BambooHR, or Workday.
- CRM systems such as HubSpot or Salesforce.
- A Google Sheet, a file in Google Drive, or a PostgreSQL-compatible database.
- A CSV or another supported file-upload flow for a source that is not connected directly.

Available sources and plan entitlements can vary. Ask Ari to check the catalog for the system you use.

A file you upload as a data source must be a CSV with a `.csv` extension, up to 50 MB. An uploaded Excel workbook is not accepted as a data source: attach it to a chat message for Ari to read, ask Ari to [import it as a model](/getting-started/import-a-spreadsheet-model), or connect it through [Google Drive](#connect-a-google-sheet-or-drive-file), which imports a workbook the way Ari imports an upload.

## Connect a business system

<Steps>
  <Step title="Tell Ari what you want to connect">
    Name the source and what you want to use it for.

    > Connect QuickBooks Online so we can build a monthly profit and loss statement.

  </Step>
  <Step title="Approve the connection">
    Ari opens or links you to the connection flow. Complete the sign-in and approval in your browser. Ari cannot enter your password or approve access for you.
  </Step>
  <Step title="Choose the tables to sync, when asked">
    Some sources, such as Shopify, NetSuite, HubSpot, Salesforce, or your own database, show a table picker after you sign in. Every available table starts selected, so uncheck the ones you do not need, then choose **Finish setup & sync N tables**, which names the count it will import; the selection cannot be changed later. At most 100 tables can be synced per connection, and a source with more than that, such as Shopify's full list, starts above the cap and asks you to uncheck tables before it lets you finish. Locked tables stay selected, and a source whose catalog lists features your account does not have, such as NetSuite, starts those tables unchecked. A larger selection makes the first sync longer. **Cancel setup** ends the setup: a new connection that never finished is removed, so nothing is left behind, and a connection that was already linked is kept.
  </Step>
  <Step title="Wait for the initial load">
    cfo.ai starts loading the connected data after the source links. The import can continue in the background while you work on something else.

    A source may still be running its own first sync when cfo.ai's load begins: an HR or payroll system such as Gusto, or a source that syncs through Fivetran, such as HubSpot, Salesforce, or a database, whose first sync copies the account's whole history and can take hours. cfo.ai then checks again every ten minutes until the provider's first sync finishes or fails, loads the data as soon as it completes, and gives up only when the provider reports a failed or paused sync. Ari can tell you that it is waiting on the provider.
  </Step>
  <Step title="Check what arrived">
    Ask Ari whether the connection has finished, when data was last loaded, and which information is ready for analysis.

    > Check whether QuickBooks finished syncing and tell me which accounting periods are available.

    If a past period was wrong at the source and you have corrected it there, ask Ari to re-import the connection's full history. The routine refresh covers recent periods only.

  </Step>
</Steps>

## Connect from the sidebar instead

You can also start without Ari. Select **Connections** in the sidebar, then **Add**. The connection manager opens with three tabs:

- **Integrations** lists the business systems cfo.ai can import from, with a **Connect** button on each card and an **Upload** button for CSV files.
- **MCP** lists MCP servers Ari can call, such as Linear or Notion, plus **Add server** for one that is not listed. The **Add MCP server** dialog takes a **Name** and the **MCP URL**; its **Advanced** section has an **Authentication** choice of **OAuth**, **Bearer token**, or **API key header**, the last with a **Header name** such as `X-API-Key` and the key. When the URL's host is `mcpgateway.rippling.com`, the dialog adds a **Rippling setup** note listing what Rippling requires first: the server URL from **IT → My IT → MCP connectors → Rippling MCP**, access assigned by a Rippling admin under **IT → MCP Gateway → Rippling MCP → Access assignments**, and an active Rippling AI trial or subscription; the same note appears beside a saved server's tool-loading error and on Ari's connect card. A server that refuses Ari because it needs a sign-in says so: **This MCP server requires sign-in. Disconnect it and add it again with OAuth or a bearer token.** Ari sees each connected server's name and status at the start of every message, so it knows to read a bank balance from a connected Mercury server without being told.
- **API** lists other services' APIs Ari can reach, such as Stripe, plus **Add API**.

The same popover shows each connection's status and its actions. See [Connect data by hand](/getting-started/build-by-hand#connect-data) for the click paths.

A connection you start here still reports to you in chat. While your workspace is new, before any connection has completed a first sync, cfo.ai ties the new connection to your most recent chat, so Ari announces there when the link completes and when the first sync finishes or fails. After that, the result of a background sync, such as data that is ready to model or a first sync that failed, is still delivered to the chat you used most recently.

## Ask Ari to connect an MCP server or API

A workspace administrator can also have Ari set up an MCP server or an API from the chat, for example "Connect PostHog's MCP server." Ari reads the provider's official documentation, then posts a card headed **Connect [service]** with the service's logo, its address, how it signs in, and a **Provider documentation** link. In this chat flow an MCP server signs in with OAuth or a **Bearer token**; a server that needs an API key header is added from the **Add MCP server** dialog instead. An API uses a **Bearer API key**, a named header, an **API key as Basic username**, or **No authentication**. The card carries no credentials, and Ari never asks for a key in the chat.

Select **Connect**. A service that uses OAuth opens its sign-in window; one that takes a token or key shows a secure field on the card, and what you type there goes to cfo.ai's connection service, not to Ari or into the conversation. The card reads **Connecting…**, then **Checking connection…** while cfo.ai confirms that the server's tools answer or that the API's endpoints loaded, then **Connected** for a server or **API saved** for an API. On a failure it offers **Retry**, and a retry keeps a connection that was already saved; **Cancel** stops the setup. A member who cannot manage connections sees **A workspace admin must connect this service.**

When the provider refuses cfo.ai's sign-in address, the message **The provider must approve cfo.ai's sign-in URL to connect.** appears on the card, and in the **Add MCP server** dialog in Settings. Trying again cannot fix that; the provider has to allow cfo.ai's callback address first. A provider that rejects the registration for another reason is named as the one that refused, and a temporary failure still asks you to try connecting again. Once a server is connected, Ari gives it 45 seconds to answer when a chat turn or the Settings page lists its tools; a server that stays silent is reported as unavailable for that turn, and the other servers' tools still work.

Once the card completes, Ari continues in the same chat: it checks the connection's tools or endpoints and, for an API, verifies the key with a documented read before relying on it. **API saved** means the definition parsed, not that the key works. An OAuth provider that needs a preregistered app, and an API that signs in with a username and password or with a key in the query string, cannot be set up this way; Ari says so instead of collecting the secret.

## Finish a connection you started earlier

If the source's sign-in window closes before you finish authorizing, for example because a pop-up was blocked or you are not the company's administrator, the connection card says **QuickBooks Online was not connected** (with the name of the source you chose) and explains that the window closed before authorization finished. Select **Try again** to reopen the sign-in on the same pending connection, or **Close**. Trying again does not create a second connection.

Connecting the same source again later continues the unfinished connection instead of starting a new one, whichever door you use: **Connect** on the source's card, **Finish setup** on the connection, a connect link, or asking Ari. This applies while no connection to that source is linked yet and the earlier connection's setup never finished: its status reads **Setup not finished**, or it failed because its link expired. The status says only what cfo.ai knows for certain: the setup may have failed, been abandoned, or still be open in a teammate's tab.

If a Fivetran-backed source's table picker loses track of the setup, for example because you finished it in another tab, the page reads **Fivetran setup was interrupted** and offers **Go to cfo.ai**. The connection was saved, so choose **Finish setup** on it to continue. A connection that lost access and reads **Reconnect required** is not picked up this way; use **Reconnect** on it. Continuing a connection someone else started needs edit access to that connection. When you continue a connection from a chat, that chat is the one Ari reports to when the link completes and the first sync finishes.

## Connect a Google Sheet or Drive file

**Google Sheets** and **Google Drive** are listed under **Data upload** on the **Integrations** tab. Select **Connect** on the card: a Google sign-in opens, then Google's own file picker, where you choose one file. The Google Sheets picker shows spreadsheets; the Google Drive picker also shows Excel workbooks and CSV files. The card reports **Opening Google authentication…**, **Choosing in Google…**, **Completing connection…**, and then **Connected**. Google grants cfo.ai access to the files you pick and nothing else in your Drive, and you can revoke it from your Google account.

What happens next depends on where you connected:

- **From a chat.** Ari attaches the file to that chat and imports it there, so Ari can ask you about the sheet while it works. The connection row reads **Attached to the chat that connected it. Ari imports it there.** Once that chat has imported the sheet, the row links the Page Ari built and reads **The chat that connected it handles later changes.**
- **From the connection manager.** Ari imports the file in the background without opening a chat. The row reads **Waiting for the first sync to read this file…**, then **Ari is importing this file…**, then **Imported to \[Page]**, with a link to the Page Ari built, and **Ari updates the model when the file changes.** If Ari stopped partway, the row says so and the next sync tries again. When you replace an uploaded file, Ari reports the upload as not ready until the new file's import finishes, instead of reading the previous file's rows; Ari reads an upload's rows in the Scenario the chat is in, the same Scenario its readiness report describes.

A Google Sheet is read with every tab, its formulas, cached values, and number formats, and Ari rebuilds it the way it rebuilds an uploaded workbook. Each sync compares the file with the last import and does nothing when it is unchanged; a changed file starts an update of the Model. A Google Sheet is read as an Excel workbook of up to 50 MB, and an Excel or CSV file stored in Drive up to 10 MB. A larger file shows **This file is too large to import. Make it smaller and the next sync imports it.**, and in a chat Ari names the limit that applied, such as the 50 MB cfo.ai attaches as an Excel workbook. One connection reads one file, and the same file cannot be connected twice in a workspace. A Google Sheets or Google Drive connection made earlier through Fivetran keeps syncing as it did.

## Upload a file

If you attach a CSV in Ari chat, choose whether it should become a data source or stay attached only to the conversation.

- **Use as a data source** when the file's rows should become available in the Model.
- **Use in chat only** when Ari should read or summarize the file without importing it.

An uploaded data source is identified by its filename until you rename it. If the same filename already backs a connection, cfo.ai asks for confirmation before replacing it. Each file can be up to 50 MB.

cfo.ai reads each column's type from its values. Dates are decided for a whole column at once: cfo.ai reads every value in the column and picks the one day and month order that reads them all, so a column holding `13/04/2026` is read day-first throughout, and a column whose values all read either way is read month-first. A column that needs both orders is not a date column. Dates may carry a clock, such as `2026-09-25 00:56`, and then load as timestamps rather than text. Plain digit strings such as `2024` or `20240229` stay numbers; only a column whose header is exactly `yyyyMMdd` is read as a date in that compact form, such as `20260131`. Some point-of-sale exports use this header.

A column named `Date` does not place the file's rows on the calendar by itself. Tell Ari which column dates the rows, such as an invoice date or a period column, and Ari saves it as the source's preferred time column; `first` and `last` over the source's rows then order by that column.

An imported source with no date column at all cannot be laid out by period. A Table Block that shows one of its Variables by month stops calculating and reports that the source **has no date column to read it by**, naming the source. Add a date column at the source and sync again, or tell Ari which existing column dates the rows. A read that does not depend on Date, such as `last` over the source's rows in a table with no Date axis, still answers. See [A table cannot date an imported source](/formulas/formula-reference/formula-errors-and-troubleshooting#a-table-cannot-date-an-imported-source).

If the file is an existing financial model rather than a source-data export, ask Ari to [import and rebuild the spreadsheet model](/getting-started/import-a-spreadsheet-model) instead of treating the workbook as an ordinary data connection.

## Understand sync status

A connected source is ready only after its background load completes. A linked account, started import, or uploaded file does not by itself mean the resulting data is already available.

After the first load, connected integrations refresh once a night, automatically; there is no manual refresh button, so ask Ari to refresh a connection if you need newer data sooner. File uploads never refresh on their own. See [how integrations stay current](/integrations/integrations-directory#how-integrations-stay-current).

If the Model contains fewer rows than the source file, ask Ari which source records were included. A saved query may intentionally filter the source to match your request. When a connection's saved queries return no rows although the source holds data, for example because a query joins through an empty report table, Ari can hand the connection to a background worker that repairs the queries. When you ask when a connection last loaded, Ari answers from the last successful load; a failed or canceled refresh does not count.

Saved queries belong to Main. Ari creates, edits, and runs them in Main whatever Scenario you are viewing, and every ordinary Scenario reads Main's latest SQL and result; a Snapshot keeps the SQL and result it was pinned with. You cannot test a query change in one Scenario alone.

Ask Ari to remove a saved query you no longer need. Ari first previews what the removal retires, the Variables and Dimensions the query owns and the formulas and tables that read them, and deletes only when you confirm that list; the connection and its other queries stay. A query whose load is still running cannot be removed until it finishes.

When Ari reports that a source finished loading, it names the periods the load covered, such as **January 2025–September 2026**, and says that completion establishes nothing about data outside that range. A table the source finished with some records unavailable is called out as a partial result rather than complete Actuals.

Each column a query returns loads into the Model as a Variable or a Dimension. cfo.ai guesses the role when the column first loads: a numeric column becomes a summed Variable unless its name marks it as an identifier: a name that ends in the word "id", including a camel-case ending such as `dealId`, or in "account number" or "account code", such as `Customer ID`, `deal_id`, `P&L Account Number`, or `SalesDefaultAccountCode`. Such a column loads as a text Dimension, so a leading zero in `00400` and every digit of a long ID stay as written, while `Account Balance` and `Number of Accounts` still sum. A column a database or warehouse query returns as text (`TEXT`, `VARCHAR`, `STRING`, or `CHAR`) loads as a text Dimension whatever its name and even when every value looks like a number, so a cast in the saved SQL, such as `to_varchar(stage_order)`, chooses the role before the first load; text whose values are all dates still loads as dates. Columns returned as numbers, and untyped CSV columns, still follow the name rule. An identifier that loaded as a number before these rules keeps its stored type. If a code loaded as a summed Variable, ask Ari to load it as a Dimension instead. Ari switches the role in place, so formulas, tables, and filters that already point at the column keep working, and every later load keeps the new role. A switched column keeps its stored type, so a number column that becomes a Dimension has number items; to keep leading zeros, return the column as text under a new name. A column that loads into a Dimension other queries also feed, such as four QuickBooks connections' **Customer** columns feeding one Customer Dimension, cannot have its role switched for one query: Ari names the shared Dimension and the other queries instead.

## Reconnect a source that lost access

When an accounting system such as QuickBooks Online or Xero revokes cfo.ai's access, for example after a password change or an expired authorization, the connection's status changes to **Reconnect required** after the next nightly refresh fails, and the connection shows a **Reconnect** action. Select it and sign in again to the company or organization the connection already holds.

A connection that is healthy or still syncing does not offer **Reconnect**. Signing in again cannot help it, so cfo.ai offers the action only when the source revoked access or when a failed sync needs a new sign-in. A connection whose setup never finished offers **Finish setup** instead.

### Retry a failed import

When a linked connection's import failed but its sign-in still works, the connection offers **Retry** instead of **Reconnect**: in the connection's details dialog, in the sidebar's Connections popover, and as a refresh icon with a **Retry** tooltip on the connection's row in the directory. Retry restarts the import on the same connection without signing in again and without using another plan slot, and the status moves from **Needs attention** through **Connecting** to **Synced**, the label a connection that loads data shows once its data is in; a connection that syncs nothing, such as an MCP server or API, reads **Connected** instead. A connection that needs attention offers one of the two actions, never both: **Retry** when cfo.ai knows the sign-in still works and only the import needs to run again, and otherwise **Reconnect**. Retry is withheld while an import or sync is still running, when the failure needs cfo.ai support, when the source is disabled, and for members who cannot manage connections.

Asking Ari to connect a source never re-authenticates an existing connection; reconnecting is a separate action that names the connection. If you ask Ari to connect NetSuite while a NetSuite connection already needs re-authentication and you do not say which company you mean, Ari asks whether you want another company connected or that connection reconnected. Name the company to add a second connection, or name the connection to reconnect it. When your plan's connection limit is reached, Ari's refusal names the connection that needs re-authentication so you can reconnect it instead of adding another.

If the provider's screen says you are already connected, its main button may read **Finish**; choose **Relink integration** there instead. **Finish** keeps the current authorization, and cfo.ai reports that the source **was not reconnected**, names the organization to sign in to, and offers **Try again**. For Xero, if the consent screen lists your organization as already connected, disconnect the cfo.ai app under **Connected apps** in Xero, then try again; the card names the app as Xero lists it.

## When a sync fails

A source that syncs through Fivetran, such as NetSuite, HubSpot, Salesforce, a database, or a Google Sheets connection made earlier through Fivetran, stays connected when a sync fails on the provider's side. The connection shows that it needs attention and offers **Retry** when the import can run again on the same sign-in, or otherwise **Reconnect**, which re-runs the provider's setup checks; its status changes to **Reconnect required** only when the provider asks for a new authorization. cfo.ai retries the sync on the next nightly run, and you can ask Ari to retry it now.

A NetSuite connection also checks, before every sync, that NetSuite still shares the tables the financial statements need, and shows **Access missing** when one is hidden. See [NetSuite table access](/integrations/integrations-directory#accounting-and-erp).

## Connections for external tools

An integration imports business data into cfo.ai. A connected external MCP server or API gives Ari access to another service's tools. The cfo.ai MCP server does the opposite: it lets an outside AI client use cfo.ai's tools.

These are separate connection types with different setup and access controls.
