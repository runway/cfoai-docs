Use a filter to show only some of a Dimension's items on a table, such as two departments out of ten, and a sort to put the items in order. Filters and sorts change only this table, and everyone who opens it sees the same view. They never change a number in your Model.

You need a desktop browser and edit access to the Page.

## Filter a table to show only some items

<Tabs>
  <Tab title="Ask Ari">
    > On the Payroll table, show only the Sales and Marketing departments.
  </Tab>
  <Tab title="By hand">
    <Steps>
      <Step title="Open the Dimension's menu">
        Right-click the Dimension's label row, such as **DEPARTMENT** above its items. Or right-click one of its items and choose **[Department] dimension settings**.
      </Step>
      <Step title="Choose Filter items">
        Choose **Filter items**. A list of the Dimension's items opens.
      </Step>
      <Step title="Pick the items to keep">
        The list opens with every item checked. Clear the check beside each item to hide. Or clear **All Items** to uncheck every item, then check the items to show. Type in **Search items** to find one in a long list.
      </Step>
      <Step title="Save">
        Select **Save**. It is unavailable until at least one item is checked.
      </Step>
    </Steps>
  </Tab>
</Tabs>

**Filter items** is in the menu for Dimensions in the rows. For a Dimension in the columns, use the table setup panel: select **Show table setup** at the left of the table header, point at the Dimension under **Columns**, and select its funnel button. The same list opens.

A filter saves the list of items to keep. An item that joins the Dimension later, such as a new department from your payroll system, stays hidden on this table until you check it in the list or clear the filter.

## Hide one item

Right-click the item, such as **Contractors**, and choose **Filter out this item**. The table must keep at least one item, so you cannot filter out the last one.

To hide several items at once, select their row names, right-click one of them, and choose **Filter selected items**. See [Menu for several selected rows](/reference/table-blocks#menu-for-several-selected-rows).

## Show one product or one country without adding rows

To limit a whole table to chosen items of a Dimension that is not on its rows or columns, such as one product or one country, use the table's item filter.

<Tabs>
  <Tab title="Ask Ari">
    > Filter the Revenue table to the Widget product and the US.
  </Tab>
  <Tab title="By hand">
    <Steps>
      <Step title="Open Filter items">
        Open the table's **…** menu, **Table block settings**, and choose **Filter items…**.
      </Step>
      <Step title="Choose a Dimension and its items">
        Choose a Dimension under **Add a dimension…**, check the item to show, and select **Apply**. Add another Dimension the same way.
      </Step>
      <Step title="Save">
        Select **Save filter**.
      </Step>
    </Steps>
  </Tab>
</Tabs>

The table header then names the filter, such as **Country: US · Product: Widget**. With one item for each Dimension, the cells stay editable, and a value you type saves for that item. With several items of a Dimension, each cell shows their total and cannot be edited. To clear the filter, select the filter in the header, select **Remove** beside each Dimension, and select **Save filter**. The exact rules are in [Item filter](/reference/table-blocks#item-filter).

## Clear a filter so every item shows again

A filter on a Dimension's items leaves no mark on the table itself. An item filter set with **Filter items…** in the table's **…** menu is different: the table header names it. To check whether a Dimension is filtered, open **Show table setup**: a funnel with a number beside a Dimension shows how many items the filter keeps. In the right-click menu, **Filter items** shows the same number. A funnel with no number means a condition filters the Dimension; see [A filter Ari wrote as a formula](#a-filter-ari-wrote-as-a-formula).

To clear the filter:

<Steps>
  <Step title="Open the filter list">
    Right-click the Dimension's label row and choose **Filter items**, or select its funnel in the table setup panel.
  </Step>
  <Step title="Choose All Items">
    Select **All Items** at the top of the list.
  </Step>
  <Step title="Save">
    Select **Save**. Every item shows again, including any you filtered out with **Filter out this item**.
  </Step>
</Steps>

**All Items** clears the checked list only. A condition saved on the same Dimension keeps filtering it until you change or remove the condition, as the next section describes.

## A filter Ari wrote as a formula

Ari can filter an axis by a condition instead of a list of items, such as the employees whose Status is Active. The condition compares Dimension values: it can read the axis's own Dimension, a Dimension mapped from it, and another Dimension loaded from the same source table, such as an employee's Department. A condition cannot read a Variable, so rows are not chosen by their numbers this way. Two things come close. To hide rows with nothing in them, ask Ari to hide the rows whose values are all zero or empty; whether they hide also depends on your workspace's policy for empty results, and a row with a negative or small value still shows. To choose rows by a number, ask Ari to add a Dimension column whose formula reads the Variable. That gives each row one value, and a condition on the axis can compare it.

When you open **Filter items** or the funnel on such an axis, the list opens with a **Filter formula** section at the top that shows the condition, read-only, above the item checkboxes. To change or remove it, select **Edit with Ari**: a request with the table and the axis attached lands in the message box for you to finish and send. The list has no field to edit the condition and no button to remove it. The checkboxes below are a separate filter, and the table shows the items that pass both. **Edit with Ari** closes the list without saving the checkboxes, so select **Save** first when you also changed a checkbox.

Ari saves one or the other on an axis. When Ari saves a condition, the checked list on that axis is cleared, and when Ari saves a list of items, the condition is removed. If you need both, check the items again by hand after Ari changes the condition.

A filter you set from a column header, described in [Filter a list by a column's value](#filter-a-list-by-a-columns-value), is saved as a condition too, so it also shows, read-only, under **Filter formula**. To change or clear that one, select the funnel in the column header and save a new choice there.

> Remove the formula filter on the Employee axis of the Headcount table and show every employee.

## Filter a list by a column's value

You can filter a table that lists records, such as one row per employee, by a column's value. This works for a column that shows which item each row belongs to, such as Status or Department. The table's rows must start with one Dimension, such as Employee, with no Variable or second Dimension beside it at the top level.

1. Right-click the column header, such as **Status**, and choose **Filter**.
2. Under **Show rows where Status is**, every value starts checked. Clear the values to hide, or clear **Any value** and check only the values to keep. Then select **Save**.

A funnel then appears in the column header. Point at it to see which values the filter keeps. To change or clear it, select the funnel; choose **Any value** and **Save** to show every row again.

If Ari saved a condition on the rows that this list cannot show, the list's title says that saving replaces the custom filter, and **Save** replaces Ari's condition with your choice. The funnel's wording for such a condition is in [What colors and marks mean](/reference/table-blocks#what-colors-and-marks-mean).

## Sort items A to Z, Z to A, or in your own order

<Tabs>
  <Tab title="Ask Ari">
    > On the Payroll table, list the departments in this order: Sales, Marketing, Engineering, then the rest.
  </Tab>
  <Tab title="By hand">
    <Steps>
      <Step title="Open the Dimension's menu">
        Right-click the Dimension's label row, or choose **[Department] dimension settings** from one of its items.
      </Step>
      <Step title="Choose a sort">
        Choose **Sort**, then:

        - **Ascending** for A to Z, or smallest to largest for number items.
        - **Descending** for Z to A.
        - **Manual** for your own order. Drag the items in the list that opens; each move saves. Items that join the Dimension later follow the ones you ordered, A to Z.
        - **None** to return to the standard order, A to Z.
      </Step>
    </Steps>
  </Tab>
</Tabs>

You can also drag item rows up or down by the grip at their left edge. The Dimension then switches to **Manual**. The table setup panel has the same choices behind each Dimension's sort button.

A sort applies to the whole level, so every group on the table that shows that Dimension lists its items in the same order.

## Sort rows by a column's values

<Tabs>
  <Tab title="Ask Ari">
    > On the Customers table, sort the rows by Customer First ARR Month, oldest first.
  </Tab>
  <Tab title="By hand">
    Right-click the header of the column to sort by and choose **Sort ascending** or **Sort descending**. A check marks the current choice.
  </Tab>
</Tabs>

The Dimension's items reorder by their values in that column, and they keep that order as values change and new items arrive. This works on a column that shows values: a Variable such as Revenue, a field such as Start date, one month of a table segmented by Date, or a comparison column such as a Scenario's **Variance**. A header that groups other columns, a total column, and a formula column do not offer it, and the table needs a Dimension in its rows. One column orders the table at a time, so sorting by another column replaces the first.

Each level sorts inside its parent. On a table that lists Regions with Customers under each, sorting by Revenue orders the Regions by their totals and the Customers within each Region by their own values. A row that has no value or shows an error goes last either way. Choose **Clear column sort** on the same header to return to the item order, or pick **None**, **Ascending**, **Descending**, or **Manual** under **Sort** to replace the column sort with an item order.

The sort stays saved with the table when you add a comparison, a spacer, or another level of rows. If the sort column leaves the table, or you nest it under another column level, the rows show their item order and the Dimension's **Sort** reads **Column sort inactive** until the column comes back. The full rules are in [Column sort](/reference/table-blocks#column-sort).

Variable rows have no sort; drag them into the order you want. Date columns always run in date order; to show fewer periods, change the table's date range.

## If Filter items or Sort is missing

The menu leaves out actions that cannot apply. Check which case you are in:

<Accordion title="The table is read-only for you">
  Ask a page owner for edit access.
</Accordion>

<Accordion title="The Dimension is Date">
  The Date axis cannot be filtered or sorted. Change the date range instead; see [Build a Table block by hand](/guides/build-a-table#set-the-dates-and-the-time-grain). A column that holds dates, such as First ARR Month, can still order the rows; see [Sort rows by a column's values](#sort-rows-by-a-columns-values).
</Accordion>

<Accordion title="The Dimension's items are dates">
  A Dimension of dates other than Date, such as Start month, has **Sort** but no **Filter items**, and its items have no **Filter out this item**.
</Accordion>

<Accordion title="The Dimension is in the columns">
  The right-click menu of a column Dimension has **Sort** but not **Filter items**. Use the funnel in the table setup panel; see [Filter a table to show only some items](#filter-a-table-to-show-only-some-items).
</Accordion>

<Accordion title="The row is a Variable">
  Variables cannot be filtered or sorted. Hide or drag them instead; see [Format and arrange a table](/guides/format-a-table).
</Accordion>

<Accordion title="The Dimension is a column that shows each row's item">
  That is a mapping. Use **Filter** on its column header, as described above, or change it with **Use as**.
</Accordion>

<Accordion title="The breakdown belongs to one item only">
  A breakdown added with **Segment by** on a single item is not a level of the whole table, so it has no filter or sort.
</Accordion>

<Accordion title="There is no label row to right-click">
  The table hides its label rows. Right-click an item and use **[Department] dimension settings**, or turn on **Show dimension headers** in the table's **…** menu, **Table block settings**.
</Accordion>
