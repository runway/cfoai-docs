A connection's status says whether its data is current and whether you must act. Every connection shows one status. You see it on the connection's row in the sidebar's **Connections** section, on the card that opens when you point at the row, on the connection's page, and on the source's card in the connection manager. Ari reads the same status when you ask about a connection. To fix a problem step by step, see [Fix a connection that needs attention](/guides/fix-a-connection).

## Sidebar marks

The mark at the right end of a connection's row in the sidebar says whether anything needs you.

| Mark | Meaning |
| --- | --- |
| No mark | The data is in and current (**Synced**), or an MCP server or API is ready (**Connected**). |
| Blinking orange dot | A sync is running (**Syncing**). |
| Steady orange dot | Something is incomplete but usually needs nothing from you: the sync resumes by itself, cfo.ai must fix it, or someone else must act. The one exception is a **Partly synced** connection whose source refused access to a table, which offers **Reconnect**. |
| Red triangle | A problem you must act on. The card names it and offers the fix. |
| Gray dot | Setup was not finished, someone stopped the latest sync, or the source was added but not connected. |

With no connections, the section reads **No connections yet**. The **Connections** section shows one row per app. An app you connected more than once, such as one QuickBooks company per entity, gets a parent row with its connections nested under it, and the parent shows the mark of its most urgent connection. A connection with no name of its own, such as an unfinished setup, is named for its source, and several such connections of one source are numbered in the order they were created: **Stripe**, **Stripe (2)**. Ari uses the same names in its chat notes. Under a parent row, a nested MCP server or API that has only its app's name reads **MCP server** or **API**, with the same number.

## Statuses

### Synced

The data reached your Model, and the last sync finished. Mark: none. Action: none. The card also shows **Last synced** and **Used in**.

### Connected

An MCP server or an API is ready for Ari to call. Mark: none. Its page and its sidebar card show two statuses: **Connection**, which reads **Connected** while Ari can call its tools or endpoints, and **Data sync**, which reads the state of the sync setups Ari saved for it, such as **Synced**, **Syncing**, **No queries yet**, **No data found**, or **Needs attention**. A working server can therefore read **Connection: Connected** beside **Data sync: Needs attention** when an import failed. A server with no sync setup has no **Last synced** time. When the data sync is failed or blocked, the **Data sync** section offers **Fix with Ari**, which starts a chat about that sync; someone who cannot edit the connection reads **Someone with edit access can fix this sync with Ari.** instead.

### Syncing

A sync is running, or a first sync is queued. Mark: blinking orange dot. The connection's page reads **A sync is running now.** No **Reconnect** or **Retry** is offered while it runs. While cfo.ai waits on the provider, the line says how long it has waited:

- **Waiting [time] so far for [source]’s first sync to finish.** It may add what the provider last reported, then **If it hasn’t finished by [date and time], this sync stops at its next check after that.** cfo.ai checks every 10 minutes and waits up to 20 hours. For a source that syncs through Fivetran, the provider's report reads **Fivetran reports its first historical sync of the account still running**, or, when the source's API has stopped answering Fivetran for now, **Fivetran rescheduled its first historical sync of the account because the source's API allows no more calls for now; its next attempt is due at [time]**. cfo.ai keeps waiting through a rescheduled first sync and asks Fivetran to run it again once that time has passed.
- **Waiting [time] so far for cfo.ai’s request allowance at [source] to reset. The allowance for this organization is used up or nearly used up, and the sync resumes on its own when it resets.** It ends the same way. Xero, for example, limits how many requests an app can make each day.
- **Waiting [time] so far for [source] to finish a sync it is still running. cfo.ai loads that sync once it finishes. If [source] still reports it running at the first check after [date and time], this sync stops.** A source that syncs through Fivetran was still running its own sync 45 minutes after cfo.ai asked for one. cfo.ai starts no new sync and checks again about every 10 minutes for up to 20 hours. The data from the last loaded sync stays usable meanwhile.

### Partly synced

The last sync finished without some of the source's tables. The data that arrived is usable. Mark: steady orange dot. The line names up to three tables and counts the rest, and it says whose side the cause is on once cfo.ai has read why each table failed:

- Until cfo.ai has read the cause, for a moment after the page opens or for as long as cfo.ai cannot read the connection's sync outcome: **[Source]’s last sync couldn’t refresh [tables]. Everything else is up to date, and cfo.ai will try again on the next sync.** Action: **Reconnect**, as for any connection that needs attention, until the cause replaces this line.
- The source refused this connection's sign-in or permissions for every missed table, such as a QuickBooks account that cannot read **accounts**: **[Source] refused this connection access to [tables], so the last sync didn’t refresh that data. A reconnect with an account that can read it lets the next sync refresh it. Everything else is up to date.** Action: **Reconnect**.
- The source refused some tables and the rest failed for another reason: the refusal sentence, then **A problem on cfo.ai’s or [Source]’s side kept [tables] from refreshing, and cfo.ai will try again on the next sync. Everything else is up to date.** Action: **Reconnect**, which repairs only the refused tables.
- No table was refused: **A problem on cfo.ai’s or [Source]’s side kept the last sync from refreshing [tables]. Reconnecting won’t change it. cfo.ai will try again on the next sync, and everything else is up to date.** Action: none; the next sync retries the missing tables.

A refusal is the source answering a sync request with a sign-in or permission error, such as HTTP 401 or 403, or QuickBooks Online's **Permission Denied**. A rate limit, a timeout, or a failure in cfo.ai's own reader is not a refusal.

### Setup not finished

Someone started connecting the source and did not finish. The setup may have failed, been abandoned, or still be open in someone's tab. Mark: gray dot. Line: **Syncing won’t begin until setup is finished.** Actions: **Finish setup** continues the same connection, and **Cancel setup** removes it without asking, because it holds no data yet.

A source whose setup cannot be resumed, such as Stripe (Direct), offers only **Cancel setup** on the card, with **Setup wasn’t finished. Cancel it and connect [source] again.** On the connection's page, the line says **Remove it** and the button is **Remove connection**. People who cannot manage connections see the line and no button.

### Connection failed

Setup failed before the source linked. Mark: red triangle. Line: the failure's reason, or **Retry to set it up again.** Action: **Retry**.

### cfo.ai lost access

The source revoked cfo.ai's access, for example after a password change or an expired authorization. Mark: red triangle. Line: **Reconnect to start syncing again.** Action: **Reconnect**, then sign in to the same company the connection already holds.

### Missing access in [source]

The source is not sharing some tables the reports need, such as **Missing access in NetSuite SuiteAnalytics**. Mark: red triangle. Line on the card: **[Source] isn’t sharing some tables the reports need. Open the connection for the steps to fix it.** A connection whose saved query fails because it reads one of those hidden tables also shows this status, not **Sync failed**, because another sync cannot help until the access is fixed. The connection's page shows an **Access missing** badge and the steps. For NetSuite they read: **NetSuite isn't sharing some tables cfo.ai needs for your financial statements. Have your NetSuite admin create an access token for the Data Warehouse Integrator role, then reconnect NetSuite with that token. Changing only the role ID won't work. Missing tables: …** Action: fix the access in the source, then **Reconnect**.

### Sync failed

There are two kinds:

- The provider's own sync failed, often for a moment. Mark: steady orange dot. Line: **[Source]’s sync hit an error. cfo.ai will try again on the next scheduled sync.** When the provider gave a reason, its report sits between the two sentences, for example **BigQuery’s sync hit an error. Fivetran reports: Problem with view (BigQueryConnectorTask_VIEW_ERROR): [the view Fivetran could not read]. cfo.ai will try again on the next scheduled sync.** Fivetran's report gives each failing task as its message, its code in parentheses, and its details, which name what failed, such as the view or table; several tasks are separated by semicolons. Ari reads the same report. Action: none, or **Retry** to run it now. When the report names something to fix at the source, fix that first. When Fivetran reports the connector broken by a generic sync failure and nothing else, and its setup tests pass, the nightly refresh starts one ordinary sync on up to two later nights; a success clears the count, and a connector that needs a new sign-in or is paused is not retried this way.
- cfo.ai could not tell why the sync failed. Mark: red triangle. Line: the source's own reason, or **The last sync couldn’t finish.** Actions: **Retry** and **Investigate with Ari**. When the reason names a table the source hides, the connection shows [Missing access in [source]](#missing-access-in-source) instead.

### First sync not ready

The provider had not finished its own first sync of your account 20 hours after cfo.ai began waiting. Mark: steady orange dot. Line: **[Source]’s data still wasn’t ready when cfo.ai stopped waiting for its first sync, so this sync ended without data. The next scheduled sync tries again.** Action: none, or **Retry** to start a new wait.

A later sync that the source still reports running when the 20 hours run out does not get this status. The connection reads **Sync failed** with a red triangle, and the line is the reason sentence **the provider's latest report still showed its sync running 20 hours after the wait for that sync began at [time]**, followed by what the source last reported. The next scheduled sync tries again, or select **Retry**.

### Paused until next sync

The source's daily request allowance ran out. Mark: steady orange dot. Line: **[Source]’s daily limit was reached. Progress is saved, and syncing picks up on the next scheduled run.** Action: none. Signing in again would not change the limit, so **Reconnect** is not offered.

### Sync stopped

cfo.ai's data warehouse refused the data. Mark: steady orange dot. Line: **Contact cfo.ai support if it isn’t fixed soon.** Action: none; only cfo.ai can fix it.

When several causes apply at once, this one is shown, because nothing else helps until it is fixed.

### Stopped

Someone stopped the latest sync. Nothing broke. Mark: gray dot. Line: **This sync was stopped before it finished.** Action: **Retry**.

### No queries yet

The source's data synced, but no saved query brings it into your Model yet. Mark: red triangle, or a steady orange dot when someone else must set up the queries. Line: **Data synced. No queries saved yet.**, or **Data synced. Someone with access can set up queries with Ari.** Action: **Set up queries with Ari**, for people who can edit the connection.

### No data found

The sync finished, but neither the source nor its queries returned any rows. Mark: red triangle. Line: **The last sync finished but found no data.** Action: **Investigate with Ari**.

### Upload incomplete

A file upload connection has no file attached yet. Upload the file again.

### Needs attention

The general status for a connection that stopped short of your Model. MCP servers and APIs show it with a next step, such as **Reconnect this source to continue.** for a server whose saved sign-in no longer works.

### Not connected

A source was added, for example from a list Ari asked you to connect, but nothing was connected yet. Mark: gray dot.

## Statuses for MCP servers and APIs

In **Settings → Connections** and on the **MCP** and **API** tabs, a server or API reads one of these, followed by its next step when it has one.

| Status | Meaning |
| --- | --- |
| **Ready for Ari** | Ari can call its tools or endpoints. |
| **Synced** | A sync setup Ari saved has brought its data in. |
| **No queries yet** | A sync setup brought its data in, and no saved query reads it yet. On the connection's page, the line reads **Data synced. No queries saved yet.** with **Set up queries with Ari** for people who can edit the connection, or **Data synced. Someone with access can set up queries with Ari.** The page reads the status again each time it opens and when Ari saves a query. |
| **Connecting** | Setup is still in progress. |
| **Waiting for you** | Someone must finish setup, such as signing in. |
| **Needs attention** | Something broke; the next step says what to do. |
| **Unavailable** | The status could not be read. |

An MCP server's row also shows the state of its saved sign-in. The state describes the saved credential, not whether the provider answered or how fresh its data is.

| Sign-in state | Meaning |
| --- | --- |
| **Sign-in saved** | The saved sign-in is current. |
| **Sign-in saved · expiry unknown** | The saved sign-in works, and the provider did not say when it expires. |
| **Access expired · renewal on next use** | The access token has expired, and cfo.ai renews it the next time it uses the server. Nothing to do. |
| **Reconnect required** | The provider refused to renew the sign-in. Select **Reconnect**, which opens the provider's sign-in again and keeps the connection and its sync setups. |
| **Sign-in incomplete** | The server was added but its sign-in never finished. |
| **Provider access not checked** | The server does not sign in with OAuth, so there is no credential state to show. |

| Next step | When |
| --- | --- |
| **Reconnect this source to continue.** | The saved sign-in has no usable token. |
| **Fix with Ari** | In the **Data sync** section when the sync is failed or blocked. Starts a chat that names the connection and asks Ari to inspect the latest run and its saved sync setup, repair or retry it, and check the result. Shown with **Ari is unavailable.** and the reason while the workspace's AI usage is blocked. |
| **Finish authorization to continue.** | Sign-in was started and not finished. |
| **Retry authorization to continue.** | Sign-in failed. |
| **Allow at least one API endpoint to continue.** | No endpoint of the API is allowed yet. |
| **Grant access to the missing source tables to continue.** | A synced source, such as NetSuite, hides tables the reports need. See [Missing access in [source]](#missing-access-in-source). |
| **Refresh the API definition to continue.** | The API's specification needs to be loaded again. |
| **Verify the available tools to continue.** | The server's tool list needs checking. |
| **Retry the import to continue.** | A data import failed. |
| **Import data to continue.** | Nothing has been imported yet. A server or API whose data synced without a saved query reads **No queries yet** instead. |
| **Review the imported data to continue.** | The import finished, and what it produced needs a look. |
| **Review the source data to continue.** | The source's data needs a look before it can be imported. |
| **Attach a file to continue.** | A file upload has no file. |
| **No action is needed while setup finishes.** | Setup is running. |

## Connection actions

| Action | What it does | Offered when |
| --- | --- | --- |
| **Finish setup** | Continues the unfinished setup on the same connection. No second connection is created. | Setup was not finished and the source can resume it. |
| **Cancel setup** | Removes an unfinished connection at once. It frees the plan slot the connection held. | Setup was not finished. |
| **Reconnect** | Opens the source's sign-in again for the same connection. | The source revoked access, a failed sync needs a new sign-in, a connection reads **Missing access in [source]** and the access has been fixed at the source, or a **Partly synced** connection's source refused access to a missed table or cfo.ai has not read why the table was missed. |
| **Retry** | Runs the import again with the same sign-in, or starts setup again after **Connection failed**. It does not use another plan slot. | A sync failed and only the import needs to run again, a sync was stopped, or setup failed. |
| **Update file** | Replaces an uploaded CSV with a new file. | On a file upload. It is the only action when the file could not be read. |
| **Set up queries with Ari** | Opens a new chat with a request for Ari to review what synced, propose saved queries, and set them up. You review the request before you send it. | **No queries yet** |
| **Investigate with Ari** | Opens a new chat and asks Ari to find out why the sync failed or found nothing, and start it again if that helps. | **No data found**, or a **Sync failed** with no known cause |
| **Remove connection** | Asks **Do you want to remove this connection? This stops future imports and cannot be undone.** Data already in your Model stays, and stops updating. | On the connection's page, for people who can manage connections |
| **Remove file** | Asks **Do you want to remove this file? This cannot be undone.** | On a file upload's row and page |
| **Manage**, **Disconnect** | **Manage** opens the server's or API's connection page, the same page its sidebar row opens, where its tools or endpoints and their permissions live. **Disconnect**, in the row's **…** menu, does the same as **Remove connection** on that page. Disconnecting a server warns **Ari will no longer be able to use this server's tools until you reconnect.** | MCP servers and APIs, in **Settings → Connections** and on the **MCP** and **API** tabs. **Manage** appears on every row, including a server whose setup is not finished. |

A connection never offers both **Retry** and **Reconnect**. No action appears while a sync is running, when only cfo.ai support can fix the failure, when cfo.ai has turned the source off, or for people who cannot manage connections. To rename a connection, open its page and select its name.

## The connection's page

Select a connection's row to open its page. Its sections, top to bottom:

| Section | What it shows |
| --- | --- |
| **Status** | The status, the line under it, any setup warning, and the actions. **Last synced** reads the date and time of the last finished sync, to the second, in your browser's time zone, such as **Oct 23, 2026, 6:02:14 PM PDT**, or **Not yet**; the sidebar card still shows how long ago, such as **Just now**. Beside the status, people who manage connections see **Sync now** on a linked integration; see [Connection actions](#connection-actions). **Used in** lists the Pages that use the connection's data. **Added** gives the date it was connected, and **File** names an uploaded file. For an MCP server or API, the facts are **Type**, **Address**, **Sign-in**, and **Added**, with **Last synced** and **Used in** once it syncs. |
| **Source tables** | **When each table from this source last synced.** Each row gives the **Table**, its **Last synced** date and time to the second in your time zone, and the date its **Data through** reaches. It appears once two or more tables have synced. |
| **Import** | **What Ari imported from this connection.** It appears for Google Sheets and Google Drive connections. |
| **Tools** | **Choose which tools Ari may use without asking first.** It appears for an MCP server that finished sign-in, for people who can manage connections. It opens with **Connection health**: **Sign-in saved**, **Sign-in saved · expiry unknown**, **Access expired · renewal on next use**, **Reconnect required**, **Sign-in incomplete**, **Provider access not checked**, or **Provider access could not be verified** when the tool list could not be read. Under it, **Tools verified: [date and time]** or **A saved sign-in does not confirm current provider access.**, and **Reconnect** for a server that signs in with OAuth. Tools are grouped as **Read-only tools** and **Write/delete tools**, and **Auto-classify** sets their permissions. When the list fails, the error shows with **Try again**. |
| **Endpoints** | **Choose which endpoints Ari may call without asking first.** It appears for an API, grouped as **Read endpoints** and **Write/delete endpoints**, with **Auto-classify**. |
| **Fetch script** | **Ari saves the script that repeats this fetch. The next fetch runs the newest revision.** It appears instead of **Endpoints** for an API that Ari reads with a saved script, and lists the saved revisions with **Restore**. |
| **Syncs** | **What Ari copies from this connection into your data.** It appears on an MCP server's or API's page for people who can manage workspace settings, before the first sync as well. |
| **Queries** | **Ari writes these queries to bring this data into your model. They are read-only.** Each saved query shows its last run, such as **Ran 2 hours ago · Completed**, **Queued**, **Running**, or **Never run**, with **Show SQL** and **Copy SQL**. With no queries, it reads **No saved queries yet.** On an MCP server's or API's page it appears with **Syncs**, or once the connection has synced. |

At the bottom, people who can manage connections see **Remove connection**, or **Remove file** for an upload.

### A removed connection's page

A link to a connection that was removed, such as a table cell's **View source**, opens a page headed **Connection removed**, with **No longer in this workspace** under it. Its **Status** section shows a **Removed** badge and reads **This connection was removed, so its data no longer updates. The values it already imported stay in your model until you replace them.** **Imported** names the saved queries that still read the connection, and **Used in** lists the Pages. **Replace with Ari** opens a new chat with an unsent request that names the connection and what it imported, so Ari can tell you which Variables and Pages use that data and help you replace it with a current source or a new file. **Add a connection** opens the connection manager, for people who can add connections.

| **Add another** | The source already has a connection; adds one more, such as a second company. |

| **Finish setup** | Continues a setup that was not finished. |
| **Retry** | Repairs a connection whose setup failed. |

## Messages when a new connection is refused

These appear in the plan tooltip on a directory card:

- **Your plan includes [N] standard integrations and all are in use. Upgrade to add more.** (or premium integrations)
- **Your plan has reached its integration limit. Upgrade to add more.**
- **Integrations aren't included in your plan. Upgrade to connect this one.**
- **Premium integrations aren't included in your plan. Upgrade to connect this one.**
- **Unable to resolve an active plan for this workspace. Choose a plan to connect integrations.**
- **Your plan is scheduled to change to [plan] on [date], [what it includes]. Keep your current plan to connect this one.**

These come from cfo.ai when a setup starts:

- **your plan has no room for another integration of this kind — upgrade your plan to add more**
- **this workspace has reached this integration's connection limit**
- **start the free trial to add integrations**
- **this workspace has no active plan — choose one, or settle the outstanding payment, to add integrations**
- **this workspace has a plan change scheduled, and the upcoming plan has no room for this integration — keep your current plan to add it**
- **this integration is temporarily disabled by cfo.ai; contact support to re-enable it**

Signing in to a company the workspace already holds shows **[Company] is already connected**, with **Use the existing connection instead of adding another.**, or **It is connected as “[name]”. Use that connection instead of adding another.**, or **It needs reconnecting. Reconnect it instead of adding another.** with a **Reconnect** button.

## Messages about MCP servers and APIs

| Message | Meaning |
| --- | --- |
| **A workspace admin must connect this service.** | You cannot manage connections. |
| **The provider must approve cfo.ai's sign-in URL to connect.** | The provider has to allow cfo.ai's sign-in address first. Trying again does not help until it does. |
| **This provider signs in only apps registered with it in advance. It offers neither automatic registration nor client metadata documents, the two ways cfo.ai identifies itself, so sign-in cannot start.** | The server cannot be connected with OAuth. |
| **This server's address, or an address it gave for sign-in, is a non-public address. cfo.ai did not contact it.** | cfo.ai connects only to public addresses. |
| **This MCP server requires sign-in. Disconnect it and add it again with OAuth or a bearer token.** | The server was added without sign-in. |
| **The MCP server rejected authorization (it answered HTTP 401). Reconnect this server and try again.** | The saved sign-in was refused. The status code is the one the server answered. |
| **Could not load tools from the MCP server (it answered HTTP 404). Try again shortly.** | The server did not return its tools. |
| **API saved** | The API's specification loaded. It does not prove the key works. |
| **Retry to finish this setup. A retry keeps any connection already saved.** | An API setup failed partway. |
| **The specification URL is not an https address.** | The OpenAPI address must start with `https://`. |
| **The specification URL answered HTTP 404, not the document.** | The address returned an error status instead of the specification. |
| **The specification document is larger than the 12 MiB this connection accepts.** | The specification is too large. |
| **Could not load the OpenAPI specification. Check its URL or paste the document as JSON.** | The address did not answer. |
| **Raw ingestion failed for [connection]. Sync page [N] failed: [cause].** | A page of an MCP sync failed. Ari's chat report states the cause in the words below, and the data from the last completed sync stays in place. |
| **the connection is no longer linked, or its access for tool "[tool]" is no longer Allow** | Every page checks both, so no page completes until the connection is linked and the tool's permission is **Allow**. |
| **the server answered HTTP 401 and rejected this connection's authorization when the page connected** | No page completes until the saved authorization changes. Select **Reconnect** on the server's row. |
| **HTTP 429 is the server limiting the rate of requests it accepts, and its Retry-After header stated a wait of [N] seconds** / **…and its answer stated no time at which that limit ends** | The server limited how often cfo.ai may call it. The sync does not fail at once: it waits the stated time, at least one second, or one minute when none is stated, then asks for the same page again, keeping the pages it already fetched. One page waits at most five times. The report appears only when the wait would not fit in the sync's 10 minutes, or a page has waited five times; the job then waits for the server, as an API sync does, and the next run meets the limit again where it left off. |
| **the server answered HTTP 503 when the page connected; the connection allowance is 45 seconds** | A 5xx status reports a fault in the server, not in the page's request. The next sync tries again. |
| **the server's current definition of tool "[tool]" is absent or differs from the description and schemas this setup saved** | No page completes while the two differ. Ask Ari to save the sync setup again. |
| **tool "[tool]" answered these arguments with an error result (isError)** | The tool returns the same error to a call with these arguments. Ask Ari to call the tool with the setup's arguments to read the error. |
| **the call to tool "[tool]" ended without a result; a call's allowance is 45 seconds** | The call did not finish in time. |
| **the server's answer is larger than the 2 MiB a sync page holds** | The page stops and saves nothing from that answer. Ask Ari to change the setup's arguments so the tool returns less, such as a narrower date range or fewer fields, before the next sync. |

## Messages in a chat

When Ari syncs a connection, a line above the message box reads **Syncing** with the connection's name. Selecting it opens a card with the run's two steps, **Sync source data** and **Run saved queries**, its progress, such as **Step 1 of 2**, and **View connection** and **Stop**. A failed run reads **Couldn't finish** and keeps the connection's own status and action. A run you stopped reads **Stopped**.

When a scheduled sync finds that a source you connected stopped updating and a repair needs you, cfo.ai opens a chat titled **[Connection name] stopped updating** in your chat list.

When a workspace has no active plan, a refresh you ask for answers **data syncing is paused for this workspace — choose a plan, or settle the outstanding payment, to resume syncing**, and the nightly refresh skips the workspace until it has a plan again.
